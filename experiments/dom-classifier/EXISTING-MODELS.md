# Existing-model and dataset reuse: DOM regions

Researched 2026-09-18. This is a read-only survey: I inspected public model
cards, repository files/configuration, and dataset metadata. **No checkpoint or
dataset archive was downloaded.**

## Recommendation: start from WebClasSeg-25, then adapt

Use [WebClasSeg25 v1.2.0](https://zenodo.org/records/19183572) as the external
seed corpus and its **functional-classification (FC)** checkpoint as the
starting model, contingent on confirming the checkpoint license. It is the
closest verified public resource: current public
service websites with both polygon/screenshot and HTML segmentation, functional
segment labels, raw MHTML, and a fixed train/test split. Version 1.2.0 was
published 2026-03-23 and corrects broken/outdated test-set MHTML links and
annotations. It contains 852 unique pages from 500 domains, represented by
2,580 annotated page/annotator records, and Zenodo lists 3.2 GB overall
(MHTML 1.5 GB, screenshots 1.7 GB, annotations 9.1 MB); fetch only the
portions actually needed after confirming rights. Zenodo's record page leaves
the Rights field blank, but its [record API metadata](https://zenodo.org/api/records/19183572)
declares the dataset CC-BY-4.0; retain required attribution. The Hugging Face
FC checkpoint's card/metadata does not state a weight license, so do not assume
the checkpoint inherits the dataset's license.

The public [benchmark repository](https://github.com/gerbejon/WebClasSeg25-segmentation-benchmark)
is MIT and includes preprocessing/training/prediction programs for HTML and
screenshot models. It explicitly identifies the FC categories as functional
segments such as header, footer and navigation. The released node datasets are
public and ungated on Hugging Face:

| Resource | Verified contents | Why it matters |
| --- | --- | --- |
| [`WebClasSeg25-html-nodes-fc-balanced`](https://huggingface.co/datasets/gerbejon/WebClasSeg25-html-nodes-fc-balanced) | 640,442 train + 48,481 test nodes; fields include opening HTML (`tag_head`), XPath, tag, parent/child labels, CSS-class path and target (`y`). | Directly reusable supervised HTML-node examples. FC labels are `advertisement`, `footer`, `header`, `image`, `maincontent`, `multiple`, `nav`, `title`. |
| [`roberta-html-nodes-fc-classifier-v2`](https://huggingface.co/gerbejon/roberta-html-nodes-fc-classifier-v2) | A present `model.safetensors` checkpoint and config for 12-layer/768-dim RoBERTa sequence classification, 514 positions, with the eight FC labels above. The Hub API reports 124,651,784 parameters and about 499 MB (FP32). | Direct released task checkpoint; use it as an initialization/baseline, not a final taxonomy. It is much larger than the 1.27M-parameter GAT alternative. |
| [`longcoder-html-nodes-fc-classifier-v1`](https://huggingface.co/gerbejon/longcoder-html-nodes-fc-classifier-v1) | A present `model.safetensors` checkpoint and tokenizer/config for 12-layer/768-dim LongCoder/Longformer sequence classification, 4,098 positions, same eight FC labels. | Preferred initialization if serialized node-context needs more than RoBERTa's 512-token window. Its autogenerated card reports only validation loss, no task-quality analysis. |

The FC mapping is valuable but incomplete for SquirrelScan. `footer`, `nav`,
and `maincontent` are strong candidate sources, but map all FC labels by DOM
context rather than equating their names with the product taxonomy: an FC
`header` can be a nested article header rather than `site_header`, and FC
`title` is not inherently `article_header`. `advertisement` is useful negative
context. The dataset has no separate `card`, `aside`, `form`, or
`consent_banner` class. Preserve those as own-crawl/human-browser-label targets
and add `unknown`/abstention. Do not silently map FC's `multiple` to a product
role.

### Safe adaptation plan

1. Reproduce the upstream HTML-node serializer against a small sample and ensure
   `path_translated_class` is a CSS-class/translated-path feature, never the
   target label. Retain only runtime-available fields (opening tag/attributes,
   XPath/ancestor features, CSS class tokens, text, and optional rendered
   geometry).
2. Fine-tune the released FC checkpoint on WebClasSeg FC plus SquirrelScan's
   own crawl labels, with an explicit label map and a new head for missing
   classes. Train a screenshot companion only if rendering is available and
   visual grouping proves necessary; do not make it a requirement for DOM-only
   audits.
3. Keep SquirrelScan's human-browser-labeled, domain/template-disjoint test set
   entirely untouched. The upstream `roberta/train.py` and `codeBERT/train.py`
   (the latter actually trains LongCoder) use their `dataset['test']` for
   evaluation and `load_best_model_at_end`; that is unsuitable as this project's
   final test protocol. Split an upstream validation set from training instead.
4. Remove the benchmark scripts' Hugging Face login/push plumbing for local
   adaptation. Report per-role macro-F1, calibration/abstention, and results by
   held-out registrable domain and template—not random DOM nodes.

This reuses an external, aligned labelled corpus and a task head while making
the project's browser labels the authority for classes WebClasSeg-25 lacks.

## Secondary candidates

### `lucymakeit/dom-node-classifier`: useful weak-label teacher, not gold

This [Apache-2.0 GATv2 checkpoint](https://huggingface.co/lucymakeit/dom-node-classifier)
is a 1.27M-parameter graph classifier with a present `model.safetensors` and
class mapping. It predicts 14 node roles from a DOM graph plus computed CSS,
viewport box, visibility and a frozen MiniLM text embedding. The model itself
is small, but MiniLM is a separate embedding dependency/cost. Its compatible
labels include navigation, card, dismissible structure, headings, text, media,
inputs/selects/buttons and links—excellent coverage for cheap candidate/weak
labels and browser-snapshot experiments.

Its model card also states that its approximately 135 pages were labelled by a
deterministic heuristic pipeline, the data are not distributed, and its held-out
split is page-stratified. The reported F1 for `structure_dismissible` is 0.363.
Therefore, use predictions only as provenance-tagged weak supervision or an
error-analysis comparator; do not blend them into human gold or claim
independent generalization. It additionally requires rendered-browser features
that an HTML-only crawl does not have.

### `microsoft/markuplm-base`: credible encoder experiment, not a role model

[Microsoft's released MarkupLM base weights](https://huggingface.co/microsoft/markuplm-base)
are an established Apache-2.0 Transformers checkpoint. The model jointly uses
text and XPath; the public config is 12 layers/768 hidden units with a
512-token context. It can support a custom token/node-label head, so it is a
reasonable later comparison if a structure-aware transformer is needed.

It is pretrained for web QA/information extraction, however, and has no
header/footer/card/consent role head or compatible regional taxonomy. It is
also materially larger and more operationally involved than reusing the FC
checkpoint. Treat it as an optional teacher/embedding or fine-tuning experiment
after the WebClasSeg adaptation establishes a held-out-domain baseline.

## Do not select as the first reusable model

* [Web2Text](https://github.com/dalab/web2text) and
  [BoilerNet](https://github.com/mrjleo/boilernet) are binary
  main-content-versus-boilerplate systems. Their DOM-order/ancestor features are
  helpful design references, but their taxonomy cannot identify footer versus
  nav versus consent/form/card. Web2Text provides old TensorFlow-1.15/Scala
  machinery and reported checkpoints; BoilerNet's public repository documents
  training against external CleanEval/GoogleTrends data rather than a portable
  released checkpoint.
* [Pulpie Orange Small](https://huggingface.co/feyninc/pulpie-orange-small)
  is a current 210M HTML-block binary content extractor, but its currently
  declared license is CC-BY-NC-4.0 and it still only predicts main versus other.
  It may be a local research oracle if licensing permits; it is not a
  production dependency or a multi-role label source.
* [DOM-LM](https://huggingface.co/Lahad/dom-lm-pretrained) has an Apache-2.0
  checkpoint, but it is explicitly an **unofficial** RoBERTa-base
  reimplementation pretrained on SWDE. It needs five structural tensors from a
  separate preprocessing repository and supplies no region-classification head.
* [WebFormer](https://github.com/xrr233/Webformer) and
  [HTML-T5](https://openreview.net/pdf?id=9JQtrumvg8) are useful papers/code
  directions for structure extraction and web automation, respectively. The
  verified public WebFormer repository documents corpus preparation and
  pretraining rather than downloadable pretrained weights; I found no official
  HTML-T5 checkpoint suitable for DOM region classification. Reproducing either
  would replace reuse with a research training project.
