- New rule `crawl/server-errors` fails once per crawled page whose final response is 5xx, listing the URL and status code. A page that errors and then answers on a retry is stored as the healthy page it became and is not reported. A page still 5xx after the retries is now stored as an error page so the rule can see it. Throttled responses (429, or a 503 with `Retry-After`) are not server errors. A crawl that stopped at its page cap or left URLs queued reports the 5xx pages it did fetch but is not counted as clean, since a page it never reached may still be failing (squirrelscan/repo#2036).
