- Every Markdown report of an audit that ran has an accessibility checklist, before the report detail section: one row per WCAG 2.2 Level A and AA success criterion (55, without the obsolete 4.1.1) with what the rules found for it on this audit (rules found an issue, rules found no issue, rules did not run, or no rule covers it) and which rules ran, did not run and found something, read from the criteria each rule declares. A rule that ran and found nothing to check counts as run. Every row still needs a manual check, and the checklist says that automated checks cover only part of WCAG and passing them is not conformance. `squirrel report --wcag-checklist [markdown|csv]` prints only the checklist, as Markdown (the default) or as CSV with empty reviewer columns. A report read with `--input` does not carry passing checks, so the checklist says on stderr that a rule with no finding reads as not run. A failed or blocked audit ran no rules, so it gets no checklist: `--wcag-checklist` on one says so on stderr and exits 1. `images/alt-text` now cites 1.1.1 Non-text Content (Level A), so the checklist counts it on that row, its JSON issue carries `wcag` and `wcagLevel` and `wcagByLevel` lists it (the JSON schema stays 1.27), and its rule page lists the criterion. `--wcag-level` still filters accessibility rules only, so `images/alt-text` runs at every level. The WCAG criteria table in `@squirrelscan/core-contracts/wcag` now lists every Level A and AA criterion. See [accessibility coverage](https://docs.squirrelscan.com/guides/accessibility-coverage#accessibility-checklist) (squirrelscan/repo#3094).
