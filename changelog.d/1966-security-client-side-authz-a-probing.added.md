- `security/client-side-authz`, a probing rule for the classic vibe-coded authorization bug: the frontend hides the admin screens behind a role check, but the admin API checks nothing (squirrelscan/repo#1966). It finds admin and other privileged API endpoints your own pages and scripts reference (a path word such as `admin`, `staff` or `internal`), sends each one `GET` with no cookies, no credentials and no query string, and fails an endpoint whose 2xx answer is JSON that carries data, naming the field names and record count, never a value. A `401` or `403`, a redirect, an HTML page, an empty or health-shaped answer, or a `200` that says unauthorized is not flagged. It runs only when probing is `active` or `aggressive`, probes only the audited origin, at most eight endpoints, and never a path that names an action or a URL only called with a write method. An unauthenticated probe cannot show cross-tenant access, and the finding says so. See [security/client-side-authz](https://docs.squirrelscan.com/rules/security/client-side-authz). That makes 331 rules, 27 of them in Security.
