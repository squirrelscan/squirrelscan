- New rule `a11y/reduced-motion`: warns when a page has motion with no `prefers-reduced-motion` handling (WCAG 2.3.3 Animation from Interactions, Level AAA; 2.2.2 Pause, Stop, Hide is not declared because the rule does not look for a pause control). Motion is a looping CSS animation (`animation` or `-webkit-animation` set to `infinite`) in an inline `style` attribute or in a rule whose selector matches an element on the page, `scroll-behavior: smooth` in a rule whose selector matches (`html`, `:root`, `body` and `*` always do), a `<video>` with both `autoplay` and `loop`, `<marquee>`, an auto-advancing carousel, or a motion library (AOS, GSAP ScrollTrigger, Lottie, animate.css or WOW.js, parallax, Locomotive Scroll, Lenis) named in a script, stylesheet or preload URL path. Handling is an `@media (prefers-reduced-motion …)` rule in CSS, a script that calls `matchMedia` with the query, or a reduced-motion `media` attribute on a stylesheet; the words in body text or a comment do not count. Inline styles, same-site stylesheets and same-site scripts are read; when a linked stylesheet could not be read the page gets a skipped `reduced-motion-unverified` check, never a pass. Third-party stylesheets are not read, except that a sheet from a font-only host (Google Fonts, Bunny Fonts, Adobe Fonts, Fontshare) holds only `@font-face` rules and is ignored. Pages with no detected motion and no unread stylesheet gain a `reduced-motion` pass. Findings never show a stylesheet's credentials, query string or fragment. The first audit after the upgrade runs page rules fresh (rule cache `prc-9`). (#711)
