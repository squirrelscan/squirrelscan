# Component finding evaluation corpus

This is the reproducible synthetic evaluation artifact for #2307. Inventoried
Product Hunt project-database `pages` rows have no inline HTML, while the
separate shared content store has 29,504 archived `text/html` blobs (about
3.73 GB original, 944 MB compressed) in a single read snapshot at
2026-09-18 02:08:20 UTC. The shared table has no URLs, but a sampled current
crawl joined all 10 project-page `content_hash` values to shared hashes (one
distinct hash), so retained hash references can recover sources. No matching
linkage to the frozen September 17 selected sites/reports was established, so
no historic replay was attempted. The corpus uses only hand-authored
`example.invalid` HTML and contains no crawl bodies, credentials, or private
reports.

Run from the public worktree:

```sh
bun scripts/component-findings/evaluate.ts > scripts/component-findings/evaluation-result.stdout.json
```

The evaluator loads `content/stale-copyright` and `a11y/link-text` from frozen
baseline commit `be239e8c3e1795ceeb7a79af1959d31abcd42643` with `git show`, then
runs that source and the current rules through the same parser. It fails when a
baseline check or health score changes after removing only additive component
evidence, when an authored raw observation key is absent or added, or when an
expected `pathname#locator:kind` group membership differs. It also re-runs every case
under several input orderings (the original, the reverse, and rotations) and
requires both group IDs and memberships to be identical across all of them.

Every expected group is hand-authored, including singletons. The evaluation
compares every pair of eligible observations, so false merge pairs and missed
merge pairs are separate counters. Unknown, main-content, and article-nested
observations are counted as raw uncertain evidence and intentionally excluded
from actionable grouping. A legacy case supplies checks without component
evidence and verifies that legacy message grouping stays readable while no
component fix group is invented.

Cases include shared chrome across three layouts; class/language footer
variants with the same text; two generic links to the same target in separate
elements; multi-page `<base>` target splits and equivalent-target merges; an
article footer before a shared site footer; a current-year exception; repeated
cards; unknown regions; nested article versus site headers; one shared footer
where each page marks a different nav link active and prints a per-page string;
identical markup on two origins; and a region past the structural budget.

The last three cover regressions found in review. The per-page-state case pairs
with `shared-footer-across-layouts` to show that interaction state and region
text do not split a component, while the cross-origin case pairs with it to show
that the origin, not the path, is what separates one.

`evaluation-result.json` is generated by the evaluator. It records provenance,
exact memberships, raw uncertain coverage, pairwise counts, and independently
measured baseline/current runs after warmups on the corpus and a 1,000-link
synthetic page. Per case it also records `evidenceShape` (every observation
carries the site origin it was scoped to, every abstention records an
`uncertainReason`, no groupable observation comes from an unknown or
content-nested region, and every group id is a 128-bit digest rather than the
canonical identity) and `affectedPageCoverage` (the group's count equals its
distinct occurrence pages).

Two whole-pipeline sections sit beside the cases. `jsonSerialization` renders
the CLI JSON for the shared-footer case and checks that each observation is
serialized exactly once: fix groups carry `occurrenceRefs` into the owning
check's evidence instead of repeating it, every reference resolves, and each
group labels its page sample. `foldPageSample` folds three pages down to a
one-page sample and checks that unfolding rebuilds exactly the recorded rows —
never a row for a page the audit did not count — and reports the observations it
could not place as a `page-sample-limit` omission marker. Timing and heap deltas are same-process observations, not
production benchmarks or retained-memory measurements. Raw report-view bytes
include the legacy report view and component fix groups held in memory; they are
not wire payloads. `renderedJsonBytes` beside them IS the CLI JSON a run would
emit, and it is the number to read for payload cost.

That cost scales with the number of defective ELEMENTS, not pages. Signatures
are SHA-256 truncated to 128 bits (`s128:` + 32 hex) precisely because six of
them ride on every occurrence; `renderedJsonBytesAtFullWidthSignatures` beside
each measurement is the same report re-expanded to the original 64-hex width, so
the saving is visible rather than asserted. It is about 13-16%.

The remaining cost is structural, not a hash width: a single synthetic page with
1,000 generic footer links still renders about 1.74 MB of JSON against 1.5 KB at
baseline (2.08 MB before the truncation), and its rule run takes roughly 95 ms
against 1.7 ms. The evaluation corpus itself stays small. This is recorded as a
measured limit, not a solved problem. Both local persistence and cloud transport bound a finding payload at
`REPORT_LIMITS.maxFindingPayload`; evidence that does not fit is replaced by an
explicit omission marker rather than dropped silently, and the legacy fields stay
byte-identical when even the marker will not fit. Cloud and dashboard consumers
are unverified.

## Live parity spot check (2026-09-19)

A fresh, dated observation, not a replay of any historic crawl. Installed
`squirrel` v0.0.96 (the branch base) and the branch CLI each audited two of our
own public sites with `-m 12 --offline --http --refresh` into a clean store.

| Site | Overall score (base / branch) | Category scores | Checks | Evidence | Fix groups |
|---|---|---|---|---|---|
| squirrelscan.com | 78 / 78 | equal | 22, identical | 7 occurrences, all `region-main` (uncertain) | 0 |
| docs.squirrelscan.com | 50 / 50 | equal | 43, identical except one `perf/ttfb` timing warning (network variance between two live fetches) | 12 occurrences | 1: generic header link text, 12 affected pages |

Two sites are a smoke test, not a corpus evaluation. The synthetic fixtures in
`evaluate.ts` remain the merge-correctness evidence.
