The questions a skeptical developer asks first, answered briefly. Each answer links to the page it comes from, and those pages win if anything here is out of date.

## Is squirrelscan open source?

The `squirrel` CLI, the audit engine and the rule packages are [MIT licensed](https://github.com/squirrelscan/squirrelscan/blob/main/LICENSE) and live in the public repository. The hosted cloud is not in that repository.

Signed out, a local audit runs the deterministic rules on your machine and needs no account ([Local audits with the CLI](/guides/local-audits-cli)). These need the cloud ([Cloud overview](/cloud)):

- Browser rendering, for JavaScript-heavy sites
- AI analysis rules, such as [`ai/llm-parsability`](/rules/ai/llm-parsability) ([Cloud rules](/cloud/rules))
- Shared data: full ad blocker filter lists and a global dead-link cache
- Publishing reports, issue tracking over time, the dashboard and teams
- The [hosted MCP server](/developers/mcp)

## What does telemetry send?

Telemetry is on by default. The CLI sends the event name, the CLI version, a random install ID and a bounded error category. After `squirrel auth login` it also attaches your user ID, so events tie to your account. It does not send API keys, URLs, hosts, paths, email addresses, report contents or raw error messages, and it sends nothing when telemetry is off. The CLI shows this once before its first telemetry-enabled command ([`self` settings](/cli/self#telemetry)).

To turn it off:

```bash
squirrel self settings set telemetry false
```

For CI or one-off commands, set `NO_TELEMETRY` (any defined value disables it) or `DO_NOT_TRACK=1`. `squirrel audit --offline` sends no telemetry ([`audit` options](/cli/audit)).

The install script is separate. The host that serves it counts each fetch: script type, a coarse client class and an optional `?source=` tag, with no IP address kept. The script itself sends an anonymous report only when the install fails, and `NO_TELEMETRY` or `DO_NOT_TRACK=1` turns that off too ([Quickstart](/quickstart#installation)). The report is a fixed set of fields: the failing step, OS, architecture, release version, exit code and the tail of the failing command's output.

## Does it obey robots.txt?

Not by default. squirrelscan always fetches and parses `robots.txt` for sitemap discovery and the `crawl/robots-txt` audit rule, but with the default `respect_robots = false` it ignores `Disallow:` rules and `Crawl-delay:`. The reasoning: an audit is something you run against your own site, not an uninvited crawl.

Auditing a site you don't own? Opt in:

```toml
[crawler]
respect_robots = true
```

Cloud audits have the same switch per website ([crawl settings](/dashboard/crawl-settings#respect-robotstxt)). Cloud audits started over MCP or the API respect `robots.txt` by default. You can turn that off for a website you own. See [`respect_robots`](/configuration/crawler#respect_robots) for the CLI setting, and the next answers for the user agent.

## What does it cost?

- **Local audits are free** when you are signed out or pass `--offline`.
- **Signed in**, every audit spends credits: 50 per audit plus 2 per audited page, including audits you run locally with `squirrel audit`.
- **Free plan:** 500 credits a month, no card required, one allowance per email inbox.
- **Pro:** $19 a month ($190 a year) for 3,000 credits a month.

External link checks, top-ups and the Team plan are in [Credits and pricing](/cloud/credits). If your balance runs out, audits still run locally and cloud rules are skipped.

## How does it work with coding agents?

Output is built for an agent to read and act on: `--format llm` gives LLM-optimized output, and every finding says how to fix it ([Fix your site with an AI agent](/guides/fix-your-site-with-an-ai-agent)). Skills, a CLI MCP server and the [hosted MCP server](/developers/mcp) cover the rest ([Agents](/developers/agents)).

The audit rules are deterministic. Local audits run only those rules. The rules that use AI models are cloud rules, and they run only when you are signed in ([Cloud rules](/cloud/rules)). The fixing is done by your own coding agent.

## How is it different from Lighthouse or Screaming Frog?

Lighthouse audits one URL per run and goes deep on that page's performance. squirrelscan crawls the whole site and checks links, security headers, structured data and agent experience together. For one slow page, Lighthouse is still the right first stop. Details: [Lighthouse alternative](https://squirrelscan.com/learn/lighthouse-alternative).

Screaming Frog is a mature desktop crawler, strong at manual, exploratory work: filtering and segmenting a crawl, and custom extraction with XPath or CSS selectors, which squirrelscan does not have. squirrelscan does not render JavaScript locally either; rendering is a cloud feature. What it offers instead is a CLI that runs the same way in CI or inside a coding agent, with output meant for a model. Many teams use both. Details: [Screaming Frog alternative](https://squirrelscan.com/learn/screaming-frog-alternative).

## What user agent does it send, and how fast does it crawl?

**The CLI today.** With the default `user_agent = ""`, the first crawl draws a random modern browser user agent and pins it to the project, so every later run reuses it. It does not announce itself as squirrelscan. To identify the crawler, set `user_agent` yourself ([`user_agent`](/configuration/crawler#user_agent), and the example in [Rate-limited hosts](/guides/rate-limited-hosts)). The defaults are 5 concurrent requests and a 50 ms delay between requests to one host. A `429`, or a `503` with `Retry-After`, makes the host back off ([`concurrency`](/configuration/crawler#concurrency), [`per_host_delay_ms`](/configuration/crawler#per_host_delay_ms)).

**The cloud today.** Page fetches use a random current browser user agent chosen per audit, rendered pages use the headless Chrome user agent, and asset and external link checks send `SquirrelScan/2.0 (+https://squirrelscan.com)` ([What squirrelscan cloud looks like in your logs](/cloud/firewall#what-squirrelscan-cloud-looks-like-in-your-logs)).

**What changes for MCP and API audits.** Cloud audits started over MCP or the API identify as squirrelscan and respect `robots.txt` by default. You can override both per website after you confirm you own it.

## What does squirrelscan store, and for how long?

- **Local audits** are stored in a database on your machine and kept until you delete them ([Reports](/reports#delete-old-audits)).
- **Cached page copies in the cloud:** a cached render is reused for at most 7 days, cached page bodies for reusing a previous crawl expire after 7 days, and cached AI page analysis expires after 30 days.
- **Deleting a website** is a soft delete: its past audits, reports and issues are preserved, and published report links keep working ([Dashboard](/dashboard#deleting-a-website)).
- **Deleting a report** removes it from your lists and from its link. A copy already cached at the edge can be shown for at most about 3 minutes ([Dashboard](/dashboard#managing-reports)). The delete is a soft delete.
- **Retention periods in the privacy policy:** published reports are kept until you unpublish or delete them or close your account. Account and billing records are kept as long as the account is active and as the law requires. Email subscriptions are kept until you unsubscribe ([Privacy policy](https://squirrelscan.com/privacy)).

To have data erased, ask: the privacy policy lists the right to request deletion. Other data, such as telemetry, has no stated period.

## Is there a roadmap, and where do I report bugs?

There is no public roadmap, and GitHub Discussions is not enabled on the repository. To report a bug or ask for a feature, [open an issue](https://github.com/squirrelscan/squirrelscan/issues) on the public repository. For help with an account or an audit, use the [support page](https://squirrelscan.com/support) or email support@squirrelscan.com.
