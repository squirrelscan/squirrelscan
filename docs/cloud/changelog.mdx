Changes to squirrelscan cloud: the dashboard, cloud audits, the API and the hosted MCP server. The `squirrel` CLI has its own [release notes](https://squirrelscan.com/releases).

## 1.1.0 (in development)

### Added

- Overview and audit pages lead with section scores and counts, with one consistent chip style for statuses and severities.
- Issues get a new list, an issue page and a Findings view.
- A new website gets a short display name and description when you add it.
- You can switch rules on for a website or for a single run through the API and MCP, including rules its site type would normally skip.
- A sampled audit says what it did not check, and offers the audit that would.
- The dashboard shows the cloud version, which links to this changelog.

### Changed

- A website added from a start URL that redirects keeps the original host as an alias, and restoring an archived website checks its aliases again.
- The editor summary takes the site's profile and detected technologies into account.
- The editor summary no longer recommends something the site already has.
- A `robots.txt` that blocks the whole site leads the summary.
- A check the cloud cannot run yet is stated once as our limit, never ranked as a problem with your site.

### Fixed

- A cancelled plan shows as cancelling until it ends, and as ended after that.
- Comparing two audits marks findings as resolved correctly, including site-wide checks and findings the newer audit no longer reports.
- The sidebar Issues badge counts the same open issues the Issues list shows.
- A technology in more than one category appears once on the overview, with its categories together.
- The summary no longer claims a TLS certificate problem when no connection could be made to check it.
- The entity map's missing-id problem lists only entities that appear on more than one page, and says when part of the graph could not be built.
- A refund in your credit history is linked to the audit it belongs to.
