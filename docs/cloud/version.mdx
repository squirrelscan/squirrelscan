The squirrelscan cloud has one version. The API, dashboard, admin, web site and workers ship together, so they all report the same number.

## Separate from the CLI

The cloud version is not the [CLI](/cli) version. The CLI is numbered `v0.0.x` and releases on its own schedule; the cloud follows its own semantic version, starting at `1.1.0-dev<N>`. A CLI update does not change the cloud version, and a cloud deploy does not change the CLI's.

## What `-dev<N>` means

Before a release, each cloud version ends in `-dev<N>`, where `N` is the Nth deploy toward that release: `1.1.0-dev7` is the seventh deploy on the way to `1.1.0`. Treat the suffix as a label, not an ordering: never decide which of two builds is newer by parsing the string. Use the build sha shown next to it when you need to identify an exact build.

## Where to see it

- **Dashboard:** the version badge in the sidebar. Hover it for a tooltip with the build sha.
- **API:** `GET /health` returns `version` and `sha`.
- **MCP:** the [hosted MCP server](/developers/mcp) reports the cloud version as `serverInfo.version` in its `initialize` response. It is the cloud's version, not the CLI's, and it changes with cloud deploys.

## Cloud changelog

The cloud changelog will be linked here once it exists. The CLI's release notes are in the [CLI changelog](https://github.com/squirrelscan/squirrelscan/blob/main/CHANGELOG.md).
