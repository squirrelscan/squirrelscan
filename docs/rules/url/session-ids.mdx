## What a session ID in a URL costs

Some servers fall back to putting the session in the URL (`?PHPSESSID=...` or `;jsessionid=...`) when a client does not accept cookies. A crawler does not, so every crawler visit gets its own session and every link it follows carries a new one. The same page then exists at an unlimited number of addresses, which wastes crawl budget and splits ranking signals across duplicates.

The URL is also the credential. A link copied from the address bar and sent to someone else can hand them the visitor's session, and the ID leaks through the `Referer` header to other sites and into server and analytics logs. [url/parameters](/rules/url/parameters) counts parameters and flags tracking ones, but does not recognise session IDs.

## What squirrel checks

The rule runs on every crawled page and reads the page URL and its internal links. It never requests anything.

A parameter counts as a session ID when its name is one of `PHPSESSID`, `jsessionid`, `sid`, `sessionid`, `session_id` or starts with `ASPSESSIONID` (any letter case), or it is the ColdFusion pair `CFID` with `CFTOKEN` (the token at least 8 characters), and its value looks generated rather than written or counted. The query form (`?PHPSESSID=...`) and the path form (`/page;jsessionid=...`) are both detected.

The value test has two levels. Neither accepts a value of fewer than 8 characters, one made only of digits (a counter, a timestamp, a numeric id), or one with words joined by `-` or `_` (`summer-collection-2024`).

- `PHPSESSID`, `jsessionid`, `session_id` and `ASPSESSIONID*` only ever mean a session, so they take the looser test: 8 or more characters with a letter and a digit, or 16 or more characters with at least two of a letter, a digit and mixed case.
- `sid` and `sessionid` are ordinary words in other systems, so they take the strict test: 8 or more characters with a letter and a digit, or 24 or more characters in mixed case.

So `sid=2`, `sid=main`, `sid=summer-collection-2024`, `sid=1234567890123456` and a lone `CFID` are not flagged.

- Warn `session-id-in-url`: `Page URL carries a session ID (PHPSESSID)`. The item is the page URL with the value replaced by `…`.
- Warn `session-id-links`: `12 internal link(s) carry a session ID (jsessionid)`. Distinct links are counted, ten are listed, and `details.additional` counts the rest. Links to other hosts are not reported.
- Pass `session-ids`: `No session IDs in URLs`.

The session value is masked wherever it appears: in the item, the message and the details. The rest of the URL is kept so you can find the link.

## How to fix it

Keep the session in a cookie and stop the server from rewriting URLs.

- PHP: `session.use_only_cookies=1` and `session.use_trans_sid=0`.
- Java servlet containers: set the tracking mode to cookie only, or disable URL rewriting.
- ASP.NET: `cookieless="false"` in the session state settings.

Redirect the old URLs to the clean ones, and add a self-referencing canonical on the clean page.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["url/session-ids"]
```

### Disable all URL Structure rules

```toml squirrel.toml
[rules]
disable = ["url/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["url/session-ids"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.
