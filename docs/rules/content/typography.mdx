## What typographic hygiene is

Each of these is trivial on its own. Together they are the tell that nobody proofread the page: two spaces between words, a page that uses both `"straight"` and `“curly”` quotes, a stray space before a comma, or `--` typed where a dash was meant. The rule is deliberately low-key. It is an info rule and it cannot move the health score more than any other info-class rule.

## What squirrel checks

The rule runs on every crawled page over the rendered prose in `<body>`. It leaves out `<script>`, `<style>`, `<noscript>`, `<pre>`, `<code>`, `<samp>`, `<kbd>`, code editors and syntax highlighters, so quoted source is never judged. It emits a single check named `typography`:

- Skipped when there is no parsed document or no `<body>`.
- Pass when nothing matched. Message: `No typographic inconsistencies in body copy`.
- Warn when something matched. Message: `3 typographic issue(s) in body copy (double-space, mixed-quotes)`.
- Fail when 20 or more occurrences were found in total.

The four families:

| Kind | What matches |
|---|---|
| `double-space` | Two or more spaces, or a space beside a no-break space, between two words on one line |
| `mixed-quotes` | Straight and curly double quotes both present, or straight and curly single quotes and apostrophes both present. A page that is all straight or all curly is clean |
| `space-before-punctuation` | A word, a single space, then `, . ; : ! ?` that ends the word. Ellipses, domains such as `example.com` and emoticons are not matched |
| `double-hyphen-dash` | `--` surrounded by spaces, or glued between two words. `---`, `-->` and a CLI flag such as `--verbose` are not matched |

Some locales put a space before `; : ! ?` on purpose. French is the main one, and the space-before-punctuation check is not run when the page's `lang` is `fr` or one of the languages that follow French typography (`br`, `oc`, `co`, `wa`, `ht`, `ln`, `wo`, `mg`). It is also not run when the page declares no `lang` at all, because a French page and a sloppy English page cannot be told apart. The other three checks always run.

Note that browsers collapse repeated spaces when they render, so a double space is a source hygiene signal rather than something a visitor sees, unless it uses a no-break space.

## How to fix it

Pick one convention and apply it everywhere. Let your editor or CMS smart-quote the copy so quotes and apostrophes come out consistent. Use CSS, not extra spaces, for layout. Replace `--` with an em dash, or with a comma, colon or full stop. If the page is French, set `<html lang="fr">`.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["content/typography"]
```

### Disable all Content rules

```toml squirrel.toml
[rules]
disable = ["content/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["content/typography"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.
