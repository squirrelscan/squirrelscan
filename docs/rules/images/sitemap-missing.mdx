## What an image sitemap is

Google's image sitemap extension lets a `<url>` entry list the images on that page with `<image:image><image:loc>`. It is the documented way to make images discoverable when they load by script or sit behind a gallery, which matters most for shops. Shopify and most sitemap plugins write these entries by default.

## What squirrel checks

The rule makes no network request. squirrel's sitemap reader keeps up to 50 image entries per `<url>`, and the rule compares them with the page's main image: the `og:image`, or the `image` of a Product (or ProductGroup) JSON-LD block. An `ImageObject` or a list of images is read too. If any one candidate is in the page's entries, the page passes.

Image URLs are normalized before they are compared, so these count as the same image: the scheme, the query string and the fragment are ignored, and a CDN size suffix is removed (Shopify's `_800x` and `_1200x630`, WordPress's `-300x200`). Shopify serves one file under two URLs, the shop's own `/cdn/shop/files/mug.png` and `cdn.shopify.com/s/files/1/<store id>/files/mug.png`, and the rule treats them as the same image. A stock Shopify sitemap therefore produces no finding.

The rule only judges a page that is:

- served with status 200;
- indexable: no `noindex` in the robots meta tag or the `X-Robots-Tag` header;
- self-canonical, or without a canonical;
- listed in a sitemap with at least one image entry of its own (a stock Shopify sitemap lists the homepage and `/pages/*` without images, and those are not judged);
- not marked as having more image entries than squirrel keeps.

A page with no `og:image` and no Product image is not flagged.

**A site whose sitemaps carry no image entries at all is skipped, not flagged.** Image sitemaps are optional, and a finding on every page of a site that never adopted them is noise. The rule starts to apply once any sitemap lists image entries.

It emits one check, `sitemap-missing-image`, info severity: `Main image is not in the page's sitemap image entries`. It passes with `The page's main image is in its sitemap image entries`.

## How to fix it

Add the image under the page's `<url>`:

```xml
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
        xmlns:image="http://www.google.com/schemas/sitemap-image/1.1">
  <url>
    <loc>https://shop.example.com/products/mug</loc>
    <image:image>
      <image:loc>https://cdn.example.com/products/mug.jpg</image:loc>
    </image:image>
  </url>
</urlset>
```

Or turn on image entries in your platform or sitemap plugin.

## Check names by outcome

Each check name this rule can emit, by what it means to a tool comparing two audits. A **problem** check is a finding. A **clean** check says the rule ran over what it covers and found nothing; it clears the problem checks listed beside it, so a finding is fixed when the rule ran over the same scope and a clean check took its place. A **not checked** check says the rule did not evaluate, and never clears a finding.
