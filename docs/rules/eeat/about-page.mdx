## What an About page is for

An About page answers who is behind this site. For a reader deciding whether to trust what they are reading, it is often the second page they open, and for Google's helpful-content guidance it is where the who and the why of a site are supposed to be answerable.

A page that exists and says three sentences does not do that job. What makes it work is specifics: who runs the organisation, what they have done, how long they have been doing it, and how to reach them.

## What squirrel checks

The rule is site-wide. It looks for an About page in three ways: a URL path at one of the configured `paths` (see Options), a URL path matching one of the built-in multilingual about patterns (slugs such as `/about`, `/about-us`, `/ueber-uns`, `/wer-wir-sind` and `/unsere-geschichte`, also under `/pages/`), or a page whose structured data declares the `AboutPage` type. `/team`, `/the-team`, `/das-team`, `/agentur` and `/agency` are deliberately not built-in slugs: a team or agency page is often not an About page, so a site that uses one names it in `paths`. The first match wins. It emits a single check named `about-page`:

- Skipped when no pages were crawled. Message: `No pages available for analysis`.
- Pass when the page is found and has 200 words or more. Message: `About page exists with substantial content`, with the URL as the value. Severity warning, weight 5.
- Info when it is found with fewer than 200 words. Message: `About page exists but has limited content`, with `N words - consider expanding` as the value.
- Pass when no page matches but a crawled page has an About section: an element whose `id` matches an about slug (`about`, `about-us`, a localised one), matched as if it were the path `/<id>`, and a same-page link to it (`href="#about"`) so a stray id does not count. Message: `About section found on the homepage (#about)`, with the URL and fragment as the value. It uses the same 200-word bar, counted over the section: fewer is info, `About section exists on the homepage (#about) but has limited content`. A real About page always takes precedence, and this is what a one-page site needs.
- Info when no crawled page is the About page but a crawled page links to one the crawl did not fetch. Message: `About page linked but not crawled`, with the link target as the value and the linking page in the details.
- Warn instead when the internal link probe requested that uncrawled target and got a 4xx or 5xx. Message: `About page link returns N`, where `N` is the status. A 401, a 403 or a rate limit is not read as broken and stays info.
- Warn when there is neither a crawled About page nor a link to one. Message: `No About page found`, with `Create /about or /about-us page` as the value.

The schema fallback exists so a localised path the URL patterns do not recognise is still found.

A crawl that excludes the About page's path, or reaches its page limit first, never fetches it. A link to the same host whose href matches one of the about patterns is evidence the page exists, not proof that it works, so the rule says it is linked but not crawled instead of advising you to create one. Anchor text alone does not count. No extra requests are made: the only status the rule can report is one the internal link probe already recorded, and the probe never requests a path the crawl scope or robots.txt excludes. To have the page checked, let the crawl fetch it. [eeat/privacy-policy](/rules/eeat/privacy-policy) and [eeat/contact-page](/rules/eeat/contact-page) treat their pages the same way.

## How to fix it

On a one-page site you do not need a separate page. Give the section an id (`<section id="about">`), link it from the navigation (`<a href="#about">`), and put real content in it.

Write the page for someone who has never heard of you: who runs this, what you do, what you have done before, where you are. Link it from the main navigation or the footer so it is reachable from every page.

The word threshold is a proxy for that. Padding the page to 200 words does not make it convincing.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `paths` | string[] | `[]` | Site-specific paths of the page, checked in addition to the built-in slugs. Patterns are matched like [`excludePatterns`](/configuration/rule-options#url-patterns), against the URL's path only (never the host, query string or fragment): a substring of the path, `/exact-segment/`, or `regex:`. |

### Configuration example

```toml squirrel.toml
[rule_options."eeat/about-page"]
paths = ["/pages/manufaktur"]
```

A crawled page at a configured path counts as the page, with no structured data needed, and a configured path that pages link to but the crawl did not fetch is reported as linked but not crawled, as for a built-in slug. A `paths` value that is not an array of strings, or a `regex:` entry that does not compile, is reported by `squirrel config validate`.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["eeat/about-page"]
```

### Disable all E-E-A-T rules

```toml squirrel.toml
[rules]
disable = ["eeat/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["eeat/about-page"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.
