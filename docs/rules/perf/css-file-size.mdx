title: "CSS file too large: the 150 KB and 500 KB thresholds"
description: "Stylesheets over 150 KB warn and over 500 KB fail. squirrel measures every CSS file the crawl found and names the pages that load it."
---

## What CSS file size costs

A stylesheet blocks rendering. The browser will not paint until it has fetched and parsed every stylesheet in `<head>`, so the size of that file sits directly on first paint, on slow connections and on cheap phones most of all.

Size usually comes from three places: a framework shipped whole rather than as the parts the site uses, selectors for pages that no longer exist, and no minification. Splitting a large stylesheet by route, inlining the styles the first screen needs and loading the rest asynchronously all attack the same number.

## What squirrel checks

The rule runs once per crawl over the CSS resources the crawl collected, with their sizes and the pages that referenced them. It emits one or two checks:

- `css-file-size`, passing with the message `No CSS files detected` when the crawl found none.
- `css-file-size`, failing with the message `N CSS file(s) exceed 500.0 KB` and one item per file, carrying its size, HTTP status, content type and the pages that load it.
- `css-file-size-warn`, warning with the message `N CSS file(s) exceed 150.0 KB` for files above the warning threshold but not above the error one, with the same items.
- `css-file-size`, passing with the message `All CSS files are within size limits` when nothing crossed either threshold.

Both thresholds are measured against the transferred size the crawl observed. A file whose size could not be determined is counted in neither bucket, so a resource the crawl could not fetch is silently excluded rather than reported as oversized. The fail and warn checks can both appear on the same audit, since they cover different files.

## How to fix it

Split the stylesheet so a page loads only what it needs, and load the rest without blocking:

```html
<link rel="stylesheet" href="/critical.css" />
<link rel="stylesheet" href="/rest.css" media="print" onload="this.media='all'" />
```

Then remove what nothing uses. A build-time purge against the templates is more reliable than reading the file, because a class used only in a rarely rendered branch is easy to delete by hand and hard to notice missing.

The common false positive is a single stylesheet deliberately shipped for the whole site and cached across every page. It still blocks the first render, so the finding is true, but the second page view pays nothing.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `warn_bytes` | number | `153600` (150 KB) | Byte size to trigger warning |
| `error_bytes` | number | `512000` (500 KB) | Byte size to trigger error |

### Configuration example

```toml squirrel.toml
[rules."perf/css-file-size"]
warn_bytes = 153600
error_bytes = 512000
```

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["perf/css-file-size"]
```

### Disable all Performance rules

```toml squirrel.toml
[rules]
disable = ["perf/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["perf/css-file-size"]
disable = ["*"]
```
