## What DOM size costs

Every element on a page is memory the browser holds, work the style engine repeats on each recalculation, and work the layout engine repeats on each reflow. Past a few thousand nodes the cost shows up as slow interactions rather than slow loading, because each click that changes a class forces the engine over the whole tree again.

Three numbers describe the shape of the problem. Total node count is the size of the tree. Depth is how far nesting goes, and deep trees make selector matching and layout more expensive per node. The widest element, meaning the one with the most direct children, is usually a list that renders every row instead of the rows on screen.

## What squirrel checks

The rule runs on every crawled page, counting element nodes only, starting from the root `<html>` element and including it. It emits three checks:

- `dom-total-nodes`: passes with the message `DOM size OK (N nodes)` under 1,500 nodes, warns with `Large DOM (N nodes)` from 1,500 to 2,999, and fails with `Excessive DOM size (N nodes)` at 3,000 or more.
- `dom-depth`: passes with the message `DOM depth OK (N levels)` at 32 levels or fewer, and warns with `DOM depth excessive (N levels)` above that. The root element counts as level 1.
- `dom-max-children`: passes with the message `Max children per element OK (N)` when no element has more than 60 direct children, and warns with `Element with N children found` above that, naming the largest count on the page.

Instead of all three, a single `dom-total-nodes` check is emitted as skipped with the message `No document root found` when the parse produced no root element. A page with no parsed document emits nothing at all.

The counts are taken from the HTML the crawl fetched. On a [browser-rendered](/guides/browser-rendering) audit that is the hydrated DOM, and on a raw crawl it is the markup the server sent, which can be far smaller on a client-rendered page.

## How to fix it

Render the rows that are on screen rather than all of them:

```jsx
import { FixedSizeList } from "react-window";

<FixedSizeList height={600} itemCount={rows.length} itemSize={40}>
  {Row}
</FixedSizeList>
```

For depth, the usual cause is wrapper elements added one at a time by nested components. Collapsing three divs that each set one style property into one element with three properties removes two levels everywhere that component appears.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `warn_threshold` | number | `1500` | Warning threshold for total nodes |
| `error_threshold` | number | `3000` | Error threshold for total nodes |
| `max_depth` | number | `32` | Maximum DOM depth |
| `max_children` | number | `60` | Maximum children per element |

### Configuration example

```toml squirrel.toml
[rules."perf/dom-size"]
warn_threshold = 1500
error_threshold = 3000
max_depth = 32
max_children = 60
```

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["perf/dom-size"]
```

### Disable all Performance rules

```toml squirrel.toml
[rules]
disable = ["perf/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["perf/dom-size"]
disable = ["*"]
```
