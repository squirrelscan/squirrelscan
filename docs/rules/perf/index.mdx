Performance rules read the HTML and the response headers to find what makes a page slow: render-blocking resources, oversized CSS and JavaScript, missing caching and compression, and the markup patterns behind each Core Web Vital. They report the causes a static read can see, not the metrics themselves, which need a real browser to measure.

<Note>squirrelscan does not measure LCP, INP or CLS. Each one is a measurement of a real render, so these rules flag the causes instead: a hero image that is lazy-loaded, not preloaded or not prioritised (LCP), images and iframes with no width and height (CLS), and third-party script load (INP). [Audits that need a browser](/rules/perf/browser-required) lists what a static audit cannot measure. Field data from real visitors is what tells you whether a metric is failing.</Note>

## Run only these rules

```bash
squirrel audit https://example.com --rule-include perf
```

[Reliability](/rules/reliability), the other category in the Performance score group, has its own code. Add it with `--rule-include perf,reliability`.

## Where to start

These carry the highest severity and weight in the category.

- [JavaScript bundle too large: the 250 KB and 1 MB limits](/rules/perf/js-file-size): Scripts over 250 KB warn and over 1 MB fail. squirrel measures every JavaScript file the crawl found and names the pages that load it.
- [CSS file too large: the 150 KB and 500 KB thresholds](/rules/perf/css-file-size): Stylesheets over 150 KB warn and over 500 KB fail. squirrel measures every CSS file the crawl found and names the pages that load it.
- [LCP image not preloaded: what squirrel counts as a hero](/rules/perf/lcp-hints): Likely Largest Contentful Paint images loaded with no preload. squirrel looks at the first three eligible candidate images on every page, and one preloaded candidate satisfies the check.
- [Time to First Byte: the 600ms and 1000ms thresholds](/rules/perf/ttfb): A server that takes over 600ms to send the first byte, or over 1000ms. squirrel measures TTFB on every fresh fetch.
- [Images without width and height: the CLS risk squirrel finds](/rules/perf/cls-hints): Images and iframes with no dimensions, so the browser cannot reserve space before they load. squirrel lists every one by page.

## Key terms

- [Client-side redirect](/glossary#client-side-redirect): A redirect done in the page (meta refresh or JavaScript) rather than with an HTTP 3xx response.
- [Client-side rendering](/glossary/client-side-rendering): Building page content in the browser with JavaScript; agents and many fetchers that do not run JavaScript see an empty page.
- [Core Web Vitals](/glossary/core-web-vitals): Google's three user-experience metrics: LCP for loading, INP for responsiveness and CLS for visual stability, judged at the 75th percentile of real visits.
- [Cumulative Layout Shift (CLS)](/glossary/cls): A score for how much visible content moves unexpectedly while the page is in use; good is 0.1 or less.
- [DOM size](/glossary#dom-size): The number and depth of elements in a page's document tree; large DOMs slow style calculation and interactions.
- [fetchpriority](/glossary#fetchpriority): An HTML attribute (high, low, auto) that hints how urgently the browser should fetch an image, script or link.
- [font-display](/glossary#font-display): The @font-face descriptor (swap, optional, fallback) that decides what text shows while a web font loads.
- [HTTP caching](/glossary/http-caching): Response headers (Cache-Control, ETag, Expires) that let browsers and CDNs reuse a response instead of fetching it again.
- [HTTP compression](/glossary#http-compression): Compressing text responses (HTML, CSS, JS, JSON) with gzip, Brotli or zstd, signalled by Content-Encoding.
- [Image width and height attributes](/glossary#image-dimensions): Declared width and height on `<img>` that let the browser reserve space before the file loads, preventing layout shift.
- [Interaction to Next Paint (INP)](/glossary/inp): The latency from a user interaction to the next frame, taken across the visit; good is 200 milliseconds or less. It replaced FID in March 2024.
- [Largest Contentful Paint (LCP)](/glossary/lcp): The time until the largest image or text block in the viewport renders; good is 2.5 seconds or less.
- [Lazy loading](/glossary/lazy-loading): Deferring off-screen images and iframes with loading="lazy" so they load as the visitor scrolls.
- [Leaked secrets](/glossary/leaked-secrets): Credentials or private keys shipped to the browser in HTML, scripts or source maps.
- [Minification](/glossary#minification): Removing whitespace, comments and long names from CSS and JavaScript so the file is smaller without changing behaviour.
- [Modern image formats](/glossary#modern-image-formats): WebP and AVIF, which encode the same image in fewer bytes than JPEG or PNG.
- [Page weight](/glossary#page-weight): The total bytes a page downloads across HTML, CSS, JavaScript, images and fonts.
- [Redirect chain](/glossary/redirect-chain): A sequence of two or more redirects between the requested URL and the final response.
- [Render-blocking resources](/glossary/render-blocking-resources): Stylesheets and synchronous scripts in the head that the browser must fetch before it can paint anything.
- [Time to First Byte (TTFB)](/glossary#ttfb): The time from the request until the first byte of the response arrives, covering redirects, DNS, connection and server time.
