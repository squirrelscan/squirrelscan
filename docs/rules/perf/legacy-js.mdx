## What legacy JavaScript is

A polyfill implements a feature the browser lacks. A transpiler rewrites modern syntax into older syntax that more browsers understand. Both were necessary when a meaningful share of traffic ran browsers without `Promise` or arrow functions. That share is now small, and the code is still shipped by default in many build configurations.

The cost is bytes and parse time for every visitor, including the majority whose browser needed none of it. The lever is the build target: a `browserslist` that names modern browsers makes the transpiler and the polyfill injector emit far less.

## What squirrel checks

The rule runs on every crawled page and looks at three things. It emits one to three checks:

- `legacy-polyfills`: warns with the message `N legacy polyfill(s) detected`, listing each by name. It matches eleven patterns in `<script src>` URLs: `core-js`, `regenerator-runtime`, `babel-polyfill`, `polyfill.io`, `es5-shim`, `es6-shim`, `promise-polyfill`, `fetch-polyfill`, `whatwg-fetch`, `@babel/runtime` and `tslib`.
- `es5-code-patterns`: reports at info status with the message `N ES5 transpilation pattern(s) found`, listing up to five. It scans inline scripts over 500 characters, skipping any whose type mentions `json`, for nine signatures including `_classCallCheck`, `_createClass`, `_inherits`, `_typeof`, `__esModule`, `__spreadArray`, `__awaiter` and `__generator`.
- `differential-serving`: passes with the message `Uses module/nomodule differential serving` when the page has both a `script[type="module"]` and a `nomodule` script.
- `es-modules`: passes with the message `N ES module script(s) detected` when there are module scripts but no `nomodule` counterpart.
- `legacy-js`: reports at info status with the message `No legacy JavaScript patterns detected` when there are no polyfills, no ES5 patterns and no module scripts.

Every result here is a warning at most, and the rule's severity is info. A page with no parsed document emits nothing at all.

## How to fix it

Set the build target to the browsers you actually support:

```json
{
  "browserslist": ["> 0.5%", "last 2 versions", "not dead"]
}
```

Both Babel and TypeScript read that list, and a modern target removes most of the helpers and nearly all of the polyfills. Where a specific feature still needs one, importing that polyfill alone is far smaller than a whole `core-js` bundle.

The common false positive is `tslib`. It is TypeScript's helper library rather than a polyfill, and importing it is usually the smaller option, because the alternative is inlining the same helpers into every file that needs them.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["perf/legacy-js"]
```

### Disable all Performance rules

```toml squirrel.toml
[rules]
disable = ["perf/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["perf/legacy-js"]
disable = ["*"]
```
