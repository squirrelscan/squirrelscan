## What total page weight is

Total page weight is the sum of everything a visitor downloads. It matters most on a metered or slow connection, where it converts directly into waiting, and it is the number that best predicts how a site behaves on a phone in a place with poor coverage.

Images are usually the largest share and the easiest to cut, through a modern format and a size that matches the layout rather than the original upload. JavaScript is the next largest and the hardest, because cutting it means removing a dependency rather than re-encoding a file.

## What squirrel checks

The rule runs once per crawl and sums what it measured: inline CSS and inline JavaScript across every page, plus the external CSS, script and image resources the crawl collected, each counted once by URL. It emits one check named `total-byte-weight`:

- Passing with the message `Total tracked resources: NKB` under 1,600 KB.
- Warning with the message `Total tracked resources: NKB (heavy page)` from 1,600 to 4,999 KB.
- Failing with the message `Total tracked resources: NKB (very heavy)` at 5,000 KB or above.

When the crawl collected no external resource sizes at all, the rule estimates instead, from the first page's counts at 30 KB per stylesheet, 50 KB per script and 100 KB per image. In that case the message opens `Estimated total:` rather than `Total tracked resources:` and the details record that it is an estimate.

The details carry the breakdown: CSS, JavaScript and image totals, the inline against external split where both are present, and the number of distinct files in each pool. Inline JavaScript excludes any `<script>` whose type mentions `json` or `template`, so JSON-LD is not counted as code. Fonts have their own bucket in the sum but the crawl does not populate it today, so a font-heavy site is undercounted.

## How to fix it

Start with images, since they are usually most of the number:

```html
<picture>
  <source srcset="/hero.avif" type="image/avif" />
  <source srcset="/hero.webp" type="image/webp" />
  <img src="/hero.jpg" width="1200" height="630" alt="" />
</picture>
```

Then serve dimensions that match the layout rather than the original file, and lazy-load everything below the fold. For JavaScript, the lever is which dependencies ship rather than how they are bundled.

The common false positive follows from what is summed. The total covers every distinct resource the crawl found across the whole site, not the weight of one page load, so a large site with many unique images reports a large number even when each page is light.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `warn_threshold_kb` | number | `1600` | Warning threshold for total page weight in KB |
| `error_threshold_kb` | number | `5000` | Error threshold for total page weight in KB |

### Configuration example

```toml squirrel.toml
[rules."perf/total-byte-weight"]
warn_threshold_kb = 1600
error_threshold_kb = 5000
```

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["perf/total-byte-weight"]
```

### Disable all Performance rules

```toml squirrel.toml
[rules]
disable = ["perf/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["perf/total-byte-weight"]
disable = ["*"]
```
