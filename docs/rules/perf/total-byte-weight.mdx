## What total page weight is

Total page weight is the sum of the documents and sub-resources a visitor downloads. It matters most on a metered or slow connection, where it converts directly into waiting, and it is the number that best predicts how a site behaves on a phone in a place with poor coverage.

Images are usually the largest share and the easiest to cut, through a modern format and a size that matches the layout rather than the original upload. JavaScript is the next largest and the hardest, because cutting it means removing a dependency rather than re-encoding a file.

## What squirrel checks

The rule runs once per crawl and sums what it measured: the size of each crawled HTML document, inline CSS and inline JavaScript across every page, plus the external CSS, script, image and font resources the crawl collected, each counted once by URL. It emits one check named `total-byte-weight`:

- Passing with the message `Total tracked resources: NKB` under 1,600 KB.
- Warning with the message `Total tracked resources: NKB (heavy page)` from 1,600 KB up to but not including 5,000 KB.
- Failing with the message `Total tracked resources: NKB (very heavy)` at 5,000 KB or above.

The threshold comparison uses the unrounded total, while the message prints it rounded, so a total of 1,599.6 KB warns and displays as `1600KB`.

When the crawl produced no resource-size record and no script record at all, the rule estimates instead, from the first page's counts at 30 KB per stylesheet, 50 KB per script and 100 KB per image. An empty record still counts as present, so a crawl that collected the containers but measured nothing reports 0 KB rather than an estimate. In that case the message opens `Estimated total:` rather than `Total tracked resources:` and the details record that it is an estimate.

The details carry the breakdown: HTML, CSS, JavaScript, image and font totals, the inline against external split where both are present, and the number of distinct files in each pool. A bucket with nothing in it is left out. Inline JavaScript excludes any `<script>` whose type mentions `json` or `template`, so JSON-LD is not counted as code. The HTML bucket is the response size the crawler recorded for each crawled page. A page with no recorded size contributes nothing.

Fonts are the woff, woff2, ttf, otf and eot files a page names directly: a `<link rel="preload" as="font">`, or a `url()` source in an `@font-face` rule inside an inline `<style>`. Same-site fonts are sized with a HEAD request, like images. A font that only an external stylesheet declares is not found, because stylesheet files are not read, so a site that loads all its fonts from a `.css` file reports a fonts bucket of zero.

Elements inside `<noscript>` are skipped: a browser with scripting enabled reads `<noscript>` content as plain text, so nothing in it loads or renders. See [content inside noscript](/rules#content-inside-noscript).

## How to fix it

Start with images, since they are usually most of the number:

```html
<picture>
  <source srcset="/hero.avif" type="image/avif" />
  <source srcset="/hero.webp" type="image/webp" />
  <img src="/hero.jpg" width="1200" height="630" alt="" />
</picture>
```

Then serve dimensions that match the layout rather than the original file, and lazy-load everything below the fold. For JavaScript, the lever is which dependencies ship rather than how they are bundled.

The common false positive follows from what is summed. The total covers every distinct resource the crawl found across the whole site, not the weight of one page load, so a large site with many unique images reports a large number even when each page is light.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `warn_threshold_kb` | number | `1600` | Warning threshold for total page weight in KB |
| `error_threshold_kb` | number | `5000` | Error threshold for total page weight in KB |

### Configuration example

```toml squirrel.toml
[rules."perf/total-byte-weight"]
warn_threshold_kb = 1600
error_threshold_kb = 5000
```

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["perf/total-byte-weight"]
```

### Disable all Performance rules

```toml squirrel.toml
[rules]
disable = ["perf/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["perf/total-byte-weight"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.
