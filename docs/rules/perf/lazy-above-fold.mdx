## What lazy loading does

`loading="lazy"` tells the browser to hold the request until the element comes within its loading distance of the viewport. For an image well below the fold that is exactly right: the bytes are never fetched if the visitor does not scroll that far.

For an image in the first screen it is the wrong instruction. The browser has to complete layout before it knows the element is visible, so the fetch starts later than it would have with no attribute at all. When that image is the Largest Contentful Paint element, the delay lands directly on the metric.

## What squirrel checks

The rule runs on every crawled page. It walks `<img>` elements in document order and considers the first three that could plausibly be above the fold. It emits one check:

- `lazy-above-fold`: warns with the message `N above-fold image(s) with lazy loading` and lists each `src`. Otherwise it passes with `No lazy loading on above-fold images`.

Three kinds of image are skipped without using up one of the three slots, so a genuinely visible image further down the markup still gets judged. An image is skipped when it or an ancestor is `aria-hidden="true"`, `hidden` or `inert`, or carries an inline `display: none`; when it sits in an inactive carousel slide; or when it is inside a `<footer>`.

A slide counts as inactive when its group has at least two slides and it is not the active one. Active is read from an explicit marker where one exists, meaning `.active`, `.is-active`, `.swiper-slide-active`, `.slick-active`, `.splide__slide--active`, `aria-current="true"` or `aria-hidden="false"`, and falls back to the first slide in DOM order only when no slide in the group is marked. Images whose `src` is a `data:` URI or contains `pixel` or `spacer` are skipped too, also without using a slot. A page with no parsed document emits nothing at all.

## How to fix it

```html
<img src="/hero.jpg" width="1200" height="630" fetchpriority="high" alt="" />
```

Leave the hero with no `loading` attribute and add `fetchpriority="high"`. Keep `loading="lazy"` for everything below the fold, which is what [images/offscreen-lazy](/rules/images/offscreen-lazy) checks.

The common false positive is a page whose first three images are all genuinely below the fold, for example under a full-height banner that is a CSS background. DOM order is the only fold signal a static read has, so those images are judged as if they were visible.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["perf/lazy-above-fold"]
```

### Disable all Performance rules

```toml squirrel.toml
[rules]
disable = ["perf/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["perf/lazy-above-fold"]
disable = ["*"]
```
