## What asset compression is

Server configuration usually compresses `text/html` and stops there. The MIME types a page actually spends its bytes on, `text/css` and `application/javascript`, have to be listed separately in nginx `gzip_types` or Apache `AddOutputFilterByType`, and it is easy to ship a site where the document is compressed and everything it loads is not.

The saving on text is large enough that this is worth checking separately from the document. Brotli beats gzip on text and every current browser accepts it; `zstd` and the shared-dictionary codings are newer and also count.

## What squirrel checks

The rule runs once per crawl over the CSS, image and script resources the crawl collected. Images are included because SVG lands in that pool and is text. It emits one check named `asset-compression`:

- Skipped with the message `No sub-resources were crawled` when the crawl collected none.
- Skipped with the message `No compressible text assets with observed response headers` when none of them can be judged.
- Passing with the message `All N compressible asset(s) are compressed or under 100.0 KB`.
- Warning with the message `N text asset(s) over 100.0 KB served without compression`, the expectation `gzip, Brotli, or zstd on every large text asset`, and one item per asset, largest first.

An asset is judged only when its status was 2xx, it recorded no error, it was fetched on this run rather than reused from a cached record, its content encoding was actually observed, and its content type is compressible. Those exclusions are the point: a record with no observed encoding cannot prove the server sent none, and reporting on it would invent a finding. Any declared coding counts as compressed, so a coding newer than this rule is never reported as uncompressed. `identity`, including a list of nothing but `identity` tokens, means no coding and does count.

## How to fix it

```nginx
gzip_types text/css application/javascript image/svg+xml application/json;
brotli_types text/css application/javascript image/svg+xml application/json;
```

Behind a CDN, check that compression is enabled for static file extensions rather than only for documents. The default on some configurations covers HTML alone.

There is no common false positive. The rule stays silent rather than judging an asset whose response headers it did not observe on this run.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `min_bytes` | number | `102400` (100 KB) | Only report uncompressed assets larger than this many bytes |

### Configuration example

```toml squirrel.toml
[rules."perf/asset-compression"]
min_bytes = 102400
```

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["perf/asset-compression"]
```

### Disable all Performance rules

```toml squirrel.toml
[rules]
disable = ["perf/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["perf/asset-compression"]
disable = ["*"]
```
