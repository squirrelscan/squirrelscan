## Why titles should be unique

A title that appears on twenty pages tells a reader choosing between twenty search results nothing. It also removes one of the clearer signals a search engine has for telling those pages apart, leaving it to work from content alone.

Duplicates are almost never written by hand. They come from a template that falls back to the site name when a page has no title of its own, from paginated listings that repeat page one's title, and from filter or sort parameters that produce many URLs for one page of content.

## What squirrel checks

The rule runs once per crawl. It normalises every non-empty page title by lowercasing it and collapsing runs of whitespace to a single space, groups pages by the result, and emits one check named `title-unique`:

- Skipped with the message `Need multiple pages to check uniqueness` when the crawl has fewer than two pages.
- Passing with the message `All page titles are unique` when no normalised title appears more than once.
- Warning with the message `N duplicate title(s) affecting M pages`. Each item is one group, identified by the first 60 characters of the title, labelled with the first 40 characters and the page count, and carrying every URL in the group.

Pages with no title are skipped rather than grouped together, so a site where fifty pages have no title at all passes this check with `All page titles are unique`. That case belongs to [core/meta-title](/rules/core/meta-title), which reports each of them individually.

The normalisation here is stricter than [content/duplicate-title](/rules/content/duplicate-title), which lowercases but does not collapse whitespace. Two titles differing only by a double space are duplicates to this rule and distinct to that one.

## How to fix it

Give the template a title that varies with the page, and a distinct one for paginated pages:

```html
<title>Configuring the build cache | Acme Docs</title>
<title>Guides, page 2 | Acme Docs</title>
```

Where the duplicates come from URL parameters serving the same content, the fix is a [canonical URL](/rules/core/canonical) rather than a new title, because those are one page rather than several.

The common false positive is a set of pages that genuinely are near-identical, such as location pages for the same service. Those still need distinct titles, and the duplicate title is a symptom of the page not being distinct either.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["core/title-unique"]
```

### Disable all Core SEO rules

```toml squirrel.toml
[rules]
disable = ["core/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["core/title-unique"]
disable = ["*"]
```
