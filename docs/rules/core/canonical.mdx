## What rel=canonical does

`<link rel="canonical">` names the URL a page wants search engines to treat as its address. When the same content is reachable at several URLs, through parameters, a trailing slash, or both `www` and the apex domain, the canonical is what consolidates the signals onto one of them.

It is a hint rather than an instruction, and search engines can pick a different URL when the evidence disagrees with the declaration. The common case is a self-referential canonical: every page names itself, which costs nothing and makes the parameterised copies point somewhere real. A relative reference is valid HTML, and Google recommends an absolute URL because a relative one is easy to resolve against the wrong base.

## What squirrel checks

The rule runs on every crawled page against the parsed canonical value. It emits one check named `canonical`:

- Warning with the message `Missing canonical URL` and a null value when there is no canonical.
- Failing with the message `Canonical URL should be absolute` and the expectation `Absolute URL starting with https://` when the value does not begin with `http`.
- Failing with the message `Invalid canonical URL format` when the value begins with `http` but does not parse as a URL.
- At info status with the message `Canonical points to different URL` when it parses and does not match the page's own URL exactly.
- Passing with the message `Self-referential canonical present` when it matches.

The comparison is between the two full URLs after parsing, so a difference in trailing slash, in scheme, or in query string is enough to make it a different URL. That result is informational rather than a warning, because pointing elsewhere is often correct.

## How to fix it

```html
<link rel="canonical" href="https://example.com/guides/build-cache" />
```

Emit it from the router's own knowledge of the route, so it is absolute, uses one scheme and one host, and matches whatever form the rest of the site uses.

The common false positive is a filtered or sorted view that canonicalises to the unfiltered page, which is correct and reports as pointing to a different URL. That result is informational, not a defect. A paginated listing whose pages canonicalise to themselves passes normally.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["core/canonical"]
```

### Disable all Core SEO rules

```toml squirrel.toml
[rules]
disable = ["core/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["core/canonical"]
disable = ["*"]
```
