## What the robots meta tag does

`<meta name="robots">` controls how a search engine treats one page. Absent, the default is `index, follow`: index the page and follow its links. `noindex` keeps the page out of the index. `nofollow` stops link signals passing to the pages it links to.

Both have legitimate uses. A thank-you page after a form submission should be `noindex`. A page of user-submitted links might be `nofollow`. What matters is whether the directive is on the pages you meant, which is the question a crawl answers and a single page view does not.

## What squirrel checks

The rule runs on every crawled page against the parsed robots meta value, lowercased. It emits one check named `robots-meta`:

- Passing with the message `No robots meta tag (defaults to index, follow)` and a null value when there is no tag.
- Warning with the message `Page is set to noindex and nofollow` when both appear.
- Warning with the message `Page is set to noindex` when only that appears.
- At info status with the message `Page is set to nofollow (links won't pass equity)` when only that appears.
- Passing with the message `Robots meta tag allows indexing` when the tag is present and carries neither.

The value is always reported alongside the message, so the full directive list is visible in the report.

The match is a substring test on the lowercased value, so `nofollow` is also found inside `nofollow-something` and, more importantly, `noindex` is found inside any token containing it. This rule reads the meta element only; an `X-Robots-Tag` header saying the same thing is checked by [crawl/indexability](/rules/crawl/indexability).

## How to fix it

Remove the directive from pages that should be indexed:

```html
<meta name="robots" content="index, follow" />
```

Omitting the tag entirely does the same thing and is one less place for a template to go wrong. Where the page really should stay out of the index, leaving it is correct, and the finding is a report rather than a defect.

The common false positive is a staging environment audited by mistake, where a site-wide `noindex` is exactly what should be there.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["core/robots-meta"]
```

### Disable all Core SEO rules

```toml squirrel.toml
[rules]
disable = ["core/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["core/robots-meta"]
disable = ["*"]
```
