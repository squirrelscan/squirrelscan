## What descriptive link text is

Screen readers can list every link on a page and read them one after another, stripped of the sentence around them. A list of twelve links that all say "read more" is unusable. WCAG success criterion 2.4.4 Link Purpose (In Context), Level A, asks that the purpose be clear from the link text, or from the sentence or list item it sits in.

An icon-only link has the same problem in a harder form: there is no text at all. It needs an `aria-label`, an `<svg><title>`, or an image with `alt`.

## What squirrel checks

Two checks, at rule severity warning. Both walk every `a[href]`, skipping fragment-only links whose `href` starts with `#` and links using an unsafe scheme such as `javascript:`.

- `link-text-empty` fails when a link has neither an accessible name from `aria-labelledby`, `aria-label` or `title`, nor accessible content: text, an `<img>` with non-empty `alt`, an `<svg>` carrying a `<title>`, `aria-label` or `aria-labelledby`, or a `[role="img"]` with an `aria-label`. Report message: `N link(s) with no accessible text`. Each item is the first 50 characters of the `href`, labelled with the reason: `empty`, `svg-no-name`, `icon-font` or `role-img-no-name`.
- `link-text-generic` warns when the link's accessible name, or its text, lowercased and stripped of punctuation, exactly matches one of 48 generic phrases, unless it is a conventional label (below). The list includes `click here`, `here`, `read more`, `learn more`, `more`, `link`, `download`, `view`, `subscribe`, `join`, `submit`, `next`, `view details`, `website` and `discover`. Report message: `N link(s) with generic text`, listing each distinct phrase once.
- `link-text` passes with `All links have descriptive text` when neither problem appears on a page that has links.
- `link-text-unconfirmed` warns with `N link(s) with no accessible text may be hidden by a style (unconfirmed)` for an empty link a style may hide in a way squirrel cannot settle.

### Conventional labels

A link that reads "Sign in", "Log out" or "Privacy policy" names its destination, so it is never reported as generic, even though it sits in the template of every page. The exempt set is matched against the whole link text after Unicode normalisation (NFKC, so full-width and non-breaking-space variants match, plus case folding and leading and trailing punctuation removed), and is the union across English, Spanish, French, German, Portuguese, Italian, Dutch, Japanese, Chinese, Korean and Russian, so no page language detection is needed. It covers:

- account actions: sign in, sign up, log in, log out, sign out, register, my account, and their translations
- legal and utility labels: terms, terms of service, terms and conditions, privacy, privacy policy, legal, legal notice, imprint, DMCA, cookies, cookie policy, accessibility, sitemap, contact, about, help, FAQ, careers, and their translations

Only the whole text counts: "Sign in to read more" is not exempt. `click here`, `read more`, `learn more`, `here`, `more`, `link`, `this`, `go` and `continue` are still reported. `links/anchor-text` and `a11y/identical-links-same-purpose` do not list these labels as generic, so they needed no change.

### Generic phrases in other languages

English phrases are always checked. The page language, the primary subtag of `<html lang>` (so `fr-CA` is French), adds its own list of generic phrases: Spanish, French, German, Portuguese, Italian, Dutch, Japanese, Chinese, Korean and Russian. Examples: `cliquez ici` and `en savoir plus` (French), `mehr` and `weiterlesen` (German), `haga clic aquí` and `leer más` (Spanish), `詳しくはこちら` (Japanese), `点击这里` (Chinese), `자세히 보기` (Korean), `читать далее` and `подробнее` (Russian). A page with no `lang`, or one that is not in that list, is checked with the English list only. Only the primary `<html lang>` is read: a `lang` on a nested element, or text in another language on a page, is not detected, so French text on an English page is not reported as generic. Ambiguous words that are also a pager or wizard button (German `Weiter`, Dutch `verder`, Russian `Продолжить`) are left out. Matching is on the whole link text after Unicode normalisation (NFKC, case folding, edge punctuation removed, full-width punctuation included), and CJK text is never split into words, so `詳しくはこちらの料金表` is not reported. A conventional account or legal label ([Conventional labels](/rules/a11y/link-text#conventional-labels)) is never reported in any language.

### Hidden links

An empty link out of the accessibility tree has nothing to announce, so it is not reported: one with the `hidden` attribute (except `hidden="until-found"`), `aria-hidden="true"` on itself or an ancestor, `display: none` on itself or an ancestor (set inline or by a `<style>` rule squirrel can decide), or inside a closed `<dialog>` or an unopened `popover`. It still needs a name before it is shown. A hidden link with generic text is skipped too.

squirrel reads the markup, inline styles and the page's `<style>` blocks, the same way as `form-labels`; see [form-labels](/rules/a11y/form-labels) for what it can and cannot decide. External stylesheets are not read. An empty link that carries a `no-js` class, itself or on an ancestor other than `<html>`, is reported as unconfirmed on a page with an external stylesheet or an `@import`, because a theme usually hides that fallback with a rule such as `.js .no-js { display: none }` once JavaScript runs.

### Conventional labels are not flagged

A link that reads "Sign in", "Log out" or "Terms" does name its destination. These are the standard labels for an account action or a site-utility page, so they are never reported, even though a header link such as "Sign in" would otherwise repeat on every page.

- **Account actions:** sign in, sign up, log in, log out, sign out, register, my account, and the same forms without the space (`signin`, `signup`, `login`, `logout`).
- **Legal and utility pages:** terms, terms of service, terms and conditions, privacy, privacy policy, legal notice, imprint, DMCA, copyright, cookies, cookie policy, accessibility, sitemap, contact, about, help, FAQ and careers.
- **Languages:** English, Spanish, French, German, Portuguese, Italian, Dutch, Japanese, Chinese (simplified and traditional), Korean and Russian. Examples: `Iniciar sesión`, `Mentions légales`, `Impressum`, `Datenschutz`, `Termos de uso`, `Informativa sulla privacy`, `Privacybeleid`, `ログイン`, `利用規約`, `登录`, `联系我们`, `로그인`, `Войти`.

The whole link text has to be the label. "Sign in to continue" is judged like any other text, and so is a label that is part of a longer sentence. Case, surrounding punctuation, non-breaking spaces, full-width characters, hyphens, a trailing arrow such as `→` or `»`, and accents on Latin letters do not matter, so `SIGN IN`, `Sign-in.`, `Sign in →`, `Se connecter` and `Datenschutzerklaerung` all count. The labels of every language are checked together, so squirrel does not need to know the page's language. The same check applies to the accessible name from `aria-label`, `aria-labelledby` or `title`.

The check runs before the generic list and always wins. `subscribe` and `join` stay on the generic list, because on their own they say what to do and not where the link goes.

### Where the link sits

Each item records the parts of the page its links sit in, as `regions` (one page per section), taken from where the page's landmarks and the [page classifier](/configuration/classifier) placed that link: the header, the footer, the navigation, a sidebar or the page content. A link they could not place adds nothing, and so does a crawl stored before link sections were recorded. The report adds the pages up, so a generic phrase in the header of nearly every page reads once as `In the site header, on 49 of 53 pages` instead of listing every page, and its pages elsewhere are listed under that line. See [findings in a shared page region](/reports#findings-in-a-shared-page-region).

## How to fix it

```html
<a href="/pricing">View our pricing plans</a>

<a href="/search" aria-label="Search">
  <svg aria-hidden="true">...</svg>
</a>
```

Write the destination into the link text. Where the design demands a short label, keep the short text visible and put the full phrase in `aria-label`, making sure the visible words appear inside it.

Matching is exact, so a download button whose visible label is precisely `Download` is reported even when the heading above it names the file. Lengthening the text to "Download the Q3 report" clears it.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["a11y/link-text"]
```

### Disable all Accessibility rules

```toml squirrel.toml
[rules]
disable = ["a11y/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["a11y/link-text"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.

## Related rules

- [a11y/aria-labels](/rules/a11y/aria-labels): accessible names for buttons and clickable `<svg>` elements. It does not look at links.
- [a11y/identical-links-same-purpose](/rules/a11y/identical-links-same-purpose): identical link text pointing at different pages.
- [a11y/label-content-name-mismatch](/rules/a11y/label-content-name-mismatch): an `aria-label` that does not contain the visible words.
- [links/anchor-text](/rules/links/anchor-text): the same text read as a ranking signal rather than a name.
