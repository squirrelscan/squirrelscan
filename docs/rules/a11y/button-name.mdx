## What an accessible name is

The accessible name is the string a screen reader announces for a control. Browsers compute it from a fixed order of sources: `aria-labelledby` first, then `aria-label`, then the element's own text content, then `title`. An `<input type="button">` uses its `value` attribute.

A button with visible text already has a name. The problem case is a button whose whole content is a picture: an icon `<svg>`, a background image, or a font glyph in a pseudo-element. The user hears "button" and nothing else.

## What squirrel checks

Two checks, at rule severity error. They cover every `<button>`, every element with `role="button"`, and every `<input>` of type `button`, `submit` or `reset`. A button has a name when it has any of the following: a non-empty `aria-label`; an `aria-labelledby` pointing at an element that has text; a non-empty `title`; text content; a `value`; a nested `<img>` with non-empty `alt`; a nested `<svg><title>` with text; or a nested element carrying `aria-label`.

- `button-name` fails with `Buttons without accessible names` for unnamed buttons that are in the accessibility tree. Up to ten offenders are listed as `button#id`, `button.class`, `input[name="..."]` or `input[type="..."]`, with a count of any remainder.
- `button-name-unconfirmed` warns with `N button(s) without accessible names may be hidden by a style (unconfirmed)` for unnamed buttons a style may hide in a way squirrel cannot settle (see [What squirrel can see](#what-squirrel-can-see)).
- `button-name` passes with `All buttons have accessible names`, or with `All buttons in the accessibility tree have accessible names` when some unnamed buttons were skipped as hidden. The pass carries `buttonsChecked`, and `hiddenWithoutName` when buttons were skipped.
- Info with `No buttons found` when the page has none.

### Hidden buttons

A button that is not in the accessibility tree has nothing to announce, so the rule does not apply to it and it is not reported. That is a button with the `hidden` attribute (except `hidden="until-found"`), `aria-hidden="true"`, `display: none` on itself or an ancestor, `visibility: hidden` on itself or inherited from an ancestor (set inline or by a `<style>` rule squirrel can decide), or a button inside a closed `<dialog>` or an unopened `popover`. On a page that loads an external stylesheet, hiding from a `<style>` rule and inherited visibility are reported as unconfirmed, because an external rule can make the button visible again. A button in a closed overlay still needs a name: give it one before the overlay can open.

A `disabled` button is still in the accessibility tree, and so is one that is moved off-screen, clipped, or made transparent. Those are checked like any other button.

### What squirrel can see

squirrel reads the markup, each element's own inline `style` attribute and the page's `<style>` blocks. A declaration counts only when it plainly sets `display: none` or `visibility: hidden` (upper case and a trailing `!important` are fine).

From `<style>` blocks, squirrel applies only the rules it can decide exactly: a rule outside any `@media`, `@supports`, `@layer` or other at-rule, whose every selector is a single compound of a tag, `.class`, `#id`, `[attr]` or `[attr=value]`, such as `.modal { display: none }`. It orders them the way a browser does: an `!important` declaration first, then the inline style, then the more specific selector, then the later rule. A rule it cannot decide, such as one with a combinator (`.nav .menu`), a pseudo-class (`:hover`, `:not()`), an at-rule around it, a selector a browser rejects (`.123`), or a value it cannot read, does not hide anything: it makes the elements it could reach unconfirmed. A `<style>` block whose `type` is anything but `text/css` is ignored, as a browser ignores it, and so is one with `media="print"`. Every rule is undecided in a block that applies only sometimes or not as written: one with another `media`, one with a `title` (an alternate stylesheet can be switched off), one inside `<svg>`, or one with an `@namespace`. When an `@keyframes` on the page sets `visibility`, an element a rule or its inline style animates is unconfirmed too, because a running animation outranks every declaration but an `!important` one. A block inside `<template>` or `<noscript>`, nested CSS, an escaped at-rule name and a non-ASCII space in the CSS are not read, and count as a stylesheet squirrel did not read.

External stylesheets are not read. On a page that loads one (`<link rel="stylesheet">`, a `<link>` preloaded `as="style"`, or an `@import`), hiding from a `<style>` rule and visibility inherited from an ancestor are reported as unconfirmed, because an external rule could show the element again. An inline `display: none` still counts. A button hidden only by the site's external CSS, such as a closed modal whose `.modal` rule lives in a stylesheet, is still reported. Check those findings in a browser.

A `<style>` rule that shows an element again is read: a `display` rule on an element the browser hides by default (one with the `hidden` attribute, a closed `<dialog>` or a `popover`), or an `!important` rule over an inline `display: none`. The same rule in an external stylesheet is missed, and that element is treated as hidden.

squirrel's parser can also build a different tree from a browser's around some elements: a `<p>`, list items, headings, buttons, forms, links and other inline formatting elements, table parts, `<select>`, `<svg>`, and tags a browser ignores or treats as empty where they appear. When a hidden element is one of those, or sits inside one, what is inside it is reported as unconfirmed rather than skipped.

A declaration (inline or in a `<style>` rule) that mentions `display` or `visibility` in any other form is reported by `button-name-unconfirmed` rather than as a failure, because squirrel will not guess at it. That covers comments, escapes, CSS variables, other functions, non-ASCII characters, the `all` shorthand, `revert`, a `!` anywhere but a trailing `!important`, and an unlisted keyword.

## How to fix it

```html
<button aria-label="Close settings">
  <svg aria-hidden="true">...</svg>
</button>
```

Put the label on the button, not on the icon inside it, and hide the icon from assistive technology with `aria-hidden="true"` so it is not announced twice.

A button whose only content is an icon-font glyph in a `::before` pseudo-element is the common false positive. squirrel sees an empty button because the glyph is not in the markup. Adding `aria-label` is the correct fix in that case anyway.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["a11y/button-name"]
```

### Disable all Accessibility rules

```toml squirrel.toml
[rules]
disable = ["a11y/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["a11y/button-name"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.
