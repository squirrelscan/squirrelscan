squirrelscan runs its accessibility rules against every page it crawls. They cover accessible names for buttons, links and form controls, ARIA roles and attributes, heading and landmark structure, tables, language declarations and viewport settings. Each page below quotes the exact report message a rule emits, and most findings identify the offending element by selector, id or quoted text, so a coding agent can go straight to the markup that needs changing.

<Note>These are hand-written checks that read each page's markup, not an axe-core run, and they cover part of WCAG. A page with no findings has not been shown to conform to WCAG: criteria that need a person to judge, such as whether alt text describes the image or captions match the audio, are beyond what they can check.</Note>

## Run only these rules

```bash
squirrel audit https://example.com --rule-include a11y
```

## Where to start

These carry the highest severity and weight in the category.

- [aria-hidden on body or html: what it breaks](/rules/a11y/aria-hidden-body): aria-hidden=true on the body or html element asks assistive technology to ignore the entire page. squirrel checks both, at the highest weight.
- [Accessible names for buttons: what counts and how to check](/rules/a11y/button-name): A button with only an icon has no name for a screen reader. squirrel lists every button on every page that has nothing to announce.
- [ARIA references pointing at duplicate or missing ids](/rules/a11y/duplicate-id-aria): aria-labelledby resolving to two elements, or to none, names the wrong thing silently. squirrel checks all eight ARIA id references.
- [Dropdowns with no accessible name: naming a select](/rules/a11y/select-name): A select announced only as 'combo box' gives no clue what it changes. squirrel checks every select element on the page.
- [input type=image without alt: an unnamed submit button](/rules/a11y/input-image-alt): An image input is a submit button drawn as a picture, and with no alt it announces nothing. squirrel checks every one on the page.

## Key terms

- [Accessible name](/glossary/accessible-name): The name assistive technology announces for an element, computed from its content, label, aria-label or aria-labelledby.
- [Alt text](/glossary#alt-text): The alt attribute that gives an image a text alternative for screen readers, failed loads and search engines.
- [Anchor text](/glossary#anchor-text): The visible, clickable text of a link, which tells readers and search engines what the target is about.
- [ARIA](/glossary/aria): Accessible Rich Internet Applications: roles, states and properties that describe custom widgets to assistive technology.
- [Captions](/glossary#captions): Synchronised text of a video's dialogue and sounds, supplied as a `<track kind="captions">` file.
- [Client-side redirect](/glossary#client-side-redirect): A redirect done in the page (meta refresh or JavaScript) rather than with an HTTP 3xx response.
- [Color contrast ratio](/glossary/color-contrast): The luminance ratio between text and its background; WCAG AA asks for 4.5:1 for body text and 3:1 for large text.
- [Form labels](/glossary#form-labels): The `<label>` or accessible name tied to each form control, plus autocomplete tokens, so people know what to enter.
- [Heading hierarchy](/glossary/heading-hierarchy): The nesting of h1 to h6 headings that gives a page its outline for readers, screen readers and parsers.
- [Keyboard accessibility](/glossary#keyboard-accessibility): Whether every control can be reached and used with a keyboard alone, with a visible focus indicator and sensible tab order.
- [Landmark regions](/glossary#landmark): The page regions (main, nav, header, footer) that screen reader users jump between, plus the skip link to main content.
- [lang attribute](/glossary#lang-attribute): The lang attribute on `<html>` (and on passages) that declares the language, so screen readers pick the right voice.
- [Touch target size](/glossary#touch-targets): The tappable area of a control; WCAG 2.2 sets 24 by 24 CSS pixels as the AA minimum.
- [Viewport meta tag](/glossary/viewport-meta-tag): `<meta name="viewport">` that sets the layout width to the device width; disabling zoom in it fails accessibility.
- [WCAG](/glossary/wcag): The W3C's Web Content Accessibility Guidelines, organised as testable success criteria at levels A, AA and AAA; 2.2 is current.
