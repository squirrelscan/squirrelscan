## What color contrast is

Contrast ratio compares the relative luminance of text and its background on a scale from 1:1 to 21:1. WCAG success criterion 1.4.3 Contrast (Minimum), Level AA, requires 4.5:1 for normal text and 3:1 for large text, where large means 18 point, or 14 point bold, and up.

The ratio is a property of the rendered pixels, so it depends on the stylesheet, the theme and any image behind the text. Static markup can only ever show part of the picture.

## What squirrel checks

One check, `color-contrast`, at severity warning. It reports an element only when it has measured the element's contrast ratio and the ratio is under 4.5:1. The 3:1 large-text allowance is not applied, so a large heading at 3.5:1 is still reported.

A pair is measured when the element's own `style` attribute settles on both a `color` and an opaque background color, and the element has text. Within the attribute the last declaration of a property wins, and an `!important` one beats later ones without it. The background color comes from `background-color`, or from a `background` shorthand whose whole value is one color; any other shorthand, and a `background-image` other than `none`, leaves the background unresolved. A color counts when its whole value is a hex value (`#rgb`, `#rrggbb`, or a 4- or 8-digit hex whose alpha is fully opaque), an `rgb()`/`rgba()` value with three comma-separated channels of 0 to 255 and, if present, an alpha of 1 or 100%, or one of 31 named colors. squirrel computes the WCAG ratio and reports anything under 4.5:1 as `span: #999 on #fff (2.85:1)`.

Everything else is left unresolved, and an unresolved pair is not a finding. axe-core treats it the same way, as "incomplete" rather than a violation. That covers:

- colors set in a stylesheet, whether external or in a `<style>` block, or inherited from an ancestor;
- class names, including Tailwind's `text-gray-300` and Bootstrap's `text-muted`. A class says nothing about the surface the text lands on;
- `transparent`, any alpha below 1, `inherit`, `currentcolor`, `var()` and other syntax, because the color behind the text or of the text is not in the value. This holds when such a value is the winning declaration, even if an earlier one in the same attribute could be measured;
- a background that may layer an image or a gradient, because there is no single color behind the text.

Findings are deduplicated, and the check reports `N color contrast issue(s) below 4.5:1` with up to ten items and the count of measured pairs. With nothing under the threshold it passes as `No obvious contrast issues detected` whenever the page has any element with a `style` or `class` attribute, and on a page with neither it returns info with `Limited contrast analysis available`.

## How to fix it

```css
.muted {
  color: #595959; /* 7:1 on white */
}
```

Darken the foreground or lighten the background until the pair clears 4.5:1, and check the pair, not the color alone.

A pass covers only the pairs squirrel could measure. Most text takes its colors from stylesheets, so check the rendered page with browser DevTools or a contrast checker as well.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["a11y/color-contrast"]
```

### Disable all Accessibility rules

```toml squirrel.toml
[rules]
disable = ["a11y/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["a11y/color-contrast"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.
