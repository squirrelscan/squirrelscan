## What color contrast is

Contrast ratio compares the relative luminance of text and its background on a scale from 1:1 to 21:1. WCAG success criterion 1.4.3 Contrast (Minimum), Level AA, requires 4.5:1 for normal text and 3:1 for large text, where large means 18 point, or 14 point bold, and up.

The ratio is a property of the rendered pixels, so it depends on the stylesheet, the theme and any image behind the text. Static markup can only ever show part of the picture.

## What squirrel checks

Two checks. `color-contrast` is at severity warning: it reports an element only when it has measured the element's contrast ratio and the ratio is under 4.5:1. The 3:1 large-text allowance is not applied, so a large heading at 3.5:1 is still reported. `color-contrast-unresolved` is an info check that counts the text squirrel could not measure.

An element is a candidate when its own `style` attribute settles on an opaque `color` and the element has text. Within the attribute the last declaration of a property wins, and an `!important` one beats later ones without it. A color counts when its whole value is a hex value (`#rgb`, `#rrggbb`, or a 4- or 8-digit hex whose alpha is fully opaque), an `rgb()`/`rgba()` value with three comma-separated channels of 0 to 255 and, if present, an alpha of 1 or 100%, or one of 31 named colors.

The background behind the text is resolved in this order:

1. The nearest inline background on the element or an ancestor. It comes from `background-color`, or from a `background` shorthand whose whole value is one color. If that element has a `background-image` other than `none`, a gradient, a shorthand that is not one color, a color that is not opaque, or a legacy `bgcolor` attribute, the pair is unresolved and the walk stops there.
2. A plain `html`, `body` or `:root` rule in a `<style>` block with a one-color background. `body` wins over `html`. Rules inside `@media` and other at-rules are not read, and a value that is not one opaque color leaves the pair unresolved. It is used only when no other rule in a `<style>` block (or at-rule) sets a background, since that could override it, and every stylesheet the page links was read (step 3).
3. A same-site linked stylesheet. The asset phase fetches up to 20 same-site stylesheets (the most widely linked first, up to 1 MB each, through the same egress rules and fetch budget as scripts) and keeps only the `html`, `body` and `:root` background color; the stylesheet text is not passed to the rule. A background set on any other selector is not read, so a container that paints over the body is not seen. The pair is resolved from it when every stylesheet the page links was read and the sources agree: a stylesheet that failed to load (a 4xx, a 5xx, a timeout, a refused or skipped request, a page that answers with HTML, or one over the size limit), one on another site, a background image or gradient on `html` or `body`, an `@import`, or an at-rule such as `@media (prefers-color-scheme: dark)` that sets the `html` or `body` background leaves the pair unresolved. Two sources naming different colors are unresolved too.
4. White, the browser's default canvas, when the page links no stylesheet (one inside `<noscript>` does not load) or every linked stylesheet was read and sets no page background, has no `@import`, and no `<style>` block mentions a background at all.

A linked stylesheet can also paint a container under the text: `.hero { background: #111 }` makes light inline text readable even when the page background is white. squirrel keeps the selectors, other than `html`, `body` and `:root`, that a linked stylesheet gives a background (up to 200 per stylesheet; past that every pair on the page is unresolved). Text that sits inside, or is, an element matching one of them is unresolved instead of measured against the page background, and so is text when a selector cannot be evaluated or the page needs more than 50,000 selector matches. At-rules nested more than 8 levels deep are not read: a background inside one leaves the pair unresolved. It is counted by `color-contrast-unresolved`; the color of that container is not read.

Otherwise a stylesheet squirrel could not read may set the background, so the pair is unresolved: it is never reported as a finding and never assumed to be white, and axe-core treats it the same way, as "incomplete". A dark theme set in a linked stylesheet therefore does not produce a warning for light inline text. squirrel computes the WCAG ratio for a measured pair and reports it as `span: #999 on #fff (2.85:1)`, or `p: #b9b9b9 on white (1.96:1)` when the background is the default white.

Unresolved text is counted by `color-contrast-unresolved`, which says `N inline-colored text element(s) could not be measured: <reason>`. The reasons are a background set by a stylesheet the audit does not read or could not load, a background image or gradient behind the text, and a color that is transparent, translucent or not a plain color value. Each item names the element, its color and the ratio against white, for orientation only: `p: #b9b9b9 (1.96:1 against white)`. The check carries the inconclusive marker, so it is a "could not judge", not a pass. Text that only inherits its color (`inherit`, `currentcolor`), and classes and `<style>` colors with no inline `color`, are not counted: nothing in the markup says what they are.

Findings are deduplicated, and `color-contrast` reports `N color contrast issue(s) below 4.5:1` with up to ten items and the count of measured pairs. With nothing under the threshold it passes as `No obvious contrast issues detected`, and the check's `note` says `No inline text colors to measure` when no pair was measured. That includes a page with no inline text color at all, which no longer returns info. A page rule cannot attach a note to the audited site as a whole, so each such page carries its own pass.

## How to fix it

```css
.muted {
  color: #595959; /* 7:1 on white */
}
```

Darken the foreground or lighten the background until the pair clears 4.5:1, and check the pair, not the color alone.

A pass covers only the pairs squirrel could measure. Most text takes its colors from stylesheets, so check the rendered page with browser DevTools or a contrast checker as well.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["a11y/color-contrast"]
```

### Disable all Accessibility rules

```toml squirrel.toml
[rules]
disable = ["a11y/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["a11y/color-contrast"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.

## Check names by outcome

Each check name this rule can emit, by what it means to a tool comparing two audits. A **problem** check is a finding. A **clean** check says the rule ran over what it covers and found nothing; it clears the problem checks listed beside it, so a finding is fixed when the rule ran over the same scope and a clean check took its place. A **not checked** check says the rule did not evaluate, and never clears a finding.
