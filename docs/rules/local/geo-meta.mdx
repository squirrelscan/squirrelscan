## What geo.placename is

`geo.placename` is a `<meta>` tag naming the city or locality a page is about. It travels with three others: `geo.region` holds an ISO 3166-2 country and subdivision code, `geo.position` holds `latitude;longitude`, and `ICBM` holds the same coordinates comma separated. None of the four is a web standard. They were proposed in an IETF Internet-Draft that expired in 2008 and never became an RFC.

Google says it "ignores locational `meta` tags (like `geo.position` or `distribution`) or geotargeting HTML attributes", so adding them will not move a page in local search. They still cost nothing to serve and stay readable by directory crawlers and in-house tools, and keeping them in step with [LocalBusiness structured data](/rules/schema/local-business) catches a stale city name. Treat them as a supplement to schema, never a replacement.

## What squirrel checks

The rule runs on every crawled page and emits one check:

- `geo-meta`: looks for `meta[name="geo.region"]`, `meta[name="geo.placename"]`, `meta[name="geo.position"]` and `meta[name="ICBM"]`. One or more present passes, with the message `N geo meta tag(s) found` and the names it found listed as items. None present reports at info status with the message `No geo meta tags found` and the value `Consider adding for local businesses`. Severity info.

The rule matches names, not values. A stale city name, an invalid ISO code and coordinates in the wrong hemisphere all pass. `ICBM` is matched with that exact uppercase spelling, so a lowercase `icbm` is not counted. The whole rule is skipped, with the reason shown in the report, when the site profile says the site is not a local business.

## How to fix it

```html
<meta name="geo.region" content="US-CA" />
<meta name="geo.placename" content="San Francisco" />
<meta name="geo.position" content="37.7749;-122.4194" />
<meta name="ICBM" content="37.7749, -122.4194" />
```

These go in `<head>` on location and service-area pages, not site-wide, and the values must match the address in your `LocalBusiness` JSON-LD.

The common false positive is a single-location business that carries the tags only on its contact page. The check is per page, so every other page reports `No geo meta tags found`. That result is info, not a failure, and it does not need fixing on pages that are not about a place.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["local/geo-meta"]
```

### Disable all Local SEO rules

```toml squirrel.toml
[rules]
disable = ["local/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["local/geo-meta"]
disable = ["*"]
```
