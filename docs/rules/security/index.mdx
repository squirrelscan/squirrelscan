Security is one of the four score groups on every report. This page covers transport and header hardening: HTTPS, response headers, cookie flags, form submission and secrets that reached the browser. Signs of compromise, legal compliance signals and content blocked by privacy filters are scored in the same group but documented in the categories below.

## Run only these rules

```bash

```

`security` runs this category only. Add the other categories in the group with `--rule-include security,integrity,legal,blocking`.

## Where to start

These carry the highest severity and weight in the category.

- [Leaked API key in client-side code: how to find one](/rules/security/leaked-secrets): An API key shipped in HTML or a bundle can be read by anyone who views source. squirrel scans every page and script against more than 90 key patterns.
- [HTTPS: what it means when a page is not served over HTTPS](/rules/security/https): A page delivered over plain HTTP can be read and rewritten in transit. squirrel flags every crawled URL whose protocol is not https.
- [GraphQL mutations over GET: why they open the door to CSRF](/rules/security/graphql-get-mutations): A server that runs a mutation sent as a GET lets any site fire it with your visitors' cookies. squirrel sends a no-op mutation that cannot write and checks the answer.
- [Mixed content: HTTP resources on an HTTPS page](/rules/security/mixed-content): An HTTPS page that loads a script or stylesheet over HTTP is not secure and browsers block it. squirrel lists every HTTP resource per page.
- [Form action over HTTP: the insecure form submission warning](/rules/security/form-https): A form on an HTTPS page that posts to http:// sends the data in the clear and browsers interstitial it. squirrel checks action and formaction.

## Key terms

- [Content Security Policy (CSP)](/glossary/content-security-policy): A response header listing where a page may load scripts, styles, frames and other resources from, limiting what injected code can do.
- [Cookie attributes](/glossary/cookie-attributes): The Secure, HttpOnly and SameSite flags on Set-Cookie that limit where a cookie is sent and whether scripts can read it.
- [GraphQL introspection](/glossary#graphql-introspection): The GraphQL feature that returns the full schema on request; left on in production it maps the API for attackers.
- [HSTS](/glossary/hsts): The Strict-Transport-Security header that tells browsers to use only HTTPS for a host for a set time.
- [HTTPS](/glossary/https): HTTP over TLS, which encrypts traffic and proves the server's identity; every page and form should use it.
- [Leaked secrets](/glossary/leaked-secrets): Credentials or private keys shipped to the browser in HTML, scripts or source maps.
- [Mixed content](/glossary#mixed-content): An HTTPS page loading scripts, styles, images or media over plain HTTP.
- [rel=noopener](/glossary#noopener): A link attribute that stops a page opened with `target=_blank` from controlling the page that opened it (tabnabbing).
- [Security headers](/glossary/security-headers): HTTP response headers (CSP, HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy) that tell browsers to restrict risky behaviour.
- [security.txt](/glossary#security-txt): A file at /.well-known/security.txt (RFC 9116) that tells researchers how to report a vulnerability.
- [Subresource Integrity (SRI)](/glossary#subresource-integrity): An integrity attribute holding a hash of a third-party script or stylesheet, so the browser refuses a tampered file.
- [Token storage](/glossary#token-storage): Where a web app keeps session or auth tokens; tokens in localStorage are readable by any script on the page.
- [Well-known URIs](/glossary#well-known-uri): Fixed paths under /.well-known/ (RFC 8615) where sites publish machine-readable files: security.txt, api-catalog, OAuth metadata and agent manifests.
- [X-Content-Type-Options](/glossary#x-content-type-options): The nosniff header that stops browsers guessing a response's type instead of trusting Content-Type.
- [X-Frame-Options](/glossary#x-frame-options): A response header that controls whether other sites may embed the page in a frame; CSP frame-ancestors is its successor.
