## What information disclosure is

A page that crashes can print what the server knows: a stack trace with file names and line numbers, the absolute path of the web root, a framework debug page with environment details, or the text of a failed SQL query. None of that is for visitors. It tells an attacker which framework and database you run, where your files live and how your queries are built, and a debug page can show configuration and credentials as well.

Version numbers in response headers are a separate check: [security/version-disclosure](/rules/security/version-disclosure) reads `Server` and `X-Powered-By`. This rule does not read headers, so one disclosure is never reported twice.

## What squirrel checks

The rule runs on every crawled page that returned a 2xx status. The crawler does not store the body of a 4xx or 5xx response yet, so error pages are not read; reading them is tracked in [#2393](https://github.com/squirrelscan/squirrelscan/issues/2393). The rule reads the visible text of the document, skipping `<script>`, `<style>`, `<template>` and `<noscript>`, and looks at the first 200,000 characters for these signatures:

- Stack traces: Python tracebacks, Java and Kotlin frames and exceptions, Node.js frames with a file path and position, PHP traces and `... in <path>.php on line N` errors, .NET frames with a source path, and Ruby backtraces.
- Framework debug pages: Laravel (Whoops and `Illuminate\` classes), Symfony, Django (`DEBUG = True`), Rails (Action Controller exception pages and `ActiveRecord::` errors), ASP.NET (`Server Error in '...' Application`) and the Werkzeug debugger.
- Database errors: `SQLSTATE[...]`, Oracle `ORA-NNNNN` errors, `PG::` errors and common PostgreSQL messages, MySQL and mysqli messages, SQL Server messages and SQLite errors.

A framework or driver name on its own is not reported, because documentation names them in prose. `Illuminate\`, `Symfony\Component\`, `ActiveRecord::`, `ActionController::RoutingError`, `System.Web.` exceptions, `mysqli::`, `mysqli_...()`, `PG::` and `ORA-NNNNN:` count only when a trace or error shape follows within about 240 characters: a `file.php:N` or similar file and line, `:line N`, a `#0 ` frame, `Stack trace:`, an `at package.Class(` frame, `Rails.root:` or `Application Trace`. Some error shapes count on their own: `PG::<Name>: ERROR:`, `Warning: mysqli_<name>(): `, `Uncaught mysqli_sql_exception`, an exception or `Warning:` prefix before `ORA-NNNNN`, and an `ORA-06512: at` line after one.
- Absolute filesystem paths such as `/var/www/...`, `/home/<user>/public_html/...`, `/Users/...` and `C:\inetpub\...`. A bare path is only reported on an error response (status 400 or higher), because tutorials and documentation quote paths on healthy pages. Since error pages are not read yet, bare paths are not reported today.

The first match is reported as `info-disclosure`, a warning, with the kind, the matched signature and a snippet of at most 160 characters. The snippet is collapsed to one line.

- Pass with `No stack trace, filesystem path, debug page or database error in the page` when nothing matches. A styled 404 page with no internal details passes.

Text in separate block elements, such as table cells, paragraphs and list items, is read as separate lines, so a trace laid out one frame per cell is still found.

The rule reads what the page shows. A page that documents an error, such as a tutorial quoting a Python traceback, can match.

## How to fix it

Turn debug output off in production and serve a generic error page:

- Laravel: `APP_DEBUG=false`. Symfony: `APP_ENV=prod`. Django: `DEBUG = False`. Rails: `config.consider_all_requests_local = false`.
- ASP.NET: `<customErrors mode="RemoteOnly" />` or `On`.
- PHP: `display_errors = Off` and `log_errors = On`.

Log the details on the server instead. If the output showed a credential, rotate it.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["security/info-disclosure"]
```

### Disable all Security rules

```toml squirrel.toml
[rules]
disable = ["security/*"]
```

## Check names by outcome

Each check name this rule can emit, by what it means to a tool comparing two audits. A **problem** check is a finding. A **clean** check says the rule ran over what it covers and found nothing; it clears the problem checks listed beside it, so a finding is fixed when the rule ran over the same scope and a clean check took its place. A **not checked** check says the rule did not evaluate, and never clears a finding.
