## What hreflang is

`<link rel="alternate" hreflang="…">` tells a search engine that a page has versions for other languages or regions, and where they are. Without it, the versions compete as near-duplicates and the wrong one is shown.

Two rules make a set work. Every page in the set lists every version including itself, so the set is confirmed from every direction. And `x-default` names the version to show a visitor whose language matches none of the others, usually a language selector or the primary version.

## What squirrel checks

The rule runs on every crawled page over every `link[rel="alternate"][hreflang]`. It emits up to four checks:

- Info when the page has no hreflang tags. Message: `No hreflang tags found (not required for single-language sites)`. No further checks run.
- `hreflang-xdefault` warns when no tag has `hreflang="x-default"`. Message: `No x-default hreflang found`.
- `hreflang-self` warns when no tag's resolved href equals the page URL exactly. Message: `No self-referencing hreflang found`. For a URL that answers with an HTTP redirect, the page URL is the one the redirect ended on, since that is the page whose tags are read: `/en/old-slug` redirecting to `/en/new-slug` passes when `/en/new-slug` references itself.
- `hreflang-codes` warns when a tag's value is not `x-default` or a valid code. Message: `1 invalid hreflang code(s): en-uk`. Each invalid value is listed with the reason and, where one exists, the fix. What counts as valid is below.
- `hreflang` passes, listing the language codes found. Message: `4 hreflang tag(s) found`.

The final pass check is always emitted alongside any warnings, so a page can report both a missing `x-default` and a count of its tags. The self-reference comparison is on the fully resolved URL, so a self-tag that differs by a trailing slash or a query string does not count. The code check validates format only. It does not check return links: whether the other versions link back to this page is not checked. Severity info, weight 3.

## What counts as a valid code

A value is valid when it is `x-default` or `language`, optionally followed by `script`, then `region`. Matching is case-insensitive, so `en-GB`, `en-gb` and `EN-gb` are all fine.

- **Language**: a two-letter ISO 639-1 code from the standard list, or any three letters (ISO 639-2/3, checked by shape only). The legacy `iw`, `in` and `ji` are accepted because Google accepts them.
- **Script**: four letters, such as `Hant` or `Latn`.
- **Region**: a two-letter ISO 3166-1 alpha-2 country code from the standard list, or a three-digit UN M.49 code such as `419`.

These are flagged: an underscore instead of a hyphen (`en_US`, use `en-US`), a language that is not a real code (`xx`, `english`), a region that is not a real code (`en-uk`, use `en-GB`), and extra subtags after the region. `uk` is only wrong as a region: as a language it is Ukrainian, so `uk` and `uk-UA` pass.

The check looks at the shape and the code lists. It does not confirm that a three-letter language exists, or that a language is used in a region.

## How to fix it

```html
<link rel="alternate" hreflang="en-au" href="https://example.com/au/pricing" />
<link rel="alternate" hreflang="en-gb" href="https://example.com/uk/pricing" />
<link rel="alternate" hreflang="x-default" href="https://example.com/pricing" />
```

Generate the full set from one source of truth so every version lists every other, including itself, with URLs matching the canonical form exactly.

Keep `hreflang` and the canonical tag consistent: each version should be canonical to itself, not to the primary language.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["i18n/hreflang"]
```

### Disable all Internationalization rules

```toml squirrel.toml
[rules]
disable = ["i18n/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["i18n/hreflang"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.
