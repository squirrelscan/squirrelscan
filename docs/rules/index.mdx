squirrelscan includes **295 rules** across **21 categories**, plus opt-in cloud gap analysis. Every category rolls up into one of four score groups: **SEO**, **Performance**, **Security**, and **Agents**. These are the four scores you see on reports and in the dashboard, alongside the overall health score.

Most rules run locally for free. A handful of [cloud rules](/cloud/rules) use AI analysis, full filter lists, or live search data - they require login and are skipped when you're not logged in. Cloud rules carry a notice banner on their doc pages.

## Content inside noscript

A browser with scripting enabled reads `<noscript>` content as plain text, so nothing in it loads, renders or reaches the accessibility tree. Sites put tracking pixels, Google Tag Manager iframes, lazy-load fallback images and fallback stylesheets there for visitors without JavaScript, so reporting them flags markup that never runs.

The rules that describe what a browser loads or renders skip elements inside `<noscript>`, so a page with a `<noscript>` fallback gets the same result as the same page without it:

- Accessibility: [aria-required-children](/rules/a11y/aria-required-children), [frame-title](/rules/a11y/frame-title), [image-redundant-alt](/rules/a11y/image-redundant-alt), [meta-refresh](/rules/a11y/meta-refresh)
- Images: [alt-text](/rules/images/alt-text), [aspect-mismatch](/rules/images/aspect-mismatch), [broken-images](/rules/images/broken-images), [dimensions](/rules/images/dimensions), [filename-quality](/rules/images/filename-quality), [lazy-loading](/rules/images/lazy-loading), [modern-format](/rules/images/modern-format), [offscreen-lazy](/rules/images/offscreen-lazy), [optimized](/rules/images/optimized), [picture-element](/rules/images/picture-element), [responsive-size](/rules/images/responsive-size), [srcset](/rules/images/srcset)
- Performance: [animated-content](/rules/perf/animated-content), [carousel-hidden-eager](/rules/perf/carousel-hidden-eager), [cls-hints](/rules/perf/cls-hints), [critical-request-chains](/rules/perf/critical-request-chains), [duplicate-js](/rules/perf/duplicate-js), [font-delivery](/rules/perf/font-delivery), [font-loading](/rules/perf/font-loading), [inp-hints](/rules/perf/inp-hints), [js-libraries](/rules/perf/js-libraries), [lazy-above-fold](/rules/perf/lazy-above-fold), [lcp-fetchpriority](/rules/perf/lcp-fetchpriority), [lcp-hints](/rules/perf/lcp-hints), [legacy-js](/rules/perf/legacy-js), [preconnect](/rules/perf/preconnect), [render-blocking](/rules/perf/render-blocking), [total-byte-weight](/rules/perf/total-byte-weight), [unminified-css](/rules/perf/unminified-css), [unminified-js](/rules/perf/unminified-js)
- Security: [mixed-content](/rules/security/mixed-content), [sri](/rules/security/sri), [third-party-cookies](/rules/security/third-party-cookies)
- Blocking and integrity: [blocked-links](/rules/adblock/blocked-links), [template-discontinuity](/rules/integrity/template-discontinuity)

Same-domain scripts, stylesheets and images that appear only inside `<noscript>` are not fetched for the file-size and compression rules either. Links inside `<noscript>` are still collected for crawling, and the remaining rules read the page as before.

## Pages kept out of search

A page marked `noindex` will not show up in search results, so findings about how it would look there are noise. Seven rules leave these pages alone:

- [core/meta-title](/rules/core/meta-title), [core/meta-description](/rules/core/meta-description) and [core/h1](/rules/core/h1) skip the page. Each records one skipped check, such as `Skipped: page is set to noindex via robots meta tag` (or `via X-Robots-Tag header`), in place of its usual result.
- [core/title-unique](/rules/core/title-unique), [content/duplicate-title](/rules/content/duplicate-title) and [content/duplicate-description](/rules/content/duplicate-description) leave the page out when they group pages by title or description.
- [links/orphan-pages](/rules/links/orphan-pages) never reports the page as an orphan. Its own links still count toward the pages they point to.

**What counts as noindex.** The page's `<meta name="robots">` content or its `X-Robots-Tag` response header contains `noindex`. This is the same test [crawl/indexability](/rules/crawl/indexability) uses, so a header scoped to one crawler, such as `X-Robots-Tag: googlebot: noindex`, counts too. A URL blocked by robots.txt is not a noindex, and crawler-specific meta tags such as `<meta name="googlebot">` are not read.

**Staging sites and preview deployments.** Pages are skipped only when the site itself is being indexed. squirrelscan decides that from the homepage, which is the page at `/` on the audited host (with or without `www.`, over http or https, with no query string), or, when the homepage was not fetched or answered with an error, from the page the audit started from. If the crawl holds more than one copy of that page, such as both the http and https homepage, any copy marked noindex counts.

| That page is | Result |
|---|---|
| indexable | noindex pages are skipped |
| noindex | nothing is skipped |
| not fetched (neither the homepage nor the start page) | nothing is skipped |

A site-wide `noindex` usually means the audit is checking a site before launch, which is when title, description and H1 findings matter most. Vercel, Netlify and Cloudflare Pages preview deployments send `X-Robots-Tag: noindex` on every page by default, so an audit of a preview URL runs every rule.

**In reports and scores.** A skipped check is not an issue. It does not appear in the issue list in any report format, it is not counted as passed, warning or failed, and the [health score](/reports#health-score) leaves it out. A page left out of a site rule's grouping simply is not in it.

**Everything else still runs.** Accessibility, security and performance rules, and every link rule other than orphan pages, check noindex pages as usual, and so do [core/robots-meta](/rules/core/robots-meta), [crawl/indexability](/rules/crawl/indexability) and [crawl/all-noindex-pages](/rules/crawl/all-noindex-pages), which report the noindex pages themselves.

## Rule time budget

Rules read content the audited site controls, so a page can be built to make a pattern match very slowly. Every rule runs under a time budget: one second per page for a page rule, and one second per page of the site for a site rule. A rule that runs past it is stopped for that page, and the audit carries on with the next rule.

The report records it as a failed check named after the rule with `-error` on the end, such as `content/hidden-text-error`, against the page where it happened (or the whole site, for a site rule), with the message `Rule error: exceeded its 1000 ms time budget and was abandoned`. Its details carry `timedOut: true`. That rule's own result for that page is not in the report.

Ordinary pages never come close: the slowest rule takes a few milliseconds per page. If you see this on a page that looks normal, [open an issue](https://github.com/squirrelscan/squirrelscan/issues) with the page URL.

## Configuration

### Enable/Disable rules

Use glob patterns in `squirrel.toml`:

```toml squirrel.toml
[rules]
# Enable specific rules or categories
enable = ["*"]  # all rules (default)

# Disable specific rules
disable = [
  "ax/*", "ai/*",   # disable all Agent Experience rules
  "content/word-count",  # disable specific rule
]
```

### Rule options

Some rules have configurable options:

```toml squirrel.toml
[rules."core/meta-title"]
min_length = 30
max_length = 75

[rules."content/word-count"]
min_words = 300
```

See individual rule pages for available options.
