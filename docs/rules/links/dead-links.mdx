## What the cloud dead-links service is

Verifying external links means at least one HTTP request per link, and often more: the checker tries `HEAD`, falls back to `GET`, and follows redirects. On a site with a few thousand outbound links, that is a slow phase for you and a burst of automated traffic for everyone you link to.

The cloud service moves that work behind a cache shared across every audit. A link any recent audit checked comes back immediately: a working link stays cached for three to thirty days, following the caching headers its server sends, and a dead one for one hour to three days. A link the service has not seen yet is queued, paced per site, and retried with a browser-like client when a plain request is refused. This rule is the gate that turns it on: enabling it routes the audit's external-link phase through the service instead of fetching each link locally.

For an audit you run with the CLI, the service replies within about a minute, sooner if 20 seconds pass without a new answer. A link it has not answered by then is left out of its reply, and squirrel checks that link locally, from your machine, as it would if you were logged out. squirrel asks about up to 200 links at a time: if a reply answers none of them, it stops asking and checks the rest of the audit's external links locally straight away, so a busy service costs one wait rather than one per batch. A link the service could not verify comes back without a dead verdict and is not counted as dead: one behind a bot wall or a challenge page, one that timed out or failed to connect from the service's network, or a 404 seen once and waiting for a second check. A rate-limited link is listed under `rate-limited-external-links`, and the others under `waf-blocked-external-links` in [links/broken-external-links](/rules/links/broken-external-links), each as status unverifiable.

## What squirrel checks

The rule is a summary. The per-link findings belong to `links/broken-external-links`, and this check never re-scores them, which is why its status is always informational. It emits a single check named `dead-links`:

- Skipped when external link checking did not run for the audit (`--offline`, `--no-external-links`, or external link checks off), with skip reason `external-links-not-checked`. Message: `External link checking was off for this audit, so external links were not verified`. It is not listed among the cloud checks a cloud audit would unlock, because turning external link checks on is what runs it.
- Info when the site has no external links. Message: `No external links found to verify`, with a value of 0.
- Info when every external link was one squirrel never requests because it looks like an action or carries a token. Message: `No external links were verified: all N look like actions or carry a token, so they were not requested`, with a value of 0. See [What the external link check never requests](/configuration/external-links#what-the-external-link-check-never-requests).
- Info otherwise, with one of two wordings: `Checked 128 external link(s); none are dead` or `Checked 128 external link(s); 4 dead`. When some targets were throttled, `; 2 rate-limited (status unverifiable)` is appended.

A link counts as dead on the same basis as `links/broken-external-links`: a fetch error, or a status of 400 or above that is neither unverifiable (a wall or a timeout) nor a rate-limit response. Severity info, weight 1, the lowest of any rule in the Links category.

## How to fix it

Log in with `squirrel auth login` to use the service. A signed-in CLI audit pays 1 credit per distinct external link the service answers, at most one per page of the audit's page limit, the same as a cloud audit. Its estimate before the audit includes them. An audit that has the cloud's spend disclosure accepted under `[cloud] max_credits_per_audit` (the default for a signed-in audit) asks nothing more; one without a per-audit cap, one that declined the cloud rendering prompt before, or one that chose its rendering with `--http`, `--render`, `--render-mode`, `[cloud] render` or `[cloud] rendering`, still gets a spend prompt in a terminal when the links alone would pass `[cloud] confirm_threshold`. A link the service leaves unanswered is checked on your machine for free. Being logged out falls back to local per-link checking.

The findings themselves are on `links/broken-external-links`. Fix them there.

## Enable / disable

### Disable cloud link checking (keep local checking)

```toml squirrel.toml
[rules]
disable = ["links/dead-links"]
```

### Disable external link checking entirely

```toml squirrel.toml
[external_links]
enabled = false
```
