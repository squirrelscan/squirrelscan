---

## What BreadcrumbList schema is

`BreadcrumbList` is the schema.org type for the trail of pages that leads to the current one. It holds an `itemListElement` array of `ListItem` nodes, each with a `position` starting at 1, a `name`, and an `item` URL. The last entry is the current page and does not need an `item`.

It describes a path, not the navigation widget, so the markup should mirror the trail a reader would follow rather than the site's whole menu. A homepage has no trail, which is why this rule skips it.

## What squirrel checks

The rule reads every `script[type="application/ld+json"]` on the page and takes the first node whose `@type` is `BreadcrumbList`, or whose `@type` array contains it. It emits one or more checks:

- `breadcrumb-schema`: on the homepage, meaning a URL path of `/` or empty, it reports at info status with the message `Homepage - breadcrumbs not typically needed` and stops. On any other page with no `BreadcrumbList` node it reports at info status with the message `No BreadcrumbList schema found` and the value `Consider adding for non-homepage`.
- `breadcrumb-items`: warns with the message `BreadcrumbList has no items` when `itemListElement` is absent, is not an array, or is empty. It warns with the message `Some breadcrumb items missing position or name` when at least one entry lacks either property.
- `breadcrumb-order`: warns with the message `Breadcrumb positions not sequential` when a numeric `position` is not one more than the previous entry's. This check is pushed once per offending entry, so a badly numbered list emits it more than once.
- `breadcrumb-valid`: passes with the message `BreadcrumbList has N item(s)` when every entry has both a `position` and a `name`.

The sequence check only runs on positions that are JavaScript numbers. A `position` written as the string `"1"` is accepted as present by `breadcrumb-valid` but skipped by `breadcrumb-order`, so a string-numbered list never reports as out of order.

## How to fix it

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Guides", "item": "https://example.com/guides" },
    { "@type": "ListItem", "position": 2, "name": "Deployment" }
  ]
}
</script>
```

Put it in the `<head>` of the page it describes, number the positions from 1 with no gaps, and emit them as numbers rather than strings.

The common false positive is a site whose JSON-LD is wrapped in an `@graph` array, which is what Yoast and several other generators emit. This rule reads the top level of each script only and does not flatten `@graph`, so a `BreadcrumbList` nested inside one reports as `No BreadcrumbList schema found`.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["schema/breadcrumb"]
```

### Disable all Structured Data rules

```toml squirrel.toml
[rules]
disable = ["schema/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["schema/breadcrumb"]
disable = ["*"]
```
