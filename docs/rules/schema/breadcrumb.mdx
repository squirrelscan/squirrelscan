## What BreadcrumbList schema is

`BreadcrumbList` is the schema.org type for the trail of pages that leads to the current one. It holds an `itemListElement` array of `ListItem` nodes, each with a `position` starting at 1, a `name`, and an `item` URL. The last entry is the current page and does not need an `item`.

It describes a path, not the navigation widget, so the markup should mirror the trail a reader would follow rather than the site's whole menu. A homepage has no trail, which is why this rule skips it.

## What squirrel checks

The rule reads every `script[type="application/ld+json"]` on the page and keeps the first `BreadcrumbList` node from the last script that contains one, matching either a plain `@type` or an `@type` array, with or without a URL prefix such as `https://schema.org/`. It emits one or more checks:

- `breadcrumb-schema`: on the homepage, meaning a URL path of `/` or empty, it reports at info status with the message `Homepage - breadcrumbs not typically needed` and stops. On any other page with no `BreadcrumbList` node it reports at info status with the message `No BreadcrumbList schema found` and the value `Consider adding for non-homepage`, unless the page shows a breadcrumb trail. When at least one link on the page sits in the breadcrumbs section, it fails with the message `A breadcrumb trail on the page has no BreadcrumbList schema` and the value `Add BreadcrumbList JSON-LD that mirrors the trail`. The check carries the number of trail links in its `details`.
- `breadcrumb-items`: warns with the message `BreadcrumbList has no items` when `itemListElement` is absent, is not an array, or is empty. It warns with the message `Some breadcrumb items missing position or name` when at least one entry lacks either property.
- `breadcrumb-order`: warns with the message `Breadcrumb positions not sequential` when a numeric `position` is not one more than the previous entry's. The first entry is compared against 1, so a list starting at 0 or 2 is reported. This check is pushed once per offending entry, so a badly numbered list emits it more than once.
- `breadcrumb-valid`: passes with the message `BreadcrumbList has N item(s)` when every entry has both a `position` and a `name`.

The breadcrumbs section is the bundled [page classifier](/configuration/classifier)'s answer for where a link sits on the page. Page markup never names it, and the classifier answers only when it is confident, so it is a high-precision signal that the page shows a trail. One link is enough, because the current page is plain text in a trail and a short one such as `Docs / Security` holds a single link. A page whose trail is declared nested in another JSON-LD node (the `breadcrumb` of a `WebPage`), or marked up as microdata or RDFa (`itemtype="https://schema.org/BreadcrumbList"`), is described already, so it keeps the info check too. When the page's markup is too large to read in full, the check is info with the message `Page markup too large to judge structured data`, because a missing schema is not proven. A run with `--no-classifier` or `classifier.enabled = false` gives no link a section, so it also keeps the info check.

The sequence check only runs on positions that are JavaScript numbers. A `position` written as the string `"1"` is accepted as present by `breadcrumb-valid` but skipped by `breadcrumb-order`, so a string-numbered list never reports as out of order. Every property test is a truthiness test rather than a presence test, so a property present but empty, `0` or `false` counts as missing. A `position` of `0` and a `name` of `""` therefore both read as missing.

An `itemListElement` entry that is a node reference, `{"@id": "…#crumb-1"}`, is read from the `ListItem` node with that `@id` anywhere in the page's JSON-LD, in the same `@graph` or another script. A relative `@id` resolves against the page URL. A reference to a node the page does not have counts as an item missing its position and name.

Severity is warning. Before the trail check existed it was info, which kept every check here advisory: a `warn` from a severity-info rule is listed but left out of the warning totals. It now counts toward them, so a malformed `BreadcrumbList` lowers the score where it used to be a recommendation.

## How to fix it

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Guides", "item": "https://example.com/guides" },
    { "@type": "ListItem", "position": 2, "name": "Deployment" }
  ]
}
</script>
```

Put it in the `<head>` of the page it describes, number the positions from 1 with no gaps, and emit them as numbers rather than strings.

JSON-LD wrapped in an `@graph` array, which is what Yoast, Rank Math and several other generators emit, is read the same as a top-level node: the rule flattens each script before looking for `BreadcrumbList`.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["schema/breadcrumb"]
```

### Disable all Structured Data rules

```toml squirrel.toml
[rules]
disable = ["schema/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["schema/breadcrumb"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it. Only an `enabled` setting under a rule's own `[rule_options]` table overrides both lists.
