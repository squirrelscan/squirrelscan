## What AggregateRating is

`AggregateRating` is the schema.org type for a summary of many ratings of one thing: `ratingValue` holds the average, `ratingCount` or `reviewCount` holds how many it is drawn from, and `bestRating` holds the top of the scale, defaulting to 5. It attaches to the thing being rated, usually a `Product` or a `LocalBusiness`.

A single `Review` is the other half. It needs an `author`, a `reviewRating` and a `datePublished`, and it rates a specific item rather than the site as a whole. Google's structured data policies require the rating to be visible to readers on the same page.

## What squirrel checks

The rule reads every `script[type="application/ld+json"]` on the page. It collects an `aggregateRating` property from any node, a node whose `@type` is exactly `AggregateRating`, a `review` property from any node, and any node whose `@type` is exactly `Review`. It emits one to three checks:

- `review-schema`: reports at info status with the message `No Review or AggregateRating schema found` when neither is present. No further checks run.
- `aggregate-rating`: warns with the message `AggregateRating missing ratingValue` when the value is absent, warns with `AggregateRating missing ratingCount/reviewCount` when neither count is present, and otherwise passes with `AggregateRating: X/5 (N reviews)`.
- `individual-reviews`: warns with the message `N review(s) missing author or rating` for entries lacking `author` or `reviewRating`, and passes with `N valid review(s) found` for those that have both. Both can appear on the same page.

The pass message prints the scale as `/5` regardless of what `bestRating` says, so a rating on a 10-point scale is still rendered as out of 5. When several nodes carry an `aggregateRating`, the last one wins. An `AggregateRating` that a generator has wrapped in an array is unwrapped and the first object entry is used.

## How to fix it

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Ceramic pour-over dripper",
  "aggregateRating": {
    "@type": "AggregateRating",
    "ratingValue": "4.7",
    "ratingCount": "218",
    "bestRating": "5"
  }
}
</script>
```

Attach the rating to the thing it rates, not to the page or the site, and print the same numbers in the page content where a reader can see them.

The common false positive is a rating rendered by a third-party widget such as Trustpilot or Yotpo. The numbers arrive after load, so a raw-HTML crawl sees markup with no matching visible text. That case is handled by [schema/rating-scope](/rules/schema/rating-scope), which recognises the widgets, rather than by this rule.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["schema/review"]
```

### Disable all Structured Data rules

```toml squirrel.toml
[rules]
disable = ["schema/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["schema/review"]
disable = ["*"]
```
