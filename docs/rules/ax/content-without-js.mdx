## What JavaScript-gated content is

Many crawlers and most AI agents fetch a URL and read the bytes the server sent. They do not run a browser. Content a framework injects on the client is therefore absent from what they see, even though it is on screen for a person.

Server rendering or static generation puts the text in the initial HTML, which is what fixes this. Interactive parts can stay on the client; the question is only whether the content an agent needs to understand the page is in the response body. A page whose raw HTML is an empty shell reads to an agent as a page with nothing on it.

## What squirrel checks

The rule compares the raw crawl HTML with a browser-rendered copy of the same page, extracting words from both with the same pipeline so the two counts are comparable. Rendering is a cloud service, so the check needs a cloud audit. It emits one check:

- `content-without-js`, skipped with the message `Raw-vs-rendered content comparison skipped` in three cases: the crawl itself was browser-rendered, which would make the comparison self-identical; the render service was not available for the audit; or the service ran but returned no HTML for this page. The skip reason names which.
- `content-without-js`, at info status with the message `~72% of this page's content (410 words) appears only after JavaScript runs — agents that read raw HTML won't see it`.
- `content-without-js`, passing with the message `Raw HTML already contains the bulk of the rendered content`.

The gap is reported only when all three of the following hold: the rendered page has at least 200 words, at least 100 of them are missing from the raw HTML, and the raw HTML covers no more than 60% of the rendered word count. Coverage is clamped to 100%, because raw can legitimately exceed rendered when a `<noscript>` block is stripped during render. The rule is skipped on a page detected as a soft 404, where raw and rendered are both the error shell.

## How to fix it

Render the primary content on the server. In a framework that supports it, that is the default page mode rather than a client-only component:

```jsx
export default async function Page() {
  const article = await getArticle();
  return <article>{article.body}</article>;
}
```

The test is `curl https://example.com/page | grep "some text from the page"`. If the text is not in the response, an agent reading raw HTML does not have it.

The common false positive is a page that is genuinely an application rather than a document, such as a dashboard behind a login. There is no content for an agent to read there and the finding does not apply. The result is info severity and does not move the score.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["ax/content-without-js"]
```

### Disable all Agent Experience rules

```toml squirrel.toml
[rules]
disable = ["ax/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["ax/content-without-js"]
disable = ["*"]
```
