## What noai and nosnippet are

`noai` and `noimageai` are an informal convention. Some AI companies said they would honour them for text and image use, no specification defines them, and nothing enforces them. They express intent, which is worth recording even where it is not binding.

`nosnippet` and `max-snippet:0` are different. They are long-standing robots directives that Google documents, they tell a search engine not to show a text snippet from the page, and answer engines treat them as instructions not to quote the page verbatim. All four can be declared in a `<meta name="robots">` tag or in an `X-Robots-Tag` response header.

## What squirrel checks

The rule runs on every crawled page. It reads the `X-Robots-Tag` response header and every `<meta>` element whose `name` is `robots`, `ai`, `googlebot` or `bingbot`, and matches four tokens case-insensitively in each: `noai`, `noimageai`, `nosnippet`, and `max-snippet:0` with optional spaces around the colon. It emits one check:

- `noai-signals`: passes with the message `No noai / noimageai / snippet-limit signals declared` and the value `none` when nothing matched. Otherwise it reports at info status with `Declares AI opt-out signals:` followed by the signals found, each described in place, joined with `, `. The four descriptions are `noai (advisory opt-out from AI text use)`, `noimageai (advisory opt-out from AI image use)`, `nosnippet (limits AI-search quoting)` and `max-snippet:0 (limits AI-search quoting)`. When `noai` or `noimageai` is among them the message ends with ` noai/noimageai are advisory only — honoring them is up to each crawler, with no enforcement behind the tag.` Each item names the token and the source it came from, such as `noai in X-Robots-Tag header`.

The `noai` match is word-bounded, so it never fires inside `noimageai`. When the page has no parsed document, which happens on an error page or a stored parse, the rule falls back to the extracted robots meta value alone. This rule reports and never penalises: the only non-info result is the pass.

## How to fix it

There is nothing to fix unless the declaration is missing or wrong. To declare the intent:

```html
<meta name="robots" content="noai, noimageai, nosnippet" />
```

Put it in `<head>`, or send the same directives in an `X-Robots-Tag` header when you want them on non-HTML responses too.

Treat these tags as the declared-intent layer and robots.txt crawler blocks, covered by [ax/ai-crawlers](/rules/ax/ai-crawlers), as the enforcement layer. A `noai` tag with no matching robots.txt block is a request, not a control.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["ax/noai-signals"]
```

### Disable all Agent Experience rules

```toml squirrel.toml
[rules]
disable = ["ax/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["ax/noai-signals"]
disable = ["*"]
```
