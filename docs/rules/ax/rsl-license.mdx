## What RSL is

Really Simple Licensing is an XML format for stating machine-readable terms for a site's content, including whether it may be used for AI training and what a crawl costs. The document is referenced from robots.txt with a `License:` directive, or from a response with a `Link: <...>; rel="license"` header.

It answers a question robots.txt cannot. A `Disallow` says a crawler may not fetch a path. A licence says what may be done with content that was fetched. Publishing one is optional and this rule never asks for one. A reference that points at nothing is the defect it exists to catch.

## What squirrel checks

The rule runs once per crawl. It looks for a `License:` directive in robots.txt, a `Link: rel=license` header, and any licence URLs those produce, then reads the result of fetching each URL. It emits one or two checks:

- `rsl-license`: reports at info status with the message `RSL licensing data not available` when the probe did not run.
- `rsl-license-present`: reports at info status with `No machine-readable licensing declared (no robots.txt License: directive or Link: rel=license)` and the value `absent` when there is no signal at all. No further checks run. Otherwise it reports at info status with `License reference declared via robots.txt License: via Link: rel=license (2 URLs)`, naming whichever sources were present.
- `rsl-license-valid`: reports at info status with `Valid RSL document found at https://example.com/license.xml` when a referenced document returned 200, parsed as XML and read as RSL, adding ` (+1 more)` when several did. When nothing resolved and no document was actually requested, it reports at info status with `License declared but the referenced document was not checked (1 URL)` and the value `unknown`. Otherwise it warns with `License declared but the referenced document didn't resolve as valid RSL (https://example.com/license.xml: HTTP 404)`, listing each broken URL with its error or status.

The distinction in the last bullet is deliberate. A URL the crawl tried and could not fetch is a broken reference and warns. A URL the crawl never requested proves nothing, and the check says it does not know rather than reporting a defect the audit did not establish. Both look like a status of 0, so the recorded reason is the only thing separating them.

## How to fix it

```
User-agent: *
License: https://example.com/license.xml
```

Put the directive in robots.txt and serve a valid RSL XML document at that URL. A `Link: <https://example.com/license.xml>; rel="license"` response header does the same job for consumers that never read robots.txt.

The common false positive is a licence document behind a redirect chain or a WAF that answers the audit differently from a browser. Check the reported status before assuming the file is missing.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["ax/rsl-license"]
```

### Disable all Agent Experience rules

```toml squirrel.toml
[rules]
disable = ["ax/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["ax/rsl-license"]
disable = ["*"]
```
