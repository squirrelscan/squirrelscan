## What archive indexing is

Two archives sit upstream of most AI training data. Common Crawl runs its own crawler, `CCBot`, and publishes a monthly corpus that the major labs build training sets from. The Internet Archive's Wayback Machine captures pages through `ia_archiver` and also ingests Common Crawl's crawls.

They are not the same thing and neither implies the other. A site can have Wayback snapshots and no Common Crawl presence, because the ingest goes one way. Common Crawl has no submission form: inclusion follows from being crawlable and linked, and the next crawl is monthly.

## What squirrel checks

The rule runs once per crawl and looks the domain up in both archives. The lookup is a cloud service, so the check needs a cloud audit. It emits one or two checks:

- `archive-indexing`, skipped with the message `Archive indexing check skipped` when the lookup did not run or returned nothing, with the reason naming why.
- `common-crawl-indexed`: passes with the message `Site is in the Common Crawl index (CC-MAIN-2026-33)`, naming the crawl the record came from. It warns with `Site is in the Common Crawl index but the latest capture is over a year old — recent content is missing from CC-derived AI training data` when the newest capture is more than 365 days before the lookup. With no record it warns with `Site is not in the Common Crawl index — Common Crawl feeds the training corpora of the major AI labs, so the site is invisible to models trained on it`.
- `wayback-archived`: passes with the message `Site is archived in the Wayback Machine`. It warns with `Site is in the Wayback Machine but the latest snapshot is over a year old` past the same 365-day threshold, and with `Site has no Wayback Machine snapshot — the Internet Archive has never captured it, a strong signal the archive crawlers can't reach or discover it` when there is no snapshot at all.

The staleness threshold is measured from the time the lookup was captured, not from the moment the report is read.

## How to fix it

Check that robots.txt does not block the archive crawlers:

```
User-agent: CCBot
Allow: /

User-agent: ia_archiver
Allow: /
```

Then request a Wayback snapshot at `web.archive.org/save`. Common Crawl has no equivalent: fix crawlability, make sure something links to the site, and wait for the next monthly crawl.

The common false positive is a site that launched recently. Common Crawl runs monthly and the Internet Archive captures on its own schedule, so a new domain can be absent from both while nothing is wrong with it.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["ax/archive-indexing"]
```

### Disable all Agent Experience rules

```toml squirrel.toml
[rules]
disable = ["ax/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["ax/archive-indexing"]
disable = ["*"]
```
