## What edge blocking is

robots.txt states a policy. It does not enforce one. A site can allow an AI user-agent in robots.txt and still block it in front of the origin, through a WAF rule, a CDN bot-management toggle, or a managed rule set with a "block AI bots" switch. The crawler gets a challenge page, a 403, or a stripped-down interstitial, and nothing in robots.txt shows it.

The two cases differ in cost. Blocking a training crawler such as `GPTBot` is often the intent behind flipping that switch. Blocking `Claude-User` is not: that user-agent fetches a page because a person asked for it inside an assistant and is waiting for the answer.

## What squirrel checks

The rule runs once per crawl. It uses three homepage fetches made during the prefetch phase, one with a browser user-agent, one as `GPTBot` and one as `Claude-User`, and compares each AI response against the browser baseline. It emits one or two checks: at most one per AI probe, or a single check covering all of them.

- `agent-blocking`, skipped with the message `Agent-access probe data not available` when the prefetch did not run, or `Browser baseline did not return 2xx (status <status>) — cannot compare agent access` when the browser fetch itself failed, where `<status>` is the status it returned or `n/a` when the probe is missing entirely. Without a healthy baseline the site may be down for everyone, so the rule declines to blame the agents.
- `agent-access-payment`: reports at info status with the message `<agent> hit a pay-per-crawl wall (<signal>) — reported by ax/pay-per-crawl, not a block` when the response is a 402 or carries a payment signal. The parenthesised signal is omitted when the response named none. A deliberate payment wall is not an access block.
- `agent-access`: at info status with `<agent> probe was inconclusive (<reason>)` when the request never completed. At warn status with `<agent> got the same status as the browser but only N% of the body — likely a soft-block / interstitial served to the agent` when the agent response was itself 2xx, the browser body was not empty, and the agent body came back under a fifth of its size. At warn status with `<agent> is blocked (<reason>) while the browser gets 200 — often an intentional training opt-out, but confirm it was deliberate` for a bot challenge, a 401, a 403 or a 5xx. The same condition on `Claude-User` is a fail with `Claude-User is blocked (<reason>) while the browser gets 200 — this breaks a live fetch a real user triggered inside an assistant, the worst case for agent access`.
- `agent-blocking`: passes with `GPTBot and Claude-User reached the homepage like a browser`, naming the probes it ran, when none of them was classified as blocked, soft-blocked, inconclusive or payment-walled. An unchallenged 3xx or 404 counts as clean, since the rule is comparing access rather than status.

The soft-block threshold is a fifth of the browser body size. That is the shape of an interstitial: a 2xx with a fraction of the content. The rule's severity is error so that a blocked user-action fetcher badges as an error; a training-crawler block emits a warn check, which the report downgrades to a warning on its own.

## How to fix it

Allow-list the user-action fetchers in the edge rules, whatever the bot-management preset does by default:

```
ChatGPT-User
Claude-User
Perplexity-User
```

These three fetch on behalf of a person who is waiting. Blocking a training crawler alongside them is a separate decision, and this rule reports it without penalising the score.

The common false positive is a rate limit that happens to catch the probe. A single homepage fetch is unlikely to trip one, but a site already under load can return a 5xx to the agent and a 200 to the browser by luck of timing. Re-run the audit after any WAF, CDN or bot-management change and check whether the finding is stable.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["ax/agent-blocking"]
```

### Disable all Agent Experience rules

```toml squirrel.toml
[rules]
disable = ["ax/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["ax/agent-blocking"]
disable = ["*"]
```
