Agent experience is how well a site works for something other than a browser with a person behind it: a chat assistant, an answer engine, or an autonomous agent. These rules ask whether such a client can read the content, reach the site at all, discover an entry point, understand the policy the site declares, and act on what it finds. Agent experience is scored as one of the four groups on every report, alongside SEO, performance and security.

See [AI crawlers](https://squirrelscan.com/learn/ai-crawlers) for how an agent works through a report.

<Note>Most AX signals are emerging standards, not settled ones. These rules are deliberately informational recommendations: they surface what an agent sees without penalizing your health score, with the exception of genuine misconfigurations: [AI Crawler Access](/rules/ax/ai-crawlers), [Agent Blocking](/rules/ax/agent-blocking), and [Token Weight](/rules/ax/token-weight) always score, and [Content Signals](/rules/ax/content-signals), [RSL License](/rules/ax/rsl-license), [Pay Per Crawl](/rules/ax/pay-per-crawl), and a masquerading [llms.txt](/rules/ax/llms-txt) warn only when something you declared is contradictory, broken, or misfiring. Even those keep training-crawler blocks informational: it is blocking an AI-search indexer or a user-action fetcher that carries the warning.</Note>

## The five pillars

AX splits into five questions, each covered by one or more rules.

### Readable

Readable asks whether an agent that fetches a URL gets the content. Most agent fetchers, such as `ChatGPT-User` and `Claude-User`, are plain HTTP clients with no JavaScript engine, so anything that only exists after hydration is invisible to them. Readable also covers token weight: a page bloated with markup relative to its text costs an agent more tokens to parse for the same information.

- [Content Without JavaScript](/rules/ax/content-without-js): flags main content that only renders client-side
- [Token Weight](/rules/ax/token-weight): per-page token estimate and text-to-HTML ratio
- [Markdown Response](/rules/ax/markdown-response): serving clean Markdown via content negotiation or a `.md` variant

### Reachable

Reachable asks whether legitimate agents are let in. `robots.txt` is the front door, and it has three different kinds of visitors to reason about: crawlers that train models (`GPTBot`, `ClaudeBot`, `CCBot`, `Google-Extended`), crawlers that back AI search results (`OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot`), and fetchers acting on a live user request (`ChatGPT-User`, `Claude-User`, `Perplexity-User`). These are separate user-agent tokens with separate policies: blocking `ClaudeBot` does not block `Claude-User`. Beyond declared policy, a WAF or bot-challenge page that 403s a verified agent breaks reachability regardless of what `robots.txt` says.

- [AI Crawler Access](/rules/ax/ai-crawlers): what `robots.txt` declares for each crawler class
- [Agent Blocking](/rules/ax/agent-blocking): behavioral probe for WAF/challenge responses served to agent user-agents

### Discoverable

Discoverable asks whether the site exposes a machine-readable entry point instead of making an agent guess. This is `llms.txt` and its neighbors: sitemaps, feeds, structured data, `AGENTS.md` for coding agents working in a repo or against docs, and the newer `.well-known` agent descriptors (MCP server cards, A2A agent cards, agent-skills manifests).

- [llms.txt](/rules/ax/llms-txt): curated Markdown map of the site's key content
- [AGENTS.md](/rules/ax/agents-md): repo and docs-oriented instructions file for coding agents
- [Well-Known Agent Files](/rules/ax/well-known-agent): MCP server cards, A2A agent cards, agent-skills manifests

### Declared

Declared asks whether the site has said anything explicit about AI access. A `Content-Signal` line in `robots.txt`, an RSL license, or a `noai` tag are all ways of declaring a position. Even "no" is good AX: an explicit block is a clear answer an agent can act on. Ambiguity, or worse, contradiction (declaring `ai-train=yes` while blocking `GPTBot`), is bad AX.

- [Content Signals](/rules/ax/content-signals): `Content-Signal` policy lines in `robots.txt`
- [noai Signals](/rules/ax/noai-signals): `noai`/`noimageai` and AI-search-quoting opt-outs
- [RSL License](/rules/ax/rsl-license): machine-readable licensing terms via the RSL standard

### Actionable

Actionable asks whether an agent can go beyond reading and transact: call an API, use an MCP endpoint, authenticate, or pay for access. This is the newest part of the category, covering OpenAPI specs, OAuth discovery documents, and HTTP 402 monetized-access responses.

- [API & OAuth Discovery](/rules/ax/api-discovery): `api-catalog`, OpenAPI, OAuth discovery documents
- [Pay Per Crawl](/rules/ax/pay-per-crawl): HTTP 402 monetized agent access (Cloudflare Pay Per Crawl, x402)
- [Archive Indexing](/rules/ax/archive-indexing): presence in the Wayback Machine and Common Crawl, the archives AI training corpora are built from (cloud)

<Note>`llms.txt` has no proven SEO value. Google has said it does not use it for search ranking or indexing. Treat it as a convenience for coding agents and docs consumption, not a ranking lever.</Note>
