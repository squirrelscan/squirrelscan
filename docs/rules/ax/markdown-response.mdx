## What a Markdown response is

Content negotiation lets one URL serve more than one representation. A client sends `Accept: text/markdown`, the server returns Markdown instead of HTML, and a `Vary: Accept` header tells caches that the response depends on the request header. `text/markdown` has been a registered media type since RFC 7763.

Two simpler routes exist. A `.md` twin of the page, such as `/index.md`, is a second URL with the same content. A `Link: <...>; rel="alternate"; type="text/markdown"` header on the HTML page advertises where that twin lives, which is how a site whose homepage is an application shell can still point an agent at readable content.

## What squirrel checks

The rule runs once per crawl against the homepage and emits one or two checks:

- `markdown-response`: reports at info status with the message `markdown probe data not available` when the probe did not run. Otherwise it reports at info status with `Serves Markdown for agents via content negotiation (text/markdown) and .md variant (https://example.com/index.md) and link rel=alternate (https://example.com/index.md)`, listing whichever of the three signals it found joined with ` and `. With none of them it warns with `No Markdown response — consider honoring Accept: text/markdown or publishing a .md variant so agents get clean content`.
- `markdown-response-headers`: emitted only when a supplementary signal is present, at info status, with the message `Additional Markdown-negotiation signals:` followed by the signals joined with `; `. Two are recognised: a `Vary` header on the negotiated response that mentions `Accept`, and Cloudflare's markdown-transform fingerprint, reported as `Cloudflare markdown-transform fingerprint (x-markdown-tokens: 1200, x-original-tokens: 9800, ~12% of original)`.

The rule's severity is info, so the warning surfaces as a recommendation and does not move the score. The `link rel=alternate` signal is counted in the first check and deliberately not repeated in the second.

## How to fix it

Honour the header and advertise the twin:

```
HTTP/1.1 200 OK
Content-Type: text/markdown; charset=utf-8
Vary: Accept
Link: <https://example.com/index.md>; rel="alternate"; type="text/markdown"
```

Serving the `.md` twin alone is enough to satisfy the check, and it is the least invasive of the three. Set `Vary: Accept` whenever the same URL returns different bodies for different `Accept` headers, or a cache will hand the HTML to an agent that asked for Markdown.

There is no common false positive. Absence is a recommendation and never a defect.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["ax/markdown-response"]
```

### Disable all Agent Experience rules

```toml squirrel.toml
[rules]
disable = ["ax/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["ax/markdown-response"]
disable = ["*"]
```
