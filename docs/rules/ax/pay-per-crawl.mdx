## What pay-per-crawl is

HTTP 402 Payment Required has been reserved in the HTTP specification for years and has only recently found a use: charging automated clients for access. Cloudflare's Pay Per Crawl returns a 402 with a `crawler-price` header naming what a fetch costs. x402 is a separate scheme that returns a 402 with a JSON body describing how to pay.

Charging for crawler access is a business decision, not a defect, and this rule reports it as such. The one case worth calling out is scope. A training crawler pulling thousands of pages and a person's assistant fetching one page they asked about are different clients, and a 402 aimed at the first will hit the second unless the rule is scoped.

## What squirrel checks

The rule runs once per crawl and reads the three homepage probes made during prefetch: one with a browser user-agent, one as `GPTBot` and one as `Claude-User`. It emits one or two checks:

- `pay-per-crawl`: reports at info status with the message `agent access probe data not available` when the probes did not run. With no probe requiring payment it reports at info status with `No monetized agent access (pay-per-crawl / x402) detected` and the value `absent`. Otherwise it reports at info status with `Monetized agent access configured via <mechanisms> for <user-agents>`, joining the distinct mechanisms with ` and ` and the charged user-agent names with `, `. A `crawler-price` or `crawler-charged` signal reads as Cloudflare Pay Per Crawl, an x402 body reads as x402, and anything else reads as `an unnamed HTTP 402 payment wall`.
- `pay-per-crawl-user-action`: emitted only when `Claude-User` is charged while the browser probe returned a 2xx. It warns with the message `Claude-User (a live user-action fetch) is charged HTTP 402 while browsers get a normal 2xx response — this bills a real person's in-the-moment question, not a background crawl`.

Detection is a report, not a judgement. Only the second check can affect anything, and it fires on one specific asymmetry: a person's live request being billed while an ordinary browser is not.

## How to fix it

Scope the 402 to the crawler classes you meant to charge, and exclude the user-action fetchers:

```
ChatGPT-User
Claude-User
Perplexity-User
```

These three fetch because a person asked, so they belong outside the payment wall even on a site that charges for bulk crawling.

There is no common false positive. A 402 is unambiguous, and the rule hands the case off from [ax/agent-blocking](/rules/ax/agent-blocking) so a payment wall is never reported as an access block.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["ax/pay-per-crawl"]
```

### Disable all Agent Experience rules

```toml squirrel.toml
[rules]
disable = ["ax/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["ax/pay-per-crawl"]
disable = ["*"]
```
