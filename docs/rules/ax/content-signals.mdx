## What Content-Signal is

`Content-Signal` is a robots.txt directive that states policy per purpose rather than per bot. It takes comma-separated `key=value` pairs, and three keys are defined: `search` covers search-result display and answer-engine citation, `ai-input` covers use as input to an AI system at inference time, and `ai-train` covers training or fine-tuning a model. Each takes `yes` or `no`.

```
User-agent: *
Content-Signal: search=yes, ai-input=yes, ai-train=no
```

It sits inside a normal robots.txt group, so a directive under `User-agent: *` speaks for every crawler and one under a named group speaks only for those agents. Cloudflare's managed robots.txt also emits a `use=` key with the values `immediate`, `reference` or `full`, describing how a collected page may be consumed. Declaring a signal is optional.

## What squirrel checks

The rule runs once per crawl against the raw robots.txt. It strips comments, tracks which user-agent group each `Content-Signal:` line sits under, and emits one to three checks:

- `content-signals`: reports at info status with the message `No Content-Signal declared in robots.txt (optional per-purpose AI policy)` and the value `absent` when no directive is present. No further checks run.
- `content-signals-policy`: always emitted when a directive is present, at info status. The message is `Content-Signal declares:` followed by each declared key as `search=yes (search-result display & answer-engine citation)`, joined with `; `, and then any recognised auxiliary key as `use=full`. When a directive is present but declares nothing recognised, the message is `Content-Signal present but declares no recognized signal`.
- `content-signals-syntax`: warns when a token's key is not one of the three signals or `use`, or when a value is anything other than `yes` or `no`, or when a token has no `=` at all. The message is `Content-Signal has invalid syntax — unknown key(s): foo; malformed token(s): bar. Valid form is comma-separated key=value using search/ai-input/ai-train with yes/no.`
- `content-signals-contradiction`: warns when a signal is declared `yes` while robots.txt fully disallows the crawler class that signal implies access for. `search` maps to the AI-search indexers, `ai-input` to the user-action fetchers, and `ai-train` to the training crawlers. The message is `Content-Signal ai-train=yes but robots.txt fully Disallow-s GPTBot, ClaudeBot — a crawler can't tell which directive wins`, one clause per contradiction joined with `; `.

A contradiction is only reported inside the directive's own scope. A `Content-Signal` under `User-agent: *`, or outside any group, is checked against every blocked crawler; one under a named group is checked only against blocks on those agents. Full blocking means `Disallow: /` with no `Allow: /` in the groups that apply to the bot. Each signal is reported at most once.

## How to fix it

```
User-agent: *
Content-Signal: search=yes, ai-input=yes, ai-train=no

User-agent: GPTBot
Disallow: /
```

Put the directive in robots.txt and keep it in step with the blocks below it. The example is consistent: `ai-train=no` and a disallowed training crawler say the same thing. Declaring `ai-train=yes` above that block is what the contradiction check reports.

There is no common false positive. Absence is reported at info status and never affects the score.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["ax/content-signals"]
```

### Disable all Agent Experience rules

```toml squirrel.toml
[rules]
disable = ["ax/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["ax/content-signals"]
disable = ["*"]
```
