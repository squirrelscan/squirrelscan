## What LLM parsability is

LLM parsability is how reliably a language model reads a page and comes away with the right facts: what the page is about, what it claims, and what the reader is meant to do next. A page scores badly when its real content is tangled with navigation text, banners and layout strings, when sections have no headings to anchor them, or when pronouns and references point at things the model has to guess.

It is not human readability and it is not a search ranking factor. It matters because assistants and answer engines quote what they parsed cleanly. Content written clearly for a person usually scores well without any separate work.

## What squirrel checks

The rule runs on every crawled page. Scoring is a cloud service, so the check needs a logged-in audit. It emits one check:

- `llm-parsability`, skipped with the message `LLM parsability analysis skipped` when the analysis was not available for the audit, with the skip reason naming why.
- `llm-parsability`, passing with the message `LLM parsability score: 84/100` at a score of 70 or above.
- `llm-parsability`, warning with the message `LLM parsability could be improved: 55/100` at a score from 40 to 69.
- `llm-parsability`, failing with the message `Poor LLM parsability: 21/100` at a score below 40.

The score is rounded to a whole number and the expected value shown in the report is `>= 70`. An audit where the analysis ran but returned nothing scores 0, which reads as a failure rather than a skip.

| Score | Status |
|-------|--------|
| 70 to 100 | Pass |
| 40 to 69 | Warning |
| 0 to 39 | Fail |

## How to fix it

Put the content in semantic elements so the model can tell it apart from the furniture:

```html
<main>
  <h1>Configuring the build cache</h1>
  <p>The build cache stores compiled output between runs...</p>
</main>
```

Give every section a heading that names what is in it, open each section with a sentence that states its point, and replace pronouns whose referent is more than a sentence away with the noun itself.

The common false positive is a page that is mostly a table, a form or a diagram. There is little prose for the model to parse and the score reflects that, but there may be nothing worth changing.
