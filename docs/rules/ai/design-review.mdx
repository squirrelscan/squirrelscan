## What a design inconsistency is

A site has a design system whether or not anyone wrote it down: a spacing grid, a few fonts, a handful of colors, and components that look the same on every page. Drift is when one page quietly breaks it, such as a pricing page whose call to action has more padding than the same button everywhere else.

Deterministic rules cannot judge that. A vision model can, so this is the one place squirrel asks one.

## What squirrel checks

A bounded sample of at most 6 pages is screenshotted and reviewed. The request is grounded with the site's own fonts, colors and spacing grid, so the model compares pages against your system and not against an outside design norm.

The rule never calls a model itself. It reads the review result and keeps a finding only when it is concrete:

- it names a sampled page and a specific element,
- the deviation carries a measured value (`24px`, `#1a73e8`, `2 columns`), not an adjective,
- it states what the site does elsewhere, and
- it cites at least one other sampled page that shows that norm.

Generic advice ("the layout feels cluttered") is dropped. At most 10 findings are reported.

It emits these checks:

- `design-review`, skipped when logged out, out of credits, not opted in, or the service was unavailable.
- `design-review`, passing with `No cross-page design inconsistencies in 3 sampled pages`.
- `design-review-deviation`, warning with a message such as `primary CTA button on https://example.com/pricing: padding is 24px, 8px off the 16px the other pages use (site norm: CTA padding is 16px)`.

## How to fix it

Make the element match the pages cited as the norm. Better, move it into a shared component or design token so it cannot drift again:

```css
.btn-primary { padding: var(--space-4); }
```

The model reads screenshots, so a deviation caused by a deliberate variant (a promo banner button) can be reported. Treat each finding as a pointer to look, then decide.

```toml squirrel.toml

disable = ["ai/design-review"]
```

### Disable all AI rules

```toml squirrel.toml
[rules]
disable = ["ai/*"]
```

## Check names by outcome

Each check name this rule can emit, by what it means to a tool comparing two audits. A **problem** check is a finding. A **clean** check says the rule ran over what it covers and found nothing; it clears the problem checks listed beside it, so a finding is fixed when the rule ran over the same scope and a clean check took its place. A **not checked** check says the rule did not evaluate, and never clears a finding.
