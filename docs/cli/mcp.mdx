The `mcp` command starts a [Model Context Protocol](https://modelcontextprotocol.io) server over stdio for agents that launch local servers, such as Claude Code and Cursor. It is a front end for the [hosted MCP server](/developers/mcp): every request goes to `https://mcp.squirrelscan.com/mcp` with the credential the CLI already holds. It has no tools of its own.

<Info>
Clients with no shell (Claude Desktop, ChatGPT) connect to the hosted URL directly and do not need this command. Use `squirrel mcp` when the client launches stdio servers, or when you want the [channel](#channel-events).
</Info>

## Usage

```bash
squirrel mcp [--channel] [--interval <seconds>] [--categories <list>]
```

The server runs in the foreground and speaks JSON-RPC on stdin and stdout. Your agent spawns it from its MCP config:

```bash
claude mcp add squirrelscan -- squirrel mcp
```

Existing `squirrel mcp` configs keep working unchanged: the command and the transport are the same.

## One tool set

`tools/list`, `tools/call`, `resources/*`, `prompts/*` and the `skills/*` methods are forwarded to the hosted server as they are. A tool added to the hosted server shows up here with no CLI release, and a call returns what the hosted server returns for the same credential. See the [hosted tool reference](/developers/mcp) for the tools.

Tools of the old local server that the hosted server names differently keep working for one release: `audit_website` and `quick_check` are forwarded to `run_audit` (with `level: "quick"` for `quick_check`). They always run in the cloud, and `offline: true` returns an error that points to `squirrel audit`.

## Needs a login

The MCP is the cloud surface. It uses the same [credential resolution](/developers/authentication) as the rest of the CLI: `SQUIRRELSCAN_API_KEY` (or the older `SQUIRREL_API_TOKEN`) first, then the session from `squirrel auth login`. The credential is read on every request, so a refreshed login is picked up without restarting the server.

Signed out, the catalog still lists (`tools/list`, resources, prompts and skills work), and every tool call returns one error that names `squirrel auth login` and says that free local audits are available through `squirrel audit`.

## Free and local audits

Free audits, and audits of `localhost`, staging and private networks, run on your machine with [`squirrel audit`](/cli/audit) and its output formats (`--format llm`, `json`, `markdown`). Agents with a shell already drive that through the squirrelscan skill. Publish the audit and the forwarded `get_report` tool reads it back.

## Channel events

`squirrel mcp --channel` also declares the Claude Code `claude/channel` capability and pushes cloud events (`audit_complete`, `audit_failed`, `issues_detected`) into the session while the forwarded tools stay available. [`squirrel channel`](/cli/channel) is an alias of it. See the [channel guide](/developers/channel) for setup and the security model.

| Option | Default | Description |
|--------|---------|-------------|
| `--channel` | off | Declare the channel and deliver cloud events. |
| `--interval` | `30` | With `--channel`: seconds between polls of the cloud feed (5 to 86400). |
| `--categories` | all three | With `--channel`: comma-separated event categories to deliver. |

## Supported protocol versions

The front end serves whatever protocol version the client asks for, and talks to the hosted server on the current revision, so the two sides do not need to match.

| Protocol version | How a client connects |
|------------------|-----------------------|
| `2026-07-28` | No `initialize` handshake. The client sends its version and capabilities on each request. |
| `2025-11-25` and earlier | The `initialize` handshake. |

With `--channel` the server uses the `initialize` handshake only, because Claude Code registers a channel only over it.

## Environment

| Variable | Description |
|----------|-------------|
| `SQUIRRELSCAN_API_KEY` | API key used instead of a login session, for headless agents and CI. |
| `SQUIRREL_MCP_SERVER` | Override the hosted MCP URL (for a staging server). |

Logs and diagnostics go to stderr. Stdout carries only the JSON-RPC stream.
