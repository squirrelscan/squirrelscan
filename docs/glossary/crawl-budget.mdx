**Crawl budget** is the number of URLs a search engine is able and willing to crawl on a site in a given period, set by how much load the server can take and how much the search engine wants the content.

Google calls the two parts the crawl capacity limit and crawl demand. Capacity starts at a conservative default and rises if the site stays fast and healthy. It drops when responses slow down or the server answers with 5xx errors or 429. Demand depends on the site's size, how often it changes, page quality and relevance. Google treats each hostname as its own site with its own budget.

## Why it matters

For most sites it does not. Google's guide is aimed at sites with a million or more pages that change weekly, or 10,000 or more that change daily. It says that if your pages are crawled the same day they are published, you do not need it, and that a current sitemap plus a regular look at the Page Indexing report is enough for Google Search.

On a large site, wasted fetches add up. Every hop in a redirect chain is a request. A soft 404 answers 200, so the search engine has to work out from the content that the page is missing. Parameter combinations turn one listing into over a hundred URLs with near-identical content. Google's own advice includes returning 404 or 410 for removed pages, which it calls a strong signal not to crawl the URL again, and avoiding long redirect chains.

## How squirrelscan checks it

squirrelscan cannot see a search engine's crawl budget. Its rules flag the patterns that waste one. [crawl/redirect-chain](/rules/crawl/redirect-chain) counts the hops on every crawled URL and warns past two by default. [links/redirect-chains](/rules/links/redirect-chains) finds internal links that point at redirecting URLs. [crawl/soft-404](/rules/crawl/soft-404) detects error pages served with 200 and re-fetches them at the end of the crawl to confirm. [crawl/sitemap-4xx](/rules/crawl/sitemap-4xx) lists sitemap entries that answer 4xx, keeping rate-limited ones apart. [url/parameters](/rules/url/parameters) counts query parameters per URL, warns above three and names tracking parameters such as `utm_source` and `gclid`.

## How to fix it

Make every URL a crawler requests worth the request. Send one redirect hop at most:

```nginx
server {
  listen 80;
  server_name example.com www.example.com;
  return 301 https://www.example.com$request_uri;
}
```

Then update internal links to the final URLs ([the redirect chain fix](/rules/crawl/redirect-chain#how-to-fix-it), [the internal link fix](/rules/links/redirect-chains#how-to-fix-it)). Return a real 404 for missing content ([the soft 404 fix](/rules/crawl/soft-404#how-to-fix-it)), remove dead entries from the sitemap ([the sitemap 4xx fix](/rules/crawl/sitemap-4xx#how-to-fix-it)), and point parameter variants at the clean URL with a canonical ([the parameters fix](/rules/url/parameters#how-to-fix-it)).

## Run the check

{/* glossary:run:start */}

```bash
squirrel audit https://example.com --rule-include crawl/redirect-chain,crawl/sitemap-4xx,crawl/soft-404,url/parameters,links/redirect-chains
```

{/* glossary:run:end */}

A signed-out local audit costs nothing.

## Related terms

- [Redirect chain](/glossary/redirect-chain): A sequence of two or more redirects between the requested URL and the final response.
- [Soft 404](/glossary#soft-404): A page that tells the visitor it does not exist (or is empty) while the server answers HTTP 200.
- [URL parameters](/glossary#url-parameters): Key-value pairs after ? in a URL; tracking and sort parameters can multiply URLs for the same content.
- [XML sitemap](/glossary/xml-sitemap): An XML file listing the URLs a site wants crawled, with optional lastmod dates, referenced from robots.txt or submitted to search engines.
