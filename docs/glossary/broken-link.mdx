A **broken link** is a link whose target answers with an error status, fails to resolve at all, or is written so badly that it cannot be followed.

There are several kinds. An internal link to a page that answers 404 or 500 is a dead end on your own site. An external link can break when another site moves or shuts down, and the request may fail outright on DNS or TLS. A fragment link such as `/pricing#team` breaks when the target page has no element with `id="team"` and no `<a name="team">`. A malformed `href` never had a target in the first place. Google treats a 4xx response other than 429 as content that does not exist.

## Why it matters

A broken link costs a visitor a click and a crawler a request, on every page that carries it. Internal links break quietly when a page is renamed and the old links stay in body copy and menus. External links decay with time. Some links only look broken, though. A site behind bot protection can refuse an automated check and still load fine in a browser, so a link checker has to keep "broken" and "could not verify" apart.

## How squirrelscan checks it

[links/broken-links](/rules/links/broken-links) compares every internal link with the status the crawl recorded and fails targets that answered 400 or above, listing the pages that link to each. Rate-limited and refused targets are reported as unverifiable, and targets the audit never fetched are not counted as broken. [links/broken-external-links](/rules/links/broken-external-links) reads the external link check, which runs only when external link checking is on, and groups failures by status. Links that bot protection refused, or that timed out, are listed as unverified. [links/dead-links](/rules/links/dead-links) is an info-level summary of the same check. [links/broken-anchors](/rules/links/broken-anchors) checks each fragment against the ids on the crawled target page, case-sensitively, as browsers do. [links/invalid-links](/rules/links/invalid-links) reports hrefs the parser could not resolve. [images/broken-images](/rules/images/broken-images) flags an empty, `#` or `data:error` image source. It sends no request, so a well-formed image URL that answers 404 passes.

## How to fix it

Point each link at the URL that works now, and fix it at the source:

```html
<a href="/guides/build-cache">Build cache guide</a>
<a href="/pricing#team-plan">Team plan</a>
```

The report lists every page that carries a broken link, so a link in a template is one change ([the internal link fix](/rules/links/broken-links#how-to-fix-it)). Where you cannot update every link, redirect the old URL permanently. Replace dead external links with a working page or an archived copy, and check unverified ones in a browser before changing them ([the external link fix](/rules/links/broken-external-links#how-to-fix-it)). Update a fragment to the id that exists now ([the anchor fix](/rules/links/broken-anchors#how-to-fix-it)), and replace a click-target anchor with a `<button>` ([the invalid link fix](/rules/links/invalid-links#how-to-fix-it)).

## Related terms

- [HTTP status code](/glossary/http-status-code): The three-digit code a server returns with every response; 2xx success, 3xx redirect, 4xx client error, 5xx server error.
- [Fragment link](/glossary#anchor-link): A link to an id within a page (#section); it is broken when no element on the target page carries that id.
- [Redirect chain](/glossary/redirect-chain): A sequence of two or more redirects between the requested URL and the final response.
