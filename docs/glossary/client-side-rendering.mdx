**Client-side rendering** (CSR) is building a page's content in the browser with JavaScript, so the HTML the server sends is a shell that only fills in after scripts run.

It is the default for many single-page apps: the HTML loads the JavaScript, and the JavaScript generates the content. The alternatives put the content in the first response. Server-side rendering builds the HTML on the server for each request, and static generation or prerendering builds it ahead of time.

## Why it matters

Whether a client sees the content depends on whether it runs JavaScript. Googlebot queues pages for rendering and runs them in a headless Chromium when its resources allow, a separate queue after the crawl. Google notes that other search engines may ignore JavaScript and miss content it generates. Most AI agent fetchers, such as `ChatGPT-User` and `Claude-User`, run no JavaScript at all, so a client-rendered article reads to them as an empty page.

## How squirrelscan checks it

[ax/content-without-js](/rules/ax/content-without-js) compares the raw HTML from the crawl with a browser-rendered copy of the same page and counts the words in each. It reports the share of the content that only appears after JavaScript runs, once the gap is large enough to matter (the thresholds are on the rule page). Rendering is a cloud service, so this comparison needs a cloud audit. [perf/browser-required](/rules/perf/browser-required) lists the measurements a static audit cannot make, such as the Core Web Vitals, which need a real render. squirrelscan does not measure LCP, INP or CLS.

## How to fix it

Render the main content on the server or at build time, and keep the interactive parts on the client. In a framework that supports it, that is usually the default page mode rather than a client-only component (see [the content-without-JavaScript fix](/rules/ax/content-without-js#how-to-fix-it)):

```jsx
export default async function Page() {
  const article = await getArticle();
  return <article>{article.body}</article>;
}
```

To test a page by hand, fetch it without a browser and look for a sentence you can see on screen: `curl https://example.com/page | grep "some text from the page"`. If the text is not in the response, an agent reading raw HTML does not have it. A dashboard behind a login is an application, not a document, and the finding does not apply to it.
