**Heading hierarchy** is the nesting of `<h1>` to `<h6>` headings that gives a page its outline, for people scanning it, for screen reader users moving through it and for software that parses it.

The W3C's page structure tutorial puts it simply: headings communicate the organization of the content, and browsers and assistive technology use them for in-page navigation. A heading of equal or higher rank starts a new section, and a lower rank starts a subsection. The tutorial says skipping ranks, an `<h2>` followed directly by an `<h4>`, can be confusing and should be avoided where possible. Closing subsections is the exception: an `<h4>` followed by an `<h2>` is fine.

## Why it matters

A screen reader user can list a page's headings and jump between them, so the outline is the table of contents. A skipped level suggests a missing section. An empty heading is announced as a heading with nothing in it. Headings are also structure under WCAG success criterion 1.3.1, Info and Relationships, which asks that relationships shown visually are also available in the markup. The common cause is choosing a heading level for its font size.

## How squirrelscan checks it

[a11y/heading-order](/rules/a11y/heading-order) reads every heading in document order and warns when one is more than a level deeper than the one before, listing each skip as `H3 after H1`. The first heading on the page never counts as a skip. [content/heading-hierarchy](/rules/content/heading-hierarchy) also warns on skipped levels and on empty headings, and notes headings over 70 characters and repeated heading text at info level. [a11y/empty-heading](/rules/a11y/empty-heading) warns on a heading with no text, no label and no image alt, skipping headings that are hidden from the accessibility tree. [core/h1](/rules/core/h1) fails a page with no `<h1>` and warns on more than one, or on an empty one.

All four read the HTML the server sent, so headings rendered by JavaScript are only seen when browser rendering is on.

## How to fix it

Choose each level from its place in the outline, and set the size in CSS:

```html
<h1>Pricing</h1>
<h2>Plans</h2>
<h3>Team</h3>
<h2>Frequently asked questions</h2>
```

Two components stacked on one page often skip a level at the seam. Pass the starting level into the component as a prop ([the heading order fix](/rules/a11y/heading-order#how-to-fix-it)). Turn a heading used only for styling into a `<div>` or `<p>` ([the empty heading fix](/rules/a11y/empty-heading#how-to-fix-it)). Give each page one `<h1>` at the top of the main content. A logo in an `<h1>` in the site header belongs to the site, not the page ([the h1 fix](/rules/core/h1#how-to-fix-it)).
