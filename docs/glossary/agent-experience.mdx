**Agent experience (AX)** is how well a site serves the AI agents that read it, find their way around it and act on it, the way UX describes how it serves people.

The client might be a chat assistant fetching a page a person asked about, an answer engine building its index, or an autonomous agent calling an API. Most agent fetchers, such as `ChatGPT-User` and `Claude-User`, are plain HTTP clients with no JavaScript engine: they read the HTML the server sent and nothing else.

## Why it matters

A page whose raw HTML is an empty shell reads to an agent as a page with nothing on it, even when a person sees a full article. Access breaks in less visible ways too. AI vendors use separate user-agent tokens for training, search and user requests: Anthropic, for example, runs `ClaudeBot`, `Claude-SearchBot` and `Claude-User` as three bots. A block meant for training can end up stopping the fetch a person is waiting on inside an assistant.

## How squirrelscan checks it

squirrelscan splits AX into five pillars, each with its own rules on the [Agent Experience hub](/rules/ax#the-five-pillars):

- Readable: is the content in the raw HTML, and how many tokens does the page cost?
- Reachable: do robots.txt and the edge let AI crawlers and fetchers in?
- Discoverable: is there a machine-readable entry point, such as `llms.txt` or a `.well-known` manifest?
- Declared: has the site stated a policy for AI use, such as a `Content-Signal` line?
- Actionable: can an agent find the API and the OAuth metadata it needs?

Agent experience is one of the four score groups on every report. Most AX rules are informational and do not move the score. AI crawler access, agent blocking and token weight always score.

## How to fix it

Start with Readable and Reachable, because the other pillars depend on an agent getting the page at all. Render the main content on the server so it is in the response body (see [the content-without-JavaScript fix](/rules/ax/content-without-js#how-to-fix-it)), and make sure robots.txt and the WAF let in the fetchers that act for a person:

```
User-agent: GPTBot
Disallow: /

User-agent: OAI-SearchBot
Allow: /

User-agent: ChatGPT-User
Allow: /
```

This example opts out of OpenAI's training crawl and lets in its search crawler and the fetches a person starts in ChatGPT. The [AI crawler access fix](/rules/ax/ai-crawlers#how-to-fix-it) and the [agent blocking fix](/rules/ax/agent-blocking#how-to-fix-it) cover the other vendors and the edge.

## Run the check

{/* glossary:run:start */}

```bash
squirrel audit https://example.com --rule-include ax/content-without-js,ax/token-weight,ax/markdown-response,ax/ai-crawlers,ax/agent-blocking,ax/llms-txt,ax/agents-md,ax/well-known-agent,ax/content-signals,ax/api-discovery
```

{/* glossary:run:end */}

To run every agent experience rule, use `--rule-include ax`. A signed-out local audit costs nothing. The raw-versus-rendered comparison in [ax/content-without-js](/rules/ax/content-without-js) needs a cloud audit, because rendering is a cloud service.

## Related terms

- [llms.txt](/glossary/llms-txt): A proposed Markdown file at /llms.txt that gives language models a curated map of a site's key content.
- [AI crawler](/glossary/ai-crawler): A bot that fetches pages for AI companies, in three classes: training crawlers, AI search indexers and user-triggered fetchers, each with its own user-agent token.
- [Generative engine optimization (GEO)](/glossary/generative-engine-optimization): Making content more likely to be retrieved, cited and quoted by AI answer engines; the term comes from a 2023 research paper.
- [Client-side rendering](/glossary/client-side-rendering): Building page content in the browser with JavaScript; agents and many fetchers that do not run JavaScript see an empty page.
