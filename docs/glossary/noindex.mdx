**noindex** is a robots rule, set in a `<meta name="robots">` tag or an `X-Robots-Tag` response header, that asks search engines to keep a page out of their results.

Google documents both forms. The header also works for files that have no HTML, such as PDFs, and Google does not support a `noindex` line in robots.txt. A noindexed page can still be crawled, and its links can still be followed unless `nofollow` is added.

## Why it matters

For `noindex` to work, the crawler has to fetch the page and read it. Google says the page must not be blocked by robots.txt: if it is, the rule is never seen, and the URL can still appear in results when other pages link to it. Blocking a page in robots.txt and adding `noindex` is a common way to get this wrong.

The other failure is a `noindex` nobody meant to ship. A staging setting left in a production template, or a header set at the CDN, removes pages from search without any visible change to the page.

## How squirrelscan checks it

[core/robots-meta](/rules/core/robots-meta) reads the robots meta tag and the `X-Robots-Tag` header on every page and names the directive and where it was set, including a header scoped to one crawler such as `googlebot`. [crawl/indexability](/rules/crawl/indexability) reports each non-indexable page at info level with its source. [crawl/all-noindex-pages](/rules/crawl/all-noindex-pages) lists every blocked page across the site, and fails for URL patterns you nominate as ones that must stay indexable.

Three rules catch contradictions. [crawl/robots-meta-conflict](/rules/crawl/robots-meta-conflict) lists pages that robots.txt blocks and that also carry `noindex`, so the rule is never read. [crawl/noindex-in-sitemap](/rules/crawl/noindex-in-sitemap) lists noindexed pages that a sitemap still submits; it reads the meta tag only. [crawl/schema-noindex-conflict](/rules/crawl/schema-noindex-conflict) flags rich result structured data on a page that cannot be indexed.

## How to fix it

To keep a page out of search, let it be crawled and say `noindex`:

```html
<meta name="robots" content="noindex" />
```

For a PDF or another file, send `X-Robots-Tag: noindex` from the server. Remove any `Disallow` that covers the same path ([the conflict fix](/rules/crawl/robots-meta-conflict#how-to-fix-it)), and drop the URL from the sitemap ([the sitemap fix](/rules/crawl/noindex-in-sitemap#how-to-fix-it)). When a page should be indexed and the report names the header, the directive is in your server or CDN configuration, so check it with `curl -I` ([the robots meta fix](/rules/core/robots-meta#how-to-fix-it)). Use `errorOnPatterns` to make sections that must stay indexable fail loudly ([the list fix](/rules/crawl/all-noindex-pages#how-to-fix-it)).

## Related terms

- [Robots meta tag](/glossary/robots-meta-tag): A `<meta name="robots">` tag carrying page-level directives such as noindex, nofollow, nosnippet and max-snippet.
- [X-Robots-Tag](/glossary#x-robots-tag): An HTTP response header that carries the same directives as the robots meta tag, and works for non-HTML files such as PDFs.
- [robots.txt](/glossary/robots-txt): A plain-text file at the site root that tells crawlers which paths they may fetch, per user-agent token (RFC 9309).
- [Indexability](/glossary/indexability): Whether a crawled URL is eligible to be indexed: reachable, a 200 response, not noindexed, not blocked and not canonicalised elsewhere.
