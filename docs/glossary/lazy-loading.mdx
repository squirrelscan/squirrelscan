**Lazy loading** is deferring the download of an off-screen image or iframe until the visitor scrolls near it, which browsers support natively with the `loading="lazy"` attribute.

The attribute works on `<img>` and `<iframe>` and needs no JavaScript. The browser holds the request until the element comes within a set distance of the viewport. The other value, `eager`, loads the resource straight away, which is also what happens with no attribute at all.

## Why it matters

Below the fold, lazy loading saves bytes the visitor may never need. Iframes gain the most: an embedded video or map is a whole document with its own scripts, and none of it loads until the visitor gets close.

Above the fold it does harm. The browser has to finish layout before it knows a lazy image is visible, so the request starts later than it would with no attribute. web.dev says not to lazy-load images that are likely to be in the viewport when the page loads, and the Largest Contentful Paint image least of all.

## How squirrelscan checks it

Four rules cover both directions. [images/offscreen-lazy](/rules/images/offscreen-lazy) treats the first three images as above the fold (the `above_fold_count` option) and warns about later images that are neither `lazy` nor `eager`. [perf/lazy-above-fold](/rules/perf/lazy-above-fold) does the reverse and flags `loading="lazy"` on the first three images that could be visible, skipping hidden images, inactive carousel slides and images in a `<footer>`. [perf/carousel-hidden-eager](/rules/perf/carousel-hidden-eager) finds eager images inside carousel slides hidden with an inline style or attribute. [images/lazy-loading](/rules/images/lazy-loading) is an info-level count of how much of the page defers.

Position comes from document order, not from layout. An image late in the markup that CSS places at the top of the screen is treated as below the fold, and a slide hidden only by a stylesheet class is not seen.

## How to fix it

Leave the hero alone and lazy-load what the visitor has to scroll to:

```html
<img src="/hero.jpg" width="1200" height="600" alt="…" fetchpriority="high" />
<img src="/gallery-1.jpg" width="600" height="400" alt="…" loading="lazy" />
<iframe src="https://www.youtube.com/embed/…" loading="lazy" title="…"></iframe>
```

A component that renders a list of images can add the attribute to every item after the first row ([the off-screen fix](/rules/images/offscreen-lazy#how-to-fix-it)). Remove it from anything on the first screen ([the above-the-fold fix](/rules/perf/lazy-above-fold#how-to-fix-it)). Most carousel libraries have an option that lazy-loads every slide except the first ([the carousel fix](/rules/perf/carousel-hidden-eager#how-to-fix-it)). If a page really shows more than three images on its first screen, raise `above_fold_count`.

## Related terms

- [Largest Contentful Paint (LCP)](/glossary/lcp): The time until the largest image or text block in the viewport renders; good is 2.5 seconds or less.
- [fetchpriority](/glossary#fetchpriority): An HTML attribute (high, low, auto) that hints how urgently the browser should fetch an image, script or link.
- [Responsive images](/glossary/responsive-images): Serving differently sized image files with srcset, sizes and `<picture>` so each device downloads one that fits.
