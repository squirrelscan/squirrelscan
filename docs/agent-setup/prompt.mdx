These are instructions for a coding agent, not a guide for a person. If you are
a person, start at [Agent setup](/agent-setup) and press **Copy prompt**. If you
are an agent, the rest of this page is your task.

## Task

Set up squirrelscan for this project so you can audit the website and fix what
you find. Work through the steps in order. The setup is not done until the
first audit has run: do not stop at "installed". Finish with the report in
step 7.

## Ground rules

- Use only the commands on this page to install or update squirrelscan. Do not
  invent another installer, package name or download URL.
- Never ask for, paste or store an API key or token. Signing in is the person's
  step: tell them to run `squirrel auth login` themselves.
- Never pass `--yes` (`-y`). It skips squirrelscan's confirmation prompts and
  lets a cloud audit spend credits up to the account's per-audit limit.
- Get the person's explicit OK before anything that spends credits or leaves
  their machine: a signed-in cloud audit, publishing a report, or turning on
  recurring audits. Before a cloud audit, show them the credit estimate the CLI
  prints and the balance from `squirrel credits`, then wait for a yes.
- Keep what is already set up. Do not overwrite an existing `squirrel.toml`,
  and do not reinstall a CLI that works: update it.
- Audit sites the person owns or is allowed to test. Probing security checks
  (`--probe active` or `aggressive`) send requests a site's firewall may treat as
  an attack: only use them on the person's own site, and only if they ask.

## 1. Check for an existing install

```bash
squirrel self version
```

If it prints a version, run `squirrel self update` and go to step 3. If the
command is not found, install it in step 2.

Check the sign-in state now, because it decides whether an audit is free:

```bash
squirrel auth status --json
```

`"authenticated":false` means signed out. Anything else means signed in: a
plain `squirrel audit` then runs in the cloud, spends credits, adds the site to
the person's dashboard and publishes a report. Step 4 avoids that.

## 2. Install the CLI

squirrelscan ships as a single binary with no runtime dependency.

```bash
curl -fsSL --connect-timeout 10 --max-time 120 "https://install.squirrelscan.com/install.sh?source=agent" | bash
```

If you would rather read the script before running it, download it from the
same URL, read it, then run it. Use no other source:

```bash
curl -fsSL --connect-timeout 10 --max-time 120 "https://install.squirrelscan.com/install.sh?source=agent" -o install.sh
less install.sh
bash install.sh
```

On Windows, use PowerShell:

```powershell
iwr -useb "https://install.squirrelscan.com/install.ps1?source=agent" | iex
```

Verify the install:

```bash
squirrel self doctor
```

If the binary is not on `PATH`, it installs to `~/.local/bin/squirrel`. Add that
directory to `PATH` rather than moving the binary, because `squirrel self update`
expects it there.

On Alpine or another musl Linux, the binary needs `libstdc++`. The installer
adds it when run as root; otherwise `apk add libstdc++` first.

## 3. Add the squirrelscan skill

The skill teaches you the audit and fix loop: which flags to use, how to read a
report and how to work through issues. Run `squirrel skills status` first. If the skill is already installed and
current, skip the install. If it is installed but behind, run
`squirrel skills update`. Otherwise install it for the agent you are:

```bash
squirrel skills install
```

It detects installed agents and installs for each one. Pass `--agent <name>` to
pick one, or `--project` to install into this repository instead of your user
folder. In Claude Code you can install the plugin instead, which brings the
skill and MCP together:

```text
/plugin marketplace add squirrelscan/skills
/plugin install squirrelscan@squirrelscan
```

Check the result with `squirrel skills status`.

## 4. Run the first audit

The first audit is always a local one, whether or not the person is signed in.
`--offline` keeps it on this machine: free, nothing published, nothing sent to
the cloud. `--level quick` keeps it to 25 pages. Run it now against the
project's site so there is something concrete to work from:

```bash
squirrel audit <url> --offline --level quick --format json
```

Without `--offline`, a signed-in audit is a billed cloud audit that publishes a
report. Do not run one until the person has said yes (see the ground rules).

Use the site's production URL if you can find one in the project (check
`package.json`, a sitemap, `README`, or the deploy config). Otherwise ask the
person which URL to audit, or point it at the local dev server.

`--format json` gives you structured output. Each issue carries a rule id, a
severity, the affected URL, and a description of the fix.

Show the person the result now: the score and the top issues. Do this before
connecting MCP. If a later step fails, they have still seen what squirrelscan
found.

If most pages come back blocked, challenged or rate limited, the site's firewall
is stopping the crawler. Do not retry harder and do not suggest turning the
firewall off. Point the person to [Firewall and WAF exceptions](https://docs.squirrelscan.com/cloud/firewall)
and [Web Bot Auth](https://docs.squirrelscan.com/guides/web-bot-auth), which
let the audit through without weakening the site.

## 5. Connect over MCP

MCP gives you the audit tools directly, so you can run audits and read issues
without shelling out. Skip this if you installed the Claude Code plugin in step
3. Check your MCP config first so the server is not added twice (in Claude
Code, run `claude mcp list`). If a `squirrelscan` server is already there,
leave it. Otherwise pick the line matching the agent you are:

- **Claude Code**: `claude mcp add --transport http squirrelscan https://mcp.squirrelscan.com/mcp`
- **Codex**: `codex mcp add squirrelscan --url https://mcp.squirrelscan.com/mcp`
- **Cursor**, **Windsurf**, **VS Code**, **opencode**, or any other MCP client:
  add an HTTP MCP server named `squirrelscan` pointing at
  `https://mcp.squirrelscan.com/mcp`, in whatever config file that client uses.

The server works unauthenticated for anonymous audits. Cloud features
(AI page analysis, browser rendering, the shared issue tracker, published
reports) need an account: tell the person to run `squirrel auth login`.

Full per-client instructions: https://docs.squirrelscan.com/developers/mcp-clients

## 6. If setup fails

If a step fails and you cannot fix it, the docs here were wrong, or something
was needlessly hard, send the team ONE report. Do not send one per error.

```bash
squirrel feedback --json --category bug_report --email <person's address> -m "<area>: expected <x>, saw <y>. Repro: <steps>"
```

`--email` is where the team can reply. Ask the person for it unless they are
signed in, because a signed-in account supplies one. Use `--category confusing`
for unclear docs and `--category tool_ergonomics` for friction. If you are
connected over MCP, the `send_feedback` tool does the same job.

Write it with the area, what you expected, what you saw and the shortest steps
to repeat it. Never include credentials, API keys, code, page content, personal
details or private file paths: describe them instead.

A sent report prints JSON with `"ok":true` and a `receipt` such as
`fb_3f9a1c0b7d2e`. Quote the receipt to the person. If there is no receipt, the
report was not sent: say so, and do not claim it was.

## 7. Report, then fix what you found

Report this to the person, one line each:

- squirrelscan version (`squirrel self version`)
- skill installed, and for which agents (`squirrel skills status`)
- MCP connected, or why not
- first audit: the URL, the score and the top three issues
- feedback receipt, if you sent a report in step 6

End the report with the exact next step for the person: one concrete action,
such as fixing the top issue, or running `squirrel auth login` themselves to
get cloud features.

Then work the issues in severity order, highest first. For each one:

1. Read the rule's explanation. Every issue references a rule id, documented at
   `https://docs.squirrelscan.com/rules/<category>/<rule-id>`.
2. Find the code that produces the offending output. Fix the source, not the
   rendered HTML: a template, a layout component, a config file, or a
   content file.
3. Re-run the audit to confirm the issue is gone and nothing regressed.

Do not suppress a rule to make a number go up. If a finding is a genuine false
positive for this project, say so and explain why rather than silencing it.

## Notes

- Audits run without an account, and any audit with `--offline`, never cost
  credits. Signed-in cloud audits use credits: see [Credits](https://docs.squirrelscan.com/cloud/credits) for the
  current prices. Free accounts get monthly credits.
- `squirrel audit --help` lists the audit levels, output formats, and crawl limits.
- squirrelscan does not follow `robots.txt` by default, so a site that blocks
  crawlers there is still audited. Set `respect_robots = true` under
  `[crawler]` in `squirrel.toml` to honour it.
