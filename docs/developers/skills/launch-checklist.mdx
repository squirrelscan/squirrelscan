`launch-checklist` is an Agent Skills `SKILL.md` from squirrelscan: a pre-launch website check for a new website, a redesign or a migration. It runs one full baseline audit through the squirrel CLI or the hosted squirrelscan MCP server. Then it works through the other squirrelscan skills in launch order and ends with a go or no-go list. It runs in Claude Code, Codex, Cursor and other coding agents.

Version 0.1.1. New to skills? Start with the [skills overview](/developers/skills/overview).

## What it does

- Runs a baseline audit at `--level full` and reads the score, the error-severity issues and the `Not checked:` line.
- Treats blockers as no-go until clear: compromise and leaks, HTTPS, indexing, broken links and server errors.
- Checks that a staging `noindex` or `Disallow: /` is gone on the live website and that canonicals and the sitemap point at the live host.
- Lists what should be fixed before launch: titles and descriptions, accessibility, performance, security headers, structured data and the bot policy.
- Lists the human checks the tool cannot do: forms end to end, analytics and consent, the 404 page, legal pages, redirects from the old domain, the email sending domain and the sitemap submission in Search Console.
- Never removes `noindex` from staging itself: only in the production build, checked again on the live URL.
- Writes a go or no-go table where each blocker is clear, not clear or not checked, with the before and after score.
- Says what it cannot judge: copy, design and legal compliance.

## Questions it answers

- Is my website ready to launch?
- Run a pre-launch website check
- Audit my migration before cutover
- Did I leave noindex or a robots.txt Disallow on the live website?
- Do my canonicals and sitemap point at the production domain?
- Which redirects do I need after changing domains?
- What should I fix before launch and what can wait?

## Requirements

The squirrel CLI installed and in your `PATH`, or the hosted squirrelscan MCP server connected (`https://mcp.squirrelscan.com/mcp`). Check the CLI with `squirrel --version`. Setup steps are in [install](/install) and [MCP clients](/developers/mcp-clients).

Install the CLI on macOS or Linux:

```bash
curl -fsSL https://install.squirrelscan.com | bash
```

## Example prompts

Paste one of these into your coding agent:

```text
Is my website ready to launch? Check https://staging.example.com
Run a pre-launch website check and give me a go or no-go list
Audit my migration before cutover and compare the live website with the baseline
```

The agent audits staging first and works through the blockers with the matching skills. It re-audits the live URL after DNS and deploy. Then it gives you the go or no-go table.

## How it works

1. Run the full baseline audit on the staging or pre-production URL.
2. Work through the blocker table, using `security-audit`, `seo-audit`, `broken-link-checker` and `audit-website` for fixes.
3. Handle the should-fix list and hand the human checks to you.
4. Write the go or no-go table, with "not checked" never counted as clear.
5. After launch, re-audit the live URL with `--refresh`, compare with the baseline and add `website-ci-gate`.
