To run a website audit in GitHub Copilot, add the squirrelscan MCP server and ask Copilot to audit your site. For a step-by-step walkthrough, see the [Copilot guide](https://squirrelscan.com/for/copilot).

GitHub Copilot agent mode can already run terminal commands on your behalf, so it can run `squirrel` with no configuration at all. Connecting the hosted MCP server replaces that parsed terminal output with native tools for cloud audits, the issue tracker, and the rule catalog.

| Surface | OAuth | Section |
|---|---|---|
| VS Code | Yes | [Add the MCP server](#2-add-the-mcp-server) |
| Visual Studio 17.14+ | Yes | [Visual Studio](#visual-studio) |
| GitHub Copilot CLI | Not documented | [GitHub Copilot CLI](#github-copilot-cli) |
| JetBrains IDEs, Xcode, Eclipse | Not documented | [JetBrains, Xcode and Eclipse](#jetbrains-xcode-and-eclipse) |

<Note>In VS Code, MCP runs through VS Code's built-in client (v1.101+), not through GitHub Copilot itself, so the config below lives in VS Code's `mcp.json`, not in a GitHub Copilot setting.</Note>

## 1. Install the CLI

The skills and local audits run through the `squirrel` binary.

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    curl -fsSL https://install.squirrelscan.com | bash
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    iwr -useb https://install.squirrelscan.com/install.ps1 | iex
    ```
  </Tab>
</Tabs>

Local audits run entirely on your machine. Logged out, they need no account and cost nothing; logged-in audits spend credits. Verify with `squirrel --version`.

## 2. Add the MCP server

VS Code uses a top-level `servers` key, not `mcpServers`, and remote entries need `"type": "http"`.

<Tabs>
  <Tab title="OAuth (recommended)">
    ```json
    {
      "servers": {
        "squirrelscan": {
          "type": "http",
          "url": "https://mcp.squirrelscan.com/mcp"
        }
      }
    }
    ```

    On first connection VS Code discovers the authorization server, registers a client, and opens a browser so you can log in. Manage or revoke the grant later under **Accounts → Manage Trusted MCP Servers**.
  </Tab>
  <Tab title="API key">
    For a config you intend to commit, use a prompted input so the key lands in VS Code's secret storage rather than in the file:

    ```json
    {
      "inputs": [
        {
          "type": "promptString",
          "id": "squirrelscan-api-key",
          "description": "squirrelscan API key",
          "password": true
        }
      ],
      "servers": {
        "squirrelscan": {
          "type": "http",
          "url": "https://mcp.squirrelscan.com/mcp",
          "headers": {
            "Authorization": "Bearer ${input:squirrelscan-api-key}"
          }
        }
      }
    }
    ```

    This also spares teammates an OAuth round trip just to open the project. Mint a key with `squirrel keys create --shell`.
  </Tab>
</Tabs>

**Where it goes.** Save either block through **Command Palette → MCP: Add Server** (choose **HTTP**), or write it yourself to `.vscode/mcp.json` for this workspace (safe to commit, no token is stored in it) or to the user `mcp.json` via **Command Palette → MCP: Open User Configuration** to get it everywhere.

<Warning>
Use a top-level `headers` object. The `"requestInit": { "headers": ... }` form belongs to the separate Visual Studio IDE and silently no-ops in VS Code, you get a server that connects unauthenticated and fails on the first tool call.
</Warning>

## 3. Install the skills

VS Code with GitHub Copilot supports the [Agent Skills](https://agentskills.io) standard:

```bash
squirrel skills install
```

That installs `audit-website` (the fix loop) and `squirrelscan` (operating the CLI). See [`squirrel skills`](/cli/skills) for the details.

## 4. Run an audit

Open GitHub Copilot Chat and switch to **agent mode**. Ask mode can read your code but cannot run tools or edit files, so audits and fixes both need agent mode.

```text
Audit https://nutshop.squirrelscan.com with squirrelscan and list the top issues by severity.
```

Then hand it the fixes. Agent mode edits across the repo the same way it acts on a failing test:

```text
Fix every core/title-missing and images/alt-missing finding, then re-audit to confirm the score went up.
```

Cap the crawl on a large site so the run stays fast:

```text
Audit only /blog/* on nutshop.squirrelscan.com, cap it at 20 pages, and fix the broken links.
```

<Tip>GitHub Copilot proposes each edit for review before applying it. On a batch of 20 image-alt fixes that gets tedious, so ask it to group the changes by file and apply them per file rather than per finding.</Tip>

## Visual Studio

Visual Studio 17.14 or later supports remote MCP servers in agent mode. Open the GitHub Copilot Chat window, switch to **Agent**, choose the tools icon, then **+**. Pick **HTTP** and enter the URL:

```text
https://mcp.squirrelscan.com/mcp
```

Visual Studio writes this entry to its MCP config:

```json
{
  "servers": {
    "squirrelscan": {
      "url": "https://mcp.squirrelscan.com/mcp"
    }
  }
}
```

Click **Auth** in the CodeLens above the server entry to log in. For an API key in Visual Studio, put the header under `requestInit`, not at the top level: `"requestInit": { "headers": { ... } }`.

## GitHub Copilot CLI

Add the server with the `copilot` command:

```bash
copilot mcp add --transport http squirrelscan https://mcp.squirrelscan.com/mcp
```

That writes this entry to `~/.copilot/mcp-config.json`:

```json
{
  "mcpServers": {
    "squirrelscan": {
      "tools": ["*"],
      "type": "http",
      "url": "https://mcp.squirrelscan.com/mcp"
    }
  }
}
```

GitHub documents the command and the config file, but does not document OAuth for remote servers. We have not confirmed a browser login from GitHub Copilot CLI, so treat OAuth there as untested. If the login does not start, use VS Code, or add an API key header with `--header`.

## JetBrains, Xcode and Eclipse

{/* Source: https://docs.github.com/en/copilot/how-tos/provide-context/use-mcp/extend-copilot-chat-with-mcp (fetched 2026-11-26): JetBrains, Xcode (GitHub Copilot for Xcode extension) and Eclipse (2024-09 or later) support remote MCP servers; every remote example uses a personal access token header and none documents OAuth. */}

GitHub documents remote MCP servers for GitHub Copilot in JetBrains IDEs, Xcode (through the GitHub Copilot for Xcode extension) and Eclipse 2024-09 or later, but only with a personal access token header. It does not document OAuth for any of them. Use the [GitHub Copilot CLI](#github-copilot-cli) or VS Code for squirrelscan, and run local audits through the `squirrel` CLI in the IDE terminal.

## Cloud agent on github.com

{/* Source: https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/extend-cloud-agent-with-mcp (re-checked 2026-11-26): repository administrators only; Settings > Code, planning, and automation > Copilot > MCP servers; syntax validated on save; only Agents secrets and variables prefixed COPILOT_MCP_ reach the config; $VAR substitution in headers; Agents secrets at organization or repository level; no OAuth for remote servers; tools run without approval and GitHub recommends allowlisting read-only tools; the config is shared with Copilot code review, which only uses tools annotated readOnlyHint: true (all ten listed tools use READ_ONLY_TOOL_ANNOTATIONS on the hosted server). Scopes: API_KEY_SCOPES in packages/core-contracts/src/api-keys.ts; the hosted read tools require audits:read, run_audit requires audits:write. */}

The cloud agent that works on issues and pull requests does not support OAuth for remote MCP servers, so this is the API key route. It reads its MCP configuration from repository settings, and only repository administrators can edit them. Set the key as a secret, never in a chat.

The agent calls MCP tools on its own, without asking first. So give it a read-only key and a read-only tool list: it can read your audits, reports and issues, and it cannot start audits that spend credits or change anything.

1. Mint a read-only key. It is shown once, so copy it straight into the secret in step 3.

   ```bash
   squirrel keys create --name copilot-cloud-agent --scopes audits:read
   ```

2. In the repository, open **Settings**, then under **Code, planning, and automation** choose **Copilot**, then **MCP servers**.
3. Add an Agents secret for the key. GitHub only passes Agents secrets and variables whose names start with `COPILOT_MCP_` to the MCP configuration, so name it `COPILOT_MCP_SQUIRRELSCAN_API_KEY`. Agents secrets can also be set at the organization level.
4. Paste this into **MCP configuration** and choose **Save MCP configuration**. GitHub validates the syntax on save.

```json
{
  "mcpServers": {
    "squirrelscan": {
      "type": "http",
      "url": "https://mcp.squirrelscan.com/mcp",
      "tools": [
        "whoami",
        "list_websites",
        "list_audits",
        "get_audit_status",
        "get_report",
        "compare_audits",
        "list_issues",
        "get_issue",
        "list_findings",
        "get_rule"
      ],
      "headers": {
        "Authorization": "Bearer $COPILOT_MCP_SQUIRRELSCAN_API_KEY"
      }
    }
  }
}
```

`tools` lists the server tools the agent may use. GitHub recommends allowlisting specific read-only tools rather than `["*"]`, because the agent uses them without asking for approval. The list above only reads.

To let the agent start audits too, add `"run_audit"` to `tools` and mint the key with `--scopes audits:read,audits:write`. Do that on purpose only: every audit spends credits, and the agent will start them without asking.

GitHub shares this configuration with Copilot code review, which only calls tools the server marks read-only (`readOnlyHint`). Every tool in the list above carries that marker, so code review can use them as well. `run_audit` does not, so code review never starts an audit.

<Warning>Never paste the key into an issue, a pull request comment, or a chat with the agent. Those are visible to others and are sent to a model. Set it only as an Agents secret.</Warning>

The hosted server crawls from squirrelscan's cloud, so the cloud agent can audit only publicly reachable URLs.

## Copilot Studio

{/* Untested: Copilot Studio was not available in the sandbox. Written from the Microsoft Learn page "Add an existing MCP server to your agent". */}

Copilot Studio can call squirrelscan as an MCP tool from a custom agent.

1. Open your agent, then **Tools**, then **Add a tool**.
2. Choose **New tool**, then **Model Context Protocol**.
3. Enter the server URL `https://mcp.squirrelscan.com/mcp`.
4. Under authentication, choose **OAuth 2.0**, then **Dynamic discovery**.

Copilot Studio supports streamable HTTP only, which is what squirrelscan serves.

<Warning>squirrelscan issues public OAuth clients only (`token_endpoint_auth_methods_supported` is `["none"]`, with PKCE S256). If Copilot Studio insists on a client secret for the connection, the login fails. This is untested, so check it before you roll the tool out.</Warning>

Power Platform data loss prevention (DLP) policies can block MCP connectors. If the tool cannot be added, ask a Power Platform admin to allow it in the environment's DLP policy.

## Microsoft 365 Copilot

Microsoft 365 Copilot does not take an MCP server from a settings page. A developer builds a declarative agent in the Microsoft 365 Agents Toolkit (**Start with an MCP Server**), points it at `https://mcp.squirrelscan.com/mcp`, and picks OAuth with dynamic client registration. An admin then has to allow the custom app. See Microsoft's [build MCP plugins](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/build-mcp-plugins) guide. This path is untested.

## Enterprise: allowlisting

{/* Sources: https://docs.github.com/en/copilot/concepts/mcp-management and https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-mcp-usage/configure-enterprise-allowlist (fetched 2026-11-26). */}

On GitHub Copilot Business and Enterprise, an org or enterprise owner controls MCP. Both steps are needed before squirrelscan connects.

1. **Turn MCP on.** Enable the **MCP servers in Copilot** policy, in the **MCP** section of the Copilot policies.
2. **Allow the server.** GitHub offers two mechanisms. GitHub recommends an allowlist in `managed-settings.json`, which can match a server by name, URL or `stdio` command. A custom registry (the **MCP Registry URL** setting with **Restrict MCP access to registry servers**) matches by name or ID only, is in public preview, and users can bypass it by editing configuration files. squirrelscan is not in GitHub's registry, so use the allowlist and set **Restrict MCP access to registry servers** to **Allow all** to avoid conflicts.

Most enterprises keep `managed-settings.json` in a `.github-private` repository. GitHub also documents installing it on users' machines through device management. A remote server such as squirrelscan is matched by URL:

```json
{
  "allowedMcpServers": [
    { "serverUrl": "https://mcp.squirrelscan.com/mcp" }
  ]
}
```

A local server is matched by its command instead, with `serverCommand` set to the command and its arguments as an array. `serverUrl` accepts `*` wildcards. See GitHub's [allowlist guide](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-mcp-usage/configure-enterprise-allowlist) for the full syntax.

How GitHub evaluates a server:

- Built-in default servers are always allowed.
- A server that matches any `deniedMcpServers` entry is blocked, so a deny wins over an allow.
- Once an allowlist exists, every server that does not match it is blocked, including servers people already use. Add their entries in the same change.
- A server whose URL or command contains an unresolved variable (`$VAR` or `${VAR}`) is blocked.
- A malformed file is treated as an empty allowlist, which blocks everything except built-in servers.

The lists cover user and repository settings. GitHub states they do not apply to servers defined in repository custom agent profiles.

Copilot Studio and Microsoft 365 Copilot follow Microsoft's controls instead: Power Platform DLP policies and custom-app upload permissions.

If squirrelscan connects on your personal account but not your work one, a policy above is almost always why. The CLI path has no such restriction, so agent mode can still run `squirrel` in the integrated terminal while you wait.

## What squirrelscan checks, and what it does not

The audit covers 360+ rules, rolling up into four scores: **SEO**, **Performance**, **Security**, and **Agents** (how well AI crawlers and agents can consume the site).

The CLI audits anything your machine can reach, including `localhost` and private staging. The hosted MCP server crawls from squirrelscan's cloud, so it needs a publicly reachable URL, use the CLI or [`squirrel mcp`](/cli/mcp) for anything private.

GitHub Copilot runs interactively in your editor, so it is the wrong tool for a per-deploy gate. Run the CLI in CI for that, it exits non-zero when a `--fail-on` threshold trips. Use GitHub Copilot for the fix loop and [CI](/guides/ci) for the gate.

squirrelscan does not track keyword rankings, backlinks, or competitors. It reports what is on the page and how it is served.
