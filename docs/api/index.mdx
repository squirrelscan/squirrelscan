squirrelscan exposes a stable, programmatic REST API under `/v1`. It's the
surface external clients, agent workflows, and MCP integrations can depend on.

<Info>
The machine-readable contract is published as an [OpenAPI 3.1 spec](/openapi.json).
Point your client generator, Postman, or an MCP server at it.
</Info>

## Base URL

```text
https://api.squirrelscan.com
```

## Authentication

Every request authenticates with a bearer token in the `Authorization` header:

```bash
curl https://api.squirrelscan.com/v1/credits \
  -H "Authorization: Bearer <token>"
```

Programmatic **API keys** are prefixed `sq_` and are the intended public auth
mechanism (rolling out, see the API-keys epic). Today the same scheme also
accepts CLI tokens (`sqcli_` prefix, issued by `squirrel auth login`) and
dashboard session JWTs, so you can start integrating immediately.

## Public surface

These are the external-client-facing routes covered by the contract:

| Resource | Endpoints |
|----------|-----------|
| **Audits** | `POST /v1/agent-runs`, `GET /v1/agent-runs`, `GET /v1/agent-runs/{id}`, `GET /v1/agent-runs/{id}/report` |
| **Reports** | `POST /v1/reports`, `GET /v1/reports`, `GET /v1/reports/{id}`, `PATCH /v1/reports/{id}`, `DELETE /v1/reports/{id}` |
| **Credits** | `GET /v1/credits` |
| **Organizations** | `GET /v1/organizations/{id}` |

<Note>
Internal server-to-server callbacks (`/v1/*/internal/*`), webhook receivers
(`/v1/webhooks`, `/v1/github`), and admin-only routes (`/v1/admin/*`,
`/v1/stats`, `/v1/users`) are **not** part of the public contract and may
change without notice.
</Note>

<Note>
The cloud services the CLI calls during an audit (`/v1/services/*`) are not
part of the public contract either. One of them, the dead-link check
(`/v1/services/dead-links`), bills each link it checks to the audit run it
belongs to. A call that names no run is billed to your org instead: 1 credit
per distinct link it verifies, and nothing for a link it cannot verify (see
[Credits and pricing](/cloud/credits)). The one exception is a `squirrel` CLI
from before v0.0.114: its run-less calls are refused with `426 RUN_REQUIRED`
and never charged. To check a site's links, run an audit
(`POST /v1/agent-runs`) with external link checks on, or a signed-in
`squirrel audit`.
</Note>

## Start a run with a rule filter

`POST /v1/agent-runs` takes the run's settings as a `config` object. This request audits one page, runs only the `ax` rules plus `core/robots-meta`, skips the headless browser and treats the site as a one-shot check:

```bash
curl -X POST https://api.squirrelscan.com/v1/agent-runs \
  -H "Authorization: Bearer $SQUIRREL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com",
    "config": {
      "maxPages": 1,
      "enabledRulePatterns": ["ax/*", "core/robots-meta"],
      "render": false,
      "ephemeral": true
    }
  }'
```

The response is `201` with the run `id`. Poll `GET /v1/agent-runs/{id}` until `status` is `completed`, then read `GET /v1/agent-runs/{id}/report`. `trigger` defaults to `api`, and `config` may also be sent as a JSON-encoded string, the older form.

| `config` key | What it does |
|--------------|--------------|
| `enabledRulePatterns` | Run only the rules these patterns select. A pattern is a category (`ax`), a category glob (`ax/*`) or an exact rule id (`core/robots-meta`), the same patterns and the same matching as the CLI's [`--rule-include`](/cli/audit). List ids with `GET /v1/rules`. At most 50 patterns of at most 100 characters, using letters, digits and `-_./*`. The website's `disable_rules` and `disabledRulePatterns` still apply on top. Opt-in rules (`gaps/*`) cannot be selected. |
| `render` | `false` fetches every page over plain HTTP with no per-page headless browser. `true` renders every page, within what the plan allows. Leave it out to follow the website's setting. Rendering does not change the price. |
| `ephemeral` | The same one-shot check as `ephemeral` on the MCP `run_audit`. If the run creates the website, that website skips the plan's website limit, stays out of website listings and is removed once the run ends. The run and its report are **not** purged: `GET /v1/agent-runs/{id}` and the report keep working, and the run stays in `GET /v1/agent-runs`. If the organization already tracks the domain, or you send `websiteId`, the run uses that website, nothing is deleted, and the response has `ephemeral: false` with an `ephemeralIgnoredReason`. |

A `config` the API cannot honour is a `400` with code `VALIDATION_ERROR`, and nothing is charged or started: invalid JSON, a value that is not an object, an unknown key, a `render` or `ephemeral` that is not a boolean, or a bad `enabledRulePatterns`. For the filter, `error.patterns` lists the entries at fault: an unknown category, a pattern that matches no rule (`core/robots-metaa`), a list over the caps, or a list the disable settings leave with no rule to run.

<Note>
`ax/*` selects every rule filed under the `ax` category, including the three that kept the older `ai/` id prefix (`ai/llm-parsability`, `ai/page-type-match`, `ai/site-metadata`), exactly as `squirrel audit --rule-include ax` does. To leave some out, add their exact ids to `disabledRulePatterns`. A run that selects a subset reports only those rules, so its overall score is not comparable to a full audit's.
</Note>

## Error envelope

All errors use one stable, typed shape:

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Report not found",
    "requestId": "8a1f…"
  }
}
```

- `code`: stable, machine-readable (`SCREAMING_SNAKE_CASE`). Match on this.
  Treat unknown codes as opaque and fall back to `message`.
- `message`: human-readable; may change. Don't match on it.
- `requestId`: present when available; quote it to support for log lookups.

Common codes: `UNAUTHORIZED`, `FORBIDDEN`, `NO_ORG`, `NOT_FOUND`,
`VALIDATION_ERROR`, `INVALID_JSON`, `PAYLOAD_TOO_LARGE`, `SECURITY_VIOLATION`,
`INSUFFICIENT_CREDITS` (with `error.required` / `error.balance`),
`DUPLICATE_REQUEST`, `RUN_NOT_ACTIVE`, `UPSTREAM_ERROR` (with `error.reason`),
`RATE_LIMITED`.

`SECURITY_VIOLATION` (`400`) is returned by `POST /v1/reports` when the report
payload trips the content security scanner; `error.threats` lists the matched
patterns.

<Note>
The shared auth middleware, the org gate, and the credit gate (`402`
`INSUFFICIENT_CREDITS`, `409` `DUPLICATE_REQUEST`, `409` `RUN_NOT_ACTIVE`) now
emit the typed envelope like every other documented route. Branch on the HTTP
status code, then split same-status conditions on `error.code`, not the human
`message`: a `409` is either `DUPLICATE_REQUEST` (this exact payload was already
charged) or `RUN_NOT_ACTIVE` (a cloud run was reaped or failed before the charge
landed, so it was never charged).
</Note>

`5xx` responses from unhandled server errors (DB/storage failures not caught by
a handler) are **not guaranteed** to follow the envelope: handle them by status
code and retry idempotent reads with backoff.

## Rate limiting

Rate limiting is being rolled out. When enforced, throttled requests return
`429 Too Many Requests` with these headers:

| Header | Meaning |
|--------|---------|
| `RateLimit-Limit` | Request quota for the current window |
| `RateLimit-Remaining` | Requests remaining in the window |
| `RateLimit-Reset` | Seconds until the window resets |
| `Retry-After` | Seconds to wait before retrying |

Back off on `Retry-After` and retry idempotent reads.

## Credits

Cloud operations (publishing reports, cloud audits) are priced in
[credits](/cloud/credits). When an organization runs out, the API returns
`402` with `code: "INSUFFICIENT_CREDITS"`.
